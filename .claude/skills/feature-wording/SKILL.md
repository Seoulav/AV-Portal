## 0. 시작 전에

1. 최신 `origin/main` 기준 브랜치인지, 같은 제품 파일을 고치는 열린 PR이 없는지 확인한다(`gh pr list --state open`). 겹치는 제품은 그 PR 병합 뒤에 한다.
2. 대상 필드는 `beta/site/detail/data/<slug>.json`의
   - `features[].text` — 화면의 **05 주요기능** 목록(`beta/site/detail/app.js:428`, 6개 넘으면 접힘)
   - `portMap.items[].desc` — **02 Port Map** 번호 카드 설명 (작업 승인 범위에 있을 때만)
3. **대상 밖**: `overview`·`lead`·`subtitle`·`keyFacts`·`specifications`·`io`·`label`, RTCOM 동기화본(`beta/site/rtcom/` — 원본은 알티컴 구성기라 여기서 고치지 않는다, AGENTS.md).

## 1. 도구 — `scripts/check-feature-wording.mjs`

Node 도구가 공개 제품 JSON의 현재 문구와 기준 커밋의 변경 범위를 검사한다.

```
node scripts/check-feature-wording.mjs                       # 남은 대상: slug · 필드 · 순번 · 문장 · 끝맺음 유형
node scripts/check-feature-wording.mjs --manufacturer Crown  # 묶음만
node scripts/check-feature-wording.mjs --field desc          # Port Map 설명만
node scripts/check-feature-wording.mjs --check               # 남은 대상이 있으면 종료 코드 1
node scripts/check-feature-wording.mjs --diff origin/main    # 기준 커밋 대비 사실 보존 검사
node scripts/check-feature-wording.mjs --json > out.json     # 대조표 만들 때
```

### 대상 판정 (서술형으로 보는 끝)

문장 끝 공백·따옴표와 **끝에 붙은 괄호 덩어리(중첩 괄호 포함)**를 떼고 본다. `지원한다(무선 LAN 필요).`의 끝은 `지원한다`다([전환 규칙 §4](references/전환규칙.md)). 특정 어미(`~습니다`)의 집계 수를 전체 대상으로 오해하지 않는다.

| 유형 | 정규식(끝) | 예 |
|---|---|---|
| `HANDA` | `[가-힣]+(한다|된다|인다|운다|킨다|는다)\.?$` | 지원한다 · 포함된다 · 높인다 · 향상시킨다 · 입력받는다 |
| `PAST` | `[가-힣]+(했다|됐다|었다|았다|였다|췄다)\.?$` | 확보했다 · 내장했다 · 설계되었다 · 갖췄다 |
| `CAN` | `수 있다\.?$` | 제어할 수 있다 |
| `EXIST` | `(있다|없다)\.?$` | 포함돼 있다 · 필요 없다 |
| `COPULA` | `(이다|다)\.?$` (위에 안 걸린 나머지 `다`) | 수신기다 · 방식이다 · 가능하다 |
| `POLITE` | `(니다|요)\.?$` | 제공합니다 · 명시합니다 |
| `PERIOD` | 명사로 끝났는데 `.`만 붙음 | `… 지원.` |

명사로 끝나면 대상이 아니다. **약어 마침표**(`Inc.`·`No.`·`approx.`)는 `PERIOD`에서 뺀다 — 목록을 도구 안에 둔다.

### `--diff` 사실 보존 검사 — 바뀐 문장마다

| 검사 | 통과 조건 |
|---|---|
| 항목 수 | `features` 길이, 순서가 같음(`desc`는 `n`별로 대응) |
| `source` | 글자 그대로 같음 |
| 숫자 | 전 문장의 숫자 토큰(`\d+([.,/x×:–-]\d+)*` + 붙은 단위)이 후 문장에 **같은 순서·같은 개수**로 있음 |
| 영문·모델 토큰 | `[A-Za-z][A-Za-z0-9+./_-]*` 토큰 집합이 같음(대소문자 구분) |
| 괄호 내용 | `(…)` 안 글자가 그대로 |
| 끝맺음 | 후 문장이 대상 판정에 걸리지 않음 |

실패하면 그 문장을 다시 쓴다. **검사를 통과시키려고 숫자·영문을 지우거나 고치지 않는다.**

## 2. 바꾸는 규칙

자세한 표와 실제 문장 예는 [전환 규칙](references/전환규칙.md)에 있다. 핵심만:

1. **끝 동사를 명사(동작명사·상태명사)로**: `~을 지원한다.` → `~ 지원`, `~을 제공한다.` → `~ 제공`, `~할 수 있다.` → `~ 가능`, `~을 갖췄다.` → `~ 탑재`·`~ 구비`.
2. **끝 동사의 목적격 조사(`을/를`)만 뗀다.** `처리를 지원한다` → `처리 지원`. 다른 조사(`로`·`에서`·`와`)는 뜻을 담으므로 둔다.
3. **마침표를 뗀다.**
4. **앞 절의 서술은 쉼표로 잇는다.** `A를 내장하며, B를 갖췄다.` → `A 내장, B 탑재`. 연결어미(`~해`·`~하여`·`~로`)가 이유·수단을 나타내면 그대로 둔다: `DSP를 내장해 튜닝을 앰프에서 수행한다.` → `DSP를 내장해 튜닝을 앰프에서 수행`.
5. **문장을 나누거나 합치지 않는다.** 항목 수가 바뀌면 화면의 「기능 N개 더 보기」 수가 달라지고 사실 보존 검사가 실패한다.
6. **뜻이 약해질 수 있으면 「검토」로 표시해 원문과 결과를 대조한다.** 특히 부정·구별·조건 문장(`~이 아니라`, `~는 포함되지 않는다`, `~일 때만`). 뜻을 보존하는 표현을 찾지 못하면 추측해 반영하지 않는다.

## 3. 절대 지킬 것

- **사실·수치·단위·모델명·인증명·조건·단서를 지우거나 바꾸지 않는다.** 「삼성전자 공식 스펙 탭은 …을 명시합니다」처럼 **출처를 밝히는 말**도 지우지 않는다 → `삼성전자 공식 스펙 탭 기준 24/7 사용`.
- 맞춤법·오타가 보여도 **이번 문장 변환에서 고치지 않는다.** 대조표 「오타 후보」에만 적는다(사실 보존 검사를 단순하게 두기 위해). 오타 수정은 별도 작업이다.
- 형제 모델(같은 문장을 쓰는 여러 제품)은 **같은 결과**로 바꾼다. 도구 `--json`의 `sameTextAs`로 묶어서 한 번에 정한다.
- 제조사 마케팅 문구 자체를 다듬지 않는다. **끝맺음만** 바꾼다.

## 4. 절차

1. `node scripts/check-feature-wording.mjs --json`으로 대상 목록을 만든다.
2. 제조사 묶음 단위로 바꾼다. 묶음 순서는 문장 수가 많은 순(작업 명세 참고).
3. 묶음마다 `--diff origin/main`을 돌려 통과시킨다.
4. [대조표 양식](references/대조표양식.md)대로 `Work/기록/<작업ID>-대조표.md`에 **바꾼 문장 전부**를 적는다.
5. 「검토」 문장은 전후 의미와 조건을 독립 확인하고 근거를 대조표에 남긴다. 판단할 근거가 부족한 문장만 사용자에게 묻는다.
6. 전부 끝나면 `--check` 0건.

## 5. 테스트와 생성물

- 새 테스트 `tests/feature-wording.test.mjs`: `--check`와 같은 판정을 테스트로 고정한다. 새 제품이 서술형으로 들어오면 실패해야 한다. 대상 밖 필드는 보지 않는다.
- 과거 해시 테스트가 깨진다 → [과거 해시 테스트 대응](../portmap-audit/references/과거해시테스트.md). 되감기 기록은 `features`(그리고 `desc`를 바꿨으면 `n`별 `desc`)만 저장한다.
- 실제 제품의 `features`를 옛 값과 비교하는 테스트는 되감기로 처리한다. `rg -l "features" tests`로 찾는다. 나머지 `features` 언급은 가짜 표본 데이터일 수 있으므로 대상을 확인한다.
- **검색 인덱스가 `features[].text`를 검색어로 담는다**(`beta/site/shared/search-index.mjs:6`). 문장을 바꾸면 반드시 `node beta/build-search-index.mjs`로 다시 만들고 `--check`를 통과시킨다.
- `beta/public-snapshot.json`은 제품 JSON의 SHA-256과 `features` 개수를 담는다. 문구만 바꿔도 SHA가 달라지므로 `node beta/update-snapshot.mjs`로 갱신한다.

## 7. 하위 에이전트에게 나눌 때

- 제조사 묶음 단위. 에이전트에게는 이 스킬, [전환 규칙](references/전환규칙.md), 대상 JSON(`--json` 결과의 해당 부분)을 주고 **전후 문장 표만** 돌려받는다. JSON 반영은 한 곳에서 한다.
- 추론 강도는 **보통**(사실 보존을 `--diff`가 잡아 준다). 「검토」 문장만 높은 강도로 본다.
- 반영 뒤 다른 에이전트가 대조표 표본(묶음별 10%)과 「검토」 전부를 독립 확인한다.
