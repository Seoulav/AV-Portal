# 과거 해시 테스트 대응 — 데이터를 고칠 때 깨지는 테스트 다루기

`portmap-audit`·`feature-wording` 공통. 제품 JSON을 고치면 **이전 작업의 테스트**가 깨진다. 이 저장소의 테스트는 "그 작업이 끝났을 때 파일이 정확히 이 모양이었다"를 SHA-256으로 고정해 두었기 때문이다. 이 문서는 그 구조와 새 작업이 할 일을 정리한다.

## 구조

`tests/*-history.mjs`(현재 37개)는 **되감기 함수**를 내보낸다. 현재 파일을 받아 "그 작업 이전 모습"으로 되돌린다.

```js
// tests/w06002-history.mjs (최신 모양)
const records = JSON.parse(readFileSync(new URL('../Work/기록/W-20261006-002-prior-fields.json', import.meta.url), 'utf8'));
export function beforeW06002Product(current, slug) {
  const record = records[slug];
  if (!record) return current;
  for (const field of ['images', 'imageStatuses']) {
    if (sha(current[field]) !== record.approved[field]) throw new Error(`${slug}: unexpected W-002 ${field} change`);
  }
  return { ...structuredClone(current), images: structuredClone(record.prior.images), imageStatuses: structuredClone(record.prior.imageStatuses) };
}
export function beforeW06002Raw(raw, slug) { … JSON.stringify(…, null, 2) + '\n' }
```

옛 테스트는 파일을 읽은 뒤 **새 작업부터 옛 작업 순으로** 되감기를 겹쳐 부른다.

```js
// tests/crown-portmap.test.mjs:127
const raw = beforeHarmanW03014Raw(beforeBssW04004Raw(beforeSamsungW04010Raw(beforeBssAlignmentRaw(
  beforeW032Raw(beforeW026Raw(readFileSync(…).replace(/\r\n/g,'\n'), slug), slug), slug), slug), slug), slug);
```

규칙 두 가지가 핵심이다.

1. **승인된 필드만 되돌린다.** 나머지 필드는 현재 값 그대로 옛 해시 검사에 넘긴다. 그래야 엉뚱한 필드가 몰래 바뀐 것을 옛 테스트가 계속 잡는다.
2. **승인 값 확인.** 되돌리기 전에 현재 필드가 "이 작업이 승인한 값"(`approved` 해시)과 같은지 본다. 다르면 예외를 던진다 — 이 작업 뒤 누군가 또 바꾼 것이다.

## 새 작업이 할 일

1. **고치기 전에** 대상 필드의 현재 값을 저장한다. 커밋 기준: 작업 브랜치를 만든 `origin/main`.
   - Port Map: 제품별 `portMap.items[]`의 좌표 필드만(`n`과 좌표). 전체 `portMap`을 저장하지 말고 **좌표만** — `label`·`desc`가 같이 되돌려지면 W-002의 변경까지 숨긴다.
   - 주요기능: 제품별 `features`(배열 전체. `text`만 바뀌고 `source`·순서는 그대로여야 한다).
2. 고친 뒤 승인 값 해시를 같은 기록에 넣는다.
   ```
   Work/기록/W-20261012-001-prior-coords.json
   { "<slug>": { "prior": { "items": [ {"n":1,"x1":…,"x2":…,"y":…}, … ] }, "approved": "<sha256 of current coord list>" } }
   ```
   기록 파일은 생성 스크립트로 만든다(손으로 쓰지 않는다). 공개 데이터의 사본일 뿐이라 커밋해도 된다.
3. `tests/w12001-history.mjs`(W-002는 `w12002-history.mjs`)를 위 최신 모양 그대로 만든다: `beforeW12001Product`, `beforeW12001Raw`.
4. `npm test`를 돌려 **깨진 테스트만** 찾는다. 각 테스트의 되감기 사슬 **가장 바깥(가장 새 작업 자리)**에 새 함수를 끼운다. 사슬이 없는 테스트(현재 상태를 보는 테스트)는 기대값을 새 값으로 갱신한다.
5. 새 작업 자신의 테스트를 하나 둔다: 바뀐 제품·표식 목록이 기록과 같고, **기록에 없는 제품의 해당 필드는 그대로**인지.

## 하지 말 것

- 깨진 옛 테스트를 지우거나 `skip`하기
- 옛 해시 값을 새 값으로 바꿔 넣기 (옛 시점의 사실을 지우는 것이다)
- 되감기에서 승인 필드 밖까지 되돌리기
- 기록 JSON을 손으로 편집하기

## 같은 파일을 연달아 고치는 두 작업

W-001(좌표) 병합 뒤 W-002(문장)를 시작하면 W-002의 되감기 사슬은 `beforeW12002 → beforeW12001 → …` 순서다. W-001의 `approved` 해시는 **좌표만** 보므로 W-002가 문장을 바꿔도 깨지지 않는다. 그래서 1번에서 "좌표만 저장"이 중요하다.
