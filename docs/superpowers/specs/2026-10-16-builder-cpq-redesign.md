# AV Portal Builder·CPQ 작업 화면 통합 디자인

작성일: 2026-10-16
상태: 사용자 검토용 설계
승인된 방향: 포털 공통 스타일 적용, Builder 3열·모바일 탭, CPQ 시작 동작 강조·견적표 우선 구조. 사용자 요청은 “https://seoulav.github.io/AV-Portal/cpq/, https://seoulav.github.io/AV-Portal/builder/ 2개소 디자인을 우리 컨셉에 맞게 수정해줘”이며 후속 선택은 “화면 구조까지 더 크게 변경”, “이 설계로 진행”이다.

## 목적과 현재 화면

두 작업 도구가 포털의 한 제품군으로 보이면서도 각각의 작업에 집중할 수 있게 한다. 2026-10-16 공개 화면 1280px·390px 관찰 기준, 포털은 푸른·보라 그라데이션, 밝은 배경, 반투명 흰 카드, 큰 둥근 모서리, 둥근 조작 요소를 쓴다. CPQ는 일부 토큰을 공유하지만 시작 버튼·자료·저장·출력이 비슷한 높이의 블록에 모여 있다. Builder는 평평한 도구 모음과 테두리 패널이 두드러지고, 390px에서는 긴 버튼 묶음과 라이브러리가 캔버스를 밀어낸다.

## 선택한 접근

포털·CPQ의 기존 색·폰트·표면 토큰을 재사용해 두 앱의 셸과 작업 배치를 맞춘다. CSS만 바꾸는 접근은 Builder의 모바일 작업 순서를 해결하지 못한다. 두 앱의 엔진이나 데이터 흐름을 새로 만드는 접근은 이번 디자인 요청을 넘는다. 따라서 컴포넌트 구조와 반응형 배치를 바꾸되 기존 작업 기능과 계산 결과는 보존한다.

## 공통 화면 언어

- AV Portal의 표시 방식(파랑→보라 정사각 마크, 파란 강조, 밝은 그라데이션 배경, 흰 반투명 카드, 둥근 칩·버튼)을 두 도구의 상단과 주요 면에 적용한다. 기존 CPQ 토큰이 기준이다. 별도 공유 패키지나 새 전역 CSS를 만들지 않고 앱별 토큰을 대응시킨다.
- 상단에는 앱 식별, 포털로 돌아가기, 현재 도구 이름을 분명히 둔다. 각 앱의 고유 기능은 헤더 아래 작업 막대에 둔다. 상태·버전·문서 이름은 조작 버튼과 혼동되지 않는 보조 정보로 표시한다.
- 강조색은 주된 시작·저장/내보내기 같은 한 단계의 대표 행동에만 사용한다. 비활성 버튼과 위험·경고 상태의 의미는 기존대로 유지한다.
- 공통 토큰을 적용하더라도 Builder의 선 종류 색, 장비 사진, 단자 상태색, CPQ의 견적 검증 상태색은 바꾸지 않는다. 다크 테마는 새 카드와 버튼에도 읽기 가능한 대비를 유지한다.

## Builder 화면

### 데스크톱

1. 상단: 포털 링크·AV System Designer 이름·베타 표시와 장비/연결 개수를 한 줄에 배치한다. 그 아래 도구 막대는 **프로젝트**(새 구성도, 열기, JSON/SVG/PDF 내보내기, 견적 만들기), **편집**(실행 취소·다시 실행·메모·영역), **보기**(케이블·자동 배치·잠금·격자·미니맵·테마)로 묶는다. 현재 버튼의 기능·비활성 조건·단축키는 그대로다.
2. 작업면: 왼쪽 라이브러리, 가운데 캔버스, 오른쪽 선택 항목/이슈를 3열로 둔다. 양쪽은 포털형 카드와 명확한 제목·검색/상태 구역을 갖고, 캔버스는 가장 큰 연속 편집면이다. 장비 노드 치수·좌표계·선 연결 규칙은 수정하지 않는다.
3. 새 구성도/빈 캔버스: 캔버스 안에 “왼쪽에서 장비를 검색해 ＋로 추가” 안내를 둔다. 안내는 장비 추가 후 사라지고 캔버스의 포인터·키보드 동작을 가리지 않는다.

### 모바일·좁은 화면

1. 상단 브랜드와 대표 프로젝트 동작을 간결하게 두고, 나머지 도구는 기능별 줄/메뉴에 담되 숨겨진 기능의 접근 경로를 명확히 표시한다.
2. `라이브러리 / 캔버스 / 선택 항목·이슈` 탭으로 한 번에 한 작업면을 보여준다. 새 빈 구성도에서는 라이브러리를, 저장된 구성도에서는 캔버스를 기본 표시한다. 라이브러리의 기존 `＋` 버튼으로 장비를 추가하면 캔버스가 보이게 한다. 탭 전환은 화면 상태일 뿐 구성도 JSON·자동 저장 데이터에 들어가지 않는다.
3. 캔버스는 충분한 높이를 유지한다. React Flow 인스턴스·장비 선택·줌 상태를 탭 전환마다 재생성하지 않는다. 감춰진 상태에서 크기 0을 기준으로 장비를 놓지 않도록, 표시 후 위치·화면 크기를 갱신한다. 태블릿 중간 폭에서도 버튼, 3열 경계, 이슈 텍스트가 잘리지 않게 한다.

## CPQ 화면

1. 상단은 포털 링크·AV 견적 산출기 이름·회사 표기를 Builder와 같은 셸 원칙으로 정리한다. 공식 참고 자료는 접근 가능한 별도 자료 카드로 유지하되 처음 시작할 때의 주 행동보다 강하게 보이지 않게 한다.
2. 문서가 없을 때의 주 카드에는 `구성도 JSON 열기`와 `품목 직접 선택`을 나란히(모바일에서는 위아래) 두고, 두 선택의 용도를 짧게 설명한다. 작업 파일 열기/저장은 별도 보조 그룹이다. 기존 파일 선택·불러오기·작업 재개 동작을 그대로 호출한다.
3. 문서가 열리면 현재의 **확인 목록 → 견적표 → 접기 영역** 순서를 유지한다. 견적표를 주 작업면으로 두고 왼쪽 탐색, 경고/검토, 참고·시공·간접비 영역의 계층을 카드·간격·섹션 제목으로 정리한다. 0/1/2 출력 등급과 Excel 다운로드는 같은 출력 그룹으로 묶되 선택 의미와 다운로드 게이트를 바꾸지 않는다.
4. 모바일에서는 시작 선택, 파일 작업, 출력 순으로 읽히게 배치하고 견적표의 기존 가로 스크롤을 유지한다. 고정 헤더나 하단 버튼이 입력 칸·오류 안내·표를 덮지 않아야 한다.

## 접근성·회귀 경계

- 버튼의 실제 라벨, 비활성 조건, 키보드 단축키, 파일 열기·저장·출력, 견적 계산, 구성도 JSON 형식·자동 저장은 유지한다.
- 모바일 탭은 버튼과 `aria-selected`/패널 연결로 키보드와 화면 읽기 도구에서 상태를 알 수 있어야 한다. 포커스 이동이 캔버스 단축키를 방해하지 않도록 확인한다.
- 빈 상태, 자료 로딩/오류, 선택한 장비·연결, 확인 이슈, CPQ 문서 없음/편집/오류, 다크 테마를 각각 확인한다. 줄바꿈과 대비가 작은 글자를 읽기 어렵게 만들면 조정한다.
- Portal 제품 데이터, Builder 라이브러리 생성기, 견적 계산 엔진, PDF/Excel 데이터 형식, 단자 색상은 범위 밖이다.

## 구현 위치와 검증

- Builder: `builder/src/App.tsx`, `builder/src/components/Toolbar.tsx`, `LibraryPanel.tsx`(모바일 ＋ 후 전환 연결), `builder/src/styles.css` 및 필요한 UI 상태 검사를 예상한다. 엔진·상태 저장 코드는 건드리지 않는다.
- CPQ: `cpq/src/app/App.tsx`, `cpq/src/styles/{tokens,base,workspace}.css` 및 필요한 UI 검사를 예상한다. 계산·출력 서비스는 건드리지 않는다.
- 독립 앱으로 빌드한 뒤 Builder/CPQ 타입 검사·단위/E2E 검사를 실행한다. 1280px·768px·390px에서 빈 화면과 작업 중 화면을 시각 확인한다. 기존 기능의 시작·추가·편집·열기·저장·내보내기를 시험한다. 저장 형식과 산출물 비교, 브라우저 오류·원치 않는 페이지 가로 넘침을 확인한다.
- 공개는 별도 브랜치/PR에서 검증 뒤 병합하고 Pages 배포 후 두 URL의 데스크톱·모바일 화면을 다시 확인한다. 작업 중 다른 PR이 앱 파일을 바꾸면 최신 main에 맞춰 재검토한다.

## 비고

디자인 변경은 현재 공개된 포털 스타일을 기준으로 한 해석이다. 카피·라벨의 세부 표현은 구현 중 기존 기능 의미와 충돌하지 않는 범위에서 다듬는다. 새 브랜드 자산이나 외부 UI 라이브러리 도입은 예정하지 않는다.
