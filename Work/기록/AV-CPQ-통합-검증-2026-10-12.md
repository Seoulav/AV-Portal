## 구성도 호환

`version`, `nodes`, `edges`, `lineTypes`를 그대로 읽고 CPQ의 `parseDiagram → diagramToQuote`를 재사용한다. Builder 1.2의 기존 필드 이름·의미를 바꾸지 않았다. 기존 Builder 정규화에서 빠지던 `systemName`, `selectedOptionQuantities`, `optionPortIds`, 최상위 `options`를 저장·열기·복사 경로에 추가했다. 메모/도형은 견적 장비에서 제외하고 알 수 없는 장비 타입은 조용히 버리지 않는다.

같은 장비 노드 2개는 CPQ 기존 규칙으로 수량 2로 합산한다. 시스템이 다르면 기존 분리 규칙을 유지한다. 케이블·커넥터는 CPQ 기존 규칙대로 첫 시스템에 귀속하며 수신 안내에 이를 표시한다. 시스템별 케이블 자동 재배분이나 기존 견적 자동 병합은 구현하지 않았다.

## 직접 구성한 합성 사례

실제 Portal 라이브러리와 승인 CPQ 자료를 사용했다. 제품/자산 응답을 모킹하지 않았다. 현장과 구성은 가상이다.

1. Builder 화면에서 Sony SRG-A40 2대와 RTCOM HD-13U 1대를 추가했다.
2. 시스템을 “가상 회의실 A”로 지정하고 첫 카메라에 RM-IP10 1개를 견적 옵션으로 추가했다. 옵션 선택은 호환성 인증이 아니다.
3. 카메라 HDMI 출력에서 분배기 입력까지 마우스로 연결하고 케이블 UMC-002 1개를 입력했다.
4. `견적 만들기`로 CPQ를 열었다. 확인 전에는 Excel 버튼이 차단됐다.
5. 표시된 기존 노무 근거를 4개 행에서 확인했다. 임의 가격이나 수동 노무 값으로 통과시키지 않았다.
6. 영업팀용 0, 공유용 1, 고객용 2등급 Excel을 실제 다운로드했다. 영업팀용은 기존 명시 확인창을 거쳤다.

## 원가 및 저장 경계

구성도는 허용 필드만 새 객체로 만들고 정확한 origin/상대 창/전송 ID를 검증한 메모리 메시지로 전달한다. URL, 전송 저장소, 서버 업로드가 없다. CPQ 원가 모듈은 기존 메모리 세션을 유지한다. 전달 필드에 합성 원가 키를 섞는 시험에서 작업 파일·localStorage·sessionStorage에 표식이 없었다. 기존 합성 원가 E2E 및 출력 경계 시험도 포털 경로에서 실행했다. 온라인·오프라인 요청 URL/헤더/본문, 웹소켓, 콘솔, localStorage/sessionStorage, IndexedDB/Cache 이름과 작업 파일 표식 검사를 통과했다.

Portal은 스크롤 위치, Builder는 구성도와 테마를 자체 저장한다. CPQ는 이 스크립트를 로드하지 않고 원가 상태를 Builder에 주지 않는다. 조사한 코드에 분석 스크립트·서비스 워커 등록은 없으며 새 시험 브라우저의 CPQ 서비스 워커 등록은 0이었다. **실제 사용자 브라우저에 과거에 등록된 동일 origin 서비스 워커 상태는 미확인**이다. 경로 분리는 origin 보안 격리가 아니다.

## 남은 범위와 검토 사항

- 공개 `https://seoulav.github.io/AV-Portal/cpq/` 배포·검증은 하지 않았다. 로컬 정적 서버에서 같은 `/AV-Portal/` 경로 구조를 검증했다. GitHub 원격 CI도 미실행이다.
- 기존 외부 CPQ의 삭제·리다이렉트를 적용하지 않았다.
- 원본 의존성 lock을 보존했다. `npm audit --omit=dev`는 기존 fflate 0.8.2의 조작된 ZIP64 해제 무한루프 공지 1건(moderate, GHSA-px8p-9vwx-vf98)을 보고했다. 통합 범위에서 의존성 업그레이드는 하지 않았다.
- Node PDF 검사에서 선택적 canvas polyfill 부재 경고, Vite에서 큰 청크 경고가 있었으나 해당 검사/빌드는 성공했다.
- 새 견적 생성까지만 지원한다. 수정 구성도로 기존 견적 자동 덮어쓰기·비교·수동 수정 병합은 후속 설계 대상이다.
