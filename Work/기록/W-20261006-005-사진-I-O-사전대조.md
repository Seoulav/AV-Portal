# W-20261006-005 후면 사진·I/O 사전 대조

2026-10-12, 구현 전에 게시된 `Rear` WebP 12장과 제품별 `io` 행을 직접 열어 대조했다. 명세의 "사진과 `io`가 크게 다르면 구현 전에 물어본다"는 조건에 따라 질문했고, 사용자는 **"보이는 단자만 표시하고 12종 진행"**을 선택했다. 이어 `mxcw640`·`mxa925w-r`은 일치하는 단자가 0개이고 현행 `validMap`이 `items.length > 0`을 요구한다는 점을 따로 설명하자, 사용자는 **"10종 지도 + 2종 사유 기록"**을 선택했다. 따라서 12종 전체를 판정하되 지도는 근거가 있는 10종에만 만든다.

| 제품 | 후면 사진에서 확인된 것 | `io`와 맞지 않거나 보이지 않는 것 | 사전 판정 |
|---|---|---|---|
| `srg-a40` | SDI·HDMI·LAN·VISCA IN/OUT·MIC·DC | GENLOCK/TC는 `quantity=0`, `Not available`이므로 번호 제외 | 진행 가능 |
| `sx-1216-rti` | C13 콘센트 4+4+2=10개, 전원 케이블·트리거 단자 | `io`는 C13 수량 **11**이라고 하며 `source=IMG` | 사진에 보이는 10개만 번호화; 불일치 유지 |
| `dm3` | 입력 XLR/콤보 16, 출력 XLR 8, Dante 2, LAN, USB-B, DC | USB-A·헤드폰은 이 후면 사진에 안 보임 | 보이는 6행만 가능 |
| `rio1608-d3` | Dante Primary/Secondary, 제어 LAN | 입력 XLR 16·출력 XLR 8·헤드폰은 **전면 사진**에 있음 | 후면 2행만 번호화 |
| `mxcw640` | 충전 접점과 기구 구조 | 마이크·헤드폰·Micro-USB·NFC 등 `io` 네 행의 단자가 안 보임 | 0/4 · 지도 없음 · 02 폴백 유지 |
| `ulxd1` | 윗면 TA4M와 안테나 SMA | 없음 | 진행 가능 |
| `mxcwapt-w` | XLR Analog out | RJ45·PoE가 안 보이며, 사진에는 `io`에 없는 Analog in도 있음 | XLR 출력만 번호화 |
| `mxa925w-r` | 닫힌 접속부 덮개와 장착 구조 | RJ45·PoE 세 행 전부 덮개 안에 가려짐 | 0/3 · 지도 없음 · 02 폴백 유지 |
| `slxd4d-plus` | 안테나 BNC 2, 채널별 XLR/6.35mm 출력, LAN, DC | 없음 | 진행 가능 |
| `slxd1-plus` | 윗면 TA4M | 없음 | 진행 가능 |
| `ua844-swb` | BNC 입력·분배 출력, 전원 입력·분배 출력 | 없음. W-004 새 게시 사진 2960×600 기준 | 진행 가능 |
| `ua845uwb` | BNC 안테나·분배 출력, AC 입력·DC 출력 | 없음. W-004 새 게시 사진 3140×700 기준 | 진행 가능 |

| 제품 | 번호 ↔ `io` 행(0부터) | 지도 항목 수 | 번호를 뺀 것 |
|---|---|---:|---|
| `srg-a40` | 1→0, 2→1, 3→2, 4→3, 5→4, 6→5, 7→6 | 7 | 7번 GENLOCK/TC 미지원 |
| `sx-1216-rti` | 1~3→0, 4→2 | 4 | 전원 플러그 형상 불명, 사진에 없는 11번째 C13 |
| `dm3` | 1~4→0, 5~6→1, 7→2, 8→3, 9→4, 10→7 | 10 | USB DEVICE·Phones는 다른 면 |

| `mxcw640` | 없음 | 0 | 4행 전부 후면에 단자 미노출; 충전 접점은 Micro-USB와 다른 형상 |

| `ua845uwb` | 1~4→0, 5~6→2, 7→1 | 7 | Cascade BNC·AC pass-through는 별도 `io` 근거가 없어 미표시 |

묶음은 같은 종류·기능의 붙은 단자만 한 범위로 표시했다. `dm3`의 두 줄 XLR은 사진의 실제 구역에 맞춰 4개씩 나누고, `ua845uwb`의 DC 출력 4개는 RF 단자를 사이에 두므로 B·A 두 구역으로 나눴다. `ulxd1`·`slxd1-plus`는 세로 사진에 맞춰 좌·우 마커를 썼다. 이 기록은 `io` 값을 고치거나 단자 수를 새 사실로 확정하는 근거가 아니다.

같은 공개용 렌더러를 로컬에서 사용해 12종 × 1280px·390px의 수정 전후 48장을 캡처했다(`tmp/w005-screens/`, 로컬 검토용). 두 폭 모두 12/12 페이지에서 문서 가로 넘침과 JavaScript 오류가 0건이었다. 수정 후 10개 지도에서 원형 번호는 사진 바깥 여백에 있고, 두 제외 제품의 02 카드는 기존 `io` 폴백 그대로다. 1280px 육안 검토에서 `ua845uwb` DC 네 단자를 처음에는 한 괄호로 가로질러 RF 단자까지 포함한 오류를 발견했다. B·A 두 구역으로 나누고 다시 캡처했다. 390px에서는 넓은 후면 사진에 좌우 스크롤 안내가 표시되며, 사진을 이동해 전체 단자를 확인한다.

`W-20261006-005-approved-maps.json`은 10종의 승인된 지도 해시와 지도 외 제품 데이터의 기준 해시를 저장한다. `tests/w06005-history.mjs`는 현재 제품을 입력받아 예상 지도가 정확할 때에만 **`portMap` 하나만** 되돌린다. 나머지 필드는 현재 값 그대로 과거 검사에 전달하며, I/O를 메모리에서 바꾼 경우 옛 원문과 달라지고 마커를 바꾼 경우 예외가 나는 전용 검사로 확인했다. 제품 JSON 전체를 과거 바이트로 바꾸는 shim은 사용하지 않았다.
