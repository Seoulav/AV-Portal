## B — RS-232C 출력 설명

### 지금 입력과 출력에 같은 문장이 있습니다

| 번호 | 라벨 | `desc` |
|---|---|---|
| 9 | RS-232C **입력** | `RS232C 어댑터를 이용하여 MDC를 연결할 때 사용합니다.` |
| 10 | RS-232C **출력** | **같은 문장** |

**삼성 매뉴얼이 두 줄에 같은 설명을 적어 놨습니다.** 제가 QMC 20쪽과 115인치 15쪽을 직접 읽어 확인했습니다. 우리 데이터는 **매뉴얼을 충실히 베낀 결과**입니다.

**그런데 읽는 사람에게는 틀린 안내가 됩니다.** 출력에 MDC를 꽂으면 안 됩니다.

### ★ 우리 데이터에 이미 맞는 기록이 있습니다

```json
{ "connector": "RS-232C 출력", "signal": "외부 제어(루프아웃)", "direction": "OUT", … }
```

**`io`는 `루프아웃`으로 제대로 적혀 있습니다.** 틀린 건 **Port Map의 `desc` 하나뿐**입니다.

다른 제조사 제품에도 맞는 표현이 있습니다.

```
novastar-h2  7번 RS-232 출력 — "직렬 제어 신호를 다음 장치로 전달합니다."
```

**우리 저장소 안에서 삼성만 어긋나 있습니다.**

### 대상 7종

| 제품 | 번호 |
|---|---|
| `lh115qhfebgxkr` | 10 |
| `lh32qmcebgcxkr` | **5** |
| `lh43qmcebgcxkr` · `lh85qmcebgcxkr` · `lh98qmcebgcxkr` | 10 |
| `lh43qhcebgcxkr` · `lh75qhcebgcxkr` | 10 |

**입력(9번·4번)은 건드리지 마세요.** 그 문장은 맞습니다.

### 출처는 사용자 확인으로

**매뉴얼에 없는 문장을 매뉴얼 출처로 달면 안 됩니다.** 저장소에 이미 쓰는 방법이 있습니다.

```json
{ "code": "U1", "name": "사용자 현장 확인(2026-10-04) — VXT Player 지원 여부", … }
```

새 코드를 만들든 `U1` 범위를 넓히든 **정하시되, 사용자 확인임이 드러나야** 합니다.

### 문장은 정하세요

뜻만 지키면 됩니다.

- **다음 디스플레이로 RS232 명령을 넘긴다**
- **MDC를 꽂는 자리가 아니다**
- `novastar-h2`의 **"다음 장치로 전달합니다"**와 결이 맞게

`desc`는 **사람이 읽는 글**입니다. 짧고 분명하게.
