## 통합안

권장: 루트 `cpq/`에 CPQ 소스를 별도 npm 프로젝트로 두고 빌드 산출물만 `/AV-Portal/cpq/`로 배포한다. Builder와 계산 코드의 관리 경계를 유지한다.

대안: 기존 사이트 외부 링크는 빠르지만 요청한 포털 경로를 충족하지 않는다. iframe은 모바일·다운로드·초점 이동 검증 부담을 늘리므로 선택하지 않는다.

1. 독립 체크아웃에 통합 기록과 파일 허용 목록을 만든다. 검증 소스를 특정 커밋에서 반입한다.
2. Builder의 저장·재열기에서 systemName, selectedOptionQuantities, optionPortIds, options를 보존하도록 추가 필드를 설계한다. 없는 정보는 임의 생성하지 않는다. 실제 시스템 구분 입력과 옵션 선택 UI 범위는 구현 명세에서 확정해야 한다.
3. `견적 만들기`는 CPQ 탭을 열고 브라우저 메모리 메시지(postMessage/MessageChannel)로 허용 필드만 전달한다. origin, 상대 창, 전송 식별자, 형식·크기, 준비 완료 응답을 확인한다. 본문을 URL이나 영구저장소에 넣지 않는다. 반복 수신·응답 지연·취소·팝업 차단을 처리한다.
4. CPQ 수신 입구는 장비가 아닌 메모·도형을 제외한 뒤 기존 parseDiagram → diagramToQuote로 새 견적을 만든다. 기존 파일 가져오기에서도 같은 구분을 적용한다. 가격·품셈·계산 로직을 별도로 구현하지 않는다.
5. 기존 onBeginLoad의 순서 보호와 mayReplaceDocument의 미저장 확인을 공통으로 거친다. 실패·취소 때 현재 견적을 보존한다. 기존 견적과 자동 병합하지 않는다.
6. 포털 메뉴에 구성도·견적을 두고 CPQ에 포털 복귀 링크를 둔다. 직접 접속은 품목 선택 화면을 연다. 새로고침 후 자동 재수신으로 작업을 덮지 않는다. 현행 미저장 이탈 경고와 작업 파일 재열기를 유지한다.
7. Pages 빌드에 CPQ 독립 설치·검사·빌드와 산출물 복사를 추가한다. main 병합은 공개 배포를 촉발하므로 결과 보고 전에는 하지 않는다.

## 원가 경계

코드에서 CPQ PrivateCostSession은 원가를 메모리에만 두며, 작업 파일 encodeWorkFile은 허용 스키마로 검증한다. 실제 유출 방지 통합 검증은 아직 하지 않았다.

Portal app.js는 스크롤 위치를 sessionStorage에 기록한다. Builder는 `av-portal-builder:current`와 rejected 키에 구성도를 자동 저장하고 테마도 저장한다. CPQ 화면에 Portal/Builder 스크립트를 불러오지 않고 CPQ 원가 상태를 전달 객체·Builder 상태·로그에 연결하지 않는다.

조사한 소스에서 분석 스크립트·서비스 워커 등록은 발견하지 못했다. 실제 사용자 브라우저의 같은 origin에 이미 등록된 서비스 워커 유무는 미확인이다. 경로가 달라도 같은 origin의 저장소는 공유되므로 경로 분리만으로 보안 경계가 생긴다고 주장하지 않는다.
