# W-20261004-014 — 세로 Port Map 높이 상한 근거

## 원인과 계산

기준 main `d29179303060fdbfedc69d54d02c8d2a323cd689`에서 52종의 지도를 1280px·390px로 캡처했다. `lh115qhfebgxkr`의 게시 사진은 270×850이며, 폭 680px을 일괄 적용한 SVG 좌표 높이는 **2,220.74px**였다. CSS의 `min-width:560px`까지 적용된 실제 표시 높이는 데스크톱 **2,179.83px**, 모바일 **1,636.33px**였다.

명시된 `displayWidth`가 없을 때만 사진 폭을 `min(680, (900−80)×원본가로/원본세로)`로 정한다. 좌우 여백 40px씩을 더해 이 제품의 SVG는 **340.47×900px**가 된다. 자동 축소에 걸린 지도에서만 기존 CSS의 최소 폭 560px을 인라인 `min-width:0`과 `max-width:계산된 폭`으로 제한했다. 이를 빼면 좌표만 줄어도 브라우저가 지도를 다시 키워 화면 상한을 지키지 못한다. 명시된 `displayWidth`는 기존 경로를 그대로 쓴다.

| 화면 폭 | 이전 실제 지도 폭×높이 | 이후 실제 지도 폭×높이 | 가로 넘침 |
|---:|---:|---:|---:|
| 1280px | 746×2,179.83px | **340.47×899.98px** | 0 |
| 390px | 560×1,636.33px | **298×787.72px** | 0 |

명세는 두 번째로 큰 `srg-x40uh`를 800px로 예상했지만, 실제 브라우저에서는 `crop`이 반영돼 약 **456.80px**다. 기존 51종의 실제 최고는 1280px에서 `ua864a` **746px**였다. 어느 쪽이든 상한 900px을 넘는 기존 지도는 없었다.

## 900px과 각인 판독

**900px은 이번 제품의 과도한 세로 스크롤을 줄이는 상한으로 적정하다.** 1280px에서 기존 2,180px의 약 41%, 390px에서 1,636px의 약 48%로 줄면서 11개 번호와 설명 목록은 유지된다. 더 낮추면 어두운 사진의 실물 단자 판독성이 더 나빠질 수 있어 이 작업에서 임의로 줄이지 않았다.

축소 후에도 카드 돋보기는 원본 사진만 비추고 번호 레일은 가리지 않는다. [USB 390px](W-20261004-014-screens/lh115qhfebgxkr-loupe-usb-390.png), [HDMI 3(ARC) 390px](W-20261004-014-screens/lh115qhfebgxkr-loupe-hdmi-390.png), [RS-232C 390px](W-20261004-014-screens/lh115qhfebgxkr-loupe-rs232-390.png)에서 각인을 식별했다. 1280px에서도 같은 세 지점을 확인했고 JS 오류가 없었다. **돋보기 없이 390px에서 작은 어두운 각인은 여전히 직접 읽기 어렵다.** W-010의 판정을 뒤집지 않으며, 다른 디스플레이로 일괄 확대하는 근거로 삼지 않는다.
