# W-20261012-004 — 카메라 SIGNAL FLOW 근거표

- 기준: `origin/main` `e6d987e2b4bb58e8ce58197697f1b1ba489a333a`.
- 사용자 요청: 2026-10-12 “카메라들은 signalflow 추가해줘”. 기존 BRC-AM7·SRG-A40의 `type: camera` 구조와 표시 범위를 따랐다.
- 사용자 정정: Sony SRG-X40UH의 `io[4]`는 VISCA over IP·PoE+만 확인되며 IP 영상 스트리밍은 공식 사양에 정보 없음·`REVIEW REQUIRED`이므로 영상 출력에서 제외한다.

| 제품 | 흐름 노드·경로 | 근거 |
|---|---|---|
| SRG-X40UH | 촬영 장면 → 영상 캡처·처리 | `specifications[0]` 이미지 센서 |
| SRG-X40UH | 캡처 → HDMI OUT, 최대 4K | `io[0]` HDMI 출력·SYSTEM SELECT 조건 |
| SRG-X40UH | 캡처 → USB-C UVC OUT, 최대 1080p | `io[1]` UVC 출력·4K/인터레이스 미출력 |
| SRG-X40UH | VISCA RS-422 IN → OUT | `io[2]` 입력·`io[3]` 출력, 데이지체인 |
| SRG-X40UH | LAN → 캡처 제어·PoE+ | `io[4]` VISCA over IP·PoE+; **영상 출력 아님** |
| TR335·TR315 | 촬영 장면 → 영상 캡처·처리 | 각 제품 `specifications[0]` 이미지 센서 |
| TR335·TR315 | 캡처 → 3G-SDI·HDMI·IP·USB 동시 출력 한 묶음 | 각 제품 `io[0]` 4매체 동시 출력, `io[1]` USB3.0 UVC 세부 정보. SDI는 1080p60까지, USB MJPG는 2160p까지 |
| TR335·TR315 | RS-232/422·CGI(IP) 제어 → 캡처 | 각 제품 `io[2]` |
| TR335·TR315 | PoE+·Ethernet → 캡처 | 각 제품 `io[3]` |

TR335와 TR315는 `io[0..3]`의 구성과 동시 출력 문구가 같아서 흐름을 복사했다. 다만 각 노드의 `evidence`는 **해당 제품 자신의 행**을 가리킨다. 네 매체를 하나의 출력 노드로 묶어 `io[0]`의 4를 보존하고, 별도 USB UVC 세부 행을 다섯째 매체나 별도 물리 포트로 단정하지 않았다. 전원과 IR은 기존 BRC-AM7·SRG-A40 흐름의 표시 범위를 따라 노드에서 생략했다. IR 수신부 자체가 제어 신호가 아니라는 뜻은 아니다. SRG-X40UH의 IP 영상 스트리밍은 공식 사양에 정보가 없어 제외했으며, 근거가 생기면 별도 검토 대상이다.

기존 BRC-AM7·SRG-A40 흐름과 CL01·RM-IP10·RM-IP500의 흐름 부재는 고정 해시로 확인했다. 새 3종은 `signalFlow` 외 필드가 변경되지 않았음을 현재 제품의 선택적 역변환 해시로 확인하고, `io` 변이가 과거 해시 검사에 드러나는 반례를 검증했다. 1280px·390px에서 03 카드가 열리고 가로 넘침·JS 오류가 없다. 390px의 흐름 그림은 기존 설계대로 카드 안에서 좌우로 스크롤한다.
