# W-20261004-032 — PDF 보기 범위 보완

2026-10-05 구현 중 Sony 한글 설명서의 표지는 보이지만 본문 한글이 빠지는 결함을 발견했다. 사용자의 원래 요청은 카메라 8종에서 문서를 **보기와 내려받기 모두** 할 수 있게 하는 것이었다. 사용자는 질문에 “이번에 최소 수정 포함”이라고 답했고, 클로드 한도 중 임시 기획·리뷰 담당자도 같은 범위의 판단을 전달했다. 특정 기술 해법을 사용자가 새로 확정한 것은 아니다.

기존 상세 카드 렌더러 변경 금지에는 예외를 만들지 않는다. PDF 뷰어에 한해 PDF.js **4.10.38**의 공식 CMap·표준 글꼴 지원 자료와 로딩 옵션을 추가한다. CMap은 글꼴 자체가 아니라 PDF 문자 코드의 매핑 자료다. PDF.js 본체, 원본 PDF, 상세 카드, 비밀번호·다운로드 정책은 바꾸지 않는다.

## 수정 전 원인 확인

- Sony `SRG-A40/A12`, `SRG-X40UH/H40UH`, `RM-IP500` 한글 PDF의 **4쪽**: 표지나 페이지 수는 정상이나 본문 글리프가 보이지 않음. [수정 전 캡처](W-20261004-032-screens/sony-srg-a40-a12-manual-ko-p4.png).
- 기존 삼성 QBC·QHC·QMC·SHC와 QPDX-5K·QHFX 한글 설명서 **각 3쪽**, 기존 RM-IP10 영어 설명서 **3쪽**: 수정 전에도 본문 표시. [기준 캡처](W-20261004-032-screens/baseline-samsung-qbc-qhc-qmc-shc-manual-ko-p3.png). 따라서 “기존 한글 PDF 전부가 빈 화면”은 사실이 아니다.
- 기존 `vendor/pdfjs/`에는 엔진·worker만 있고 `cmaps/`와 `standard_fonts/`가 없었다. CMap 없이 Sony 4쪽의 한글 추출은 0자였으며, 같은 버전 CMap을 지정하자 3건 모두 100자 넘게 복원되고 브라우저 글리프도 보였다. 원본 PDF 바이트는 그대로다.

## 정확한 변경

| 파일 | 변경 |
|---|---|
| `beta/site/vendor/pdfjs/cmaps/` | 공식 `pdfjs-dist@4.10.38`의 CMap 169파일·1,167,747바이트. 배포본의 라이선스 포함 |
| `beta/site/vendor/pdfjs/standard_fonts/` | 같은 배포본의 표준 글꼴 16파일·780,306바이트. Foxit·Liberation 라이선스 포함 |
| `beta/site/shared/pdf-viewer.mjs` | 기존 `getDocument()`에 같은 출처 `cMapUrl`(끝 `/`), `cMapPacked: true`, `standardFontDataUrl`만 추가. `isEvalSupported: false` 유지 |
| `beta/verify-pages.mjs` | 새 지원 자산 디렉터리가 공개 배포 목록에 있어야 함을 확인 |
| `tests/pdf-viewer-fonts.test.mjs` | Sony 3건 4쪽의 실제 한글 추출과 설정 회귀 검사 |

지원 자산 증가분 **1,948,053바이트(약 1.86 MiB)**. 공급처는 npm 공식 배포 패키지 `pdfjs-dist@4.10.38`; 내려받은 tarball SHA-256 `1011b38553532d7078c59f26b15a471f8daE00f101b60e2add9b8511737a1ce0`(대소문자 무관). 기존 `VERSION.txt`도 4.10.38이다. 엔진·worker 버전 교체 없음.

## 확인 기준

- Sony 3건 **4쪽 한글 본문**: [A40 1280px](W-20261004-032-screens/sony-a40-popup-p4-1280-after.png) · [A40 390px](W-20261004-032-screens/sony-a40-popup-p4-390-after.png), X40UH·RM-IP500도 같은 두 화면에서 확인. 표지·HTTP 200만으로 판정하지 않았다.
- 기존 삼성 한글·RM-IP10 영어 문서의 수정 전후 페이지를 비교했고, PDF.js 지원 자산의 HTTP 오류 및 JS 오류가 없었다.
- 잠긴 삼성 PDF는 비밀번호 입력 전 내려받기 `href`가 없고 입력창이 나타난다. [390px 캡처](W-20261004-032-screens/locked-samsung-prompt-390-after.png). 기존 `verifyPdfLock` 검사도 유지한다.
- 8종의 PDF 보기·내려받기, 페이지 이동·확대는 실제 팝업과 다운로드로 확인한다. 검사 결과는 `Work/지시서.md`와 Work 인계서에 기록한다.
