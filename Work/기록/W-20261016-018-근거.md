**계산 결과(원문 직접 인용과 구별)**: 2×2 4K60 화면은 출력4개 × 용량2 = 출력링크8개. VPU1개를 사용하고 소스링크8÷용량2 = 4K 믹싱4개, split8개. 최대 VPU 수에 따라 Cmini/C/C+/Cmax는 같은 화면을 각각1/2/3/4개 구성. 모든 모델의 화면당 값은4/8이며, 시스템 전체4K mix/split은4/8·8/16·12/24·16/32. 출력 그룹화·회전 등 별도 조건을 추가한 시나리오는 이번 계산에 포함하지 않음.

- 브로슈어 [Quick Overview 7쪽](https://dwn01.analogway.com/Site+Internet/Series/Aquilon/Common/Brochure/brochure-Aquilon-april2026-web.pdf#page=7): Cmini/C/C+/Cmax 열 순서. 영어 행명 `4K60p input connectors`:8/16/24/32; `4K60p output connectors`:12/16/20/24; `Max 4K mixing layers`:4/8/12/16; `Max 2K/DL mixing layers`:8/16/24/32; `Rack units`:3/4/5/6. 각주 `1) Up to`, `3) Doubled for split layers`.
- 브로슈어 SHA-256: `124c2fb363afec992027d02e7db14c7612666ad38ce69bbdab2fc276701f75ff`. 기존 게시본을 공유하는 uploads4행만 추가하며 PDF 파일은 추가하지 않음.
- layerPlan의 기존 키 `splitLayers2k`는 현행 UI에서 4K 분할 수를 표시하는 레거시 키다. 기존 RS와 동일하게 mix4K×2를 넣었으며 스키마·키 의미를 임의 변경하지 않음.
- `rs1DatasheetPage`는 기존 계약이 요구하는 레거시 키를 유지. C의 Region Captive 설명 근거는 각 C 전용 데이터시트6쪽(C+8쪽) 및 공용 매뉴얼83쪽이다. RS 데이터시트를 C의 숫자 근거로 쓰지 않음.
- 화면당 출력링크8개 이하를 여러 VPU에 분산할 수 있는지, 혼합용량 PiP의 비용, Region Captive의 절감 산식은 미확인으로 유지. 배경은 매뉴얼101쪽의 출력과 같은 용량·비확대 조건 유지.
