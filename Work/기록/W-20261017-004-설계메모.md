- 상태: **설계 준비 완료 · 시안 구현 대기**. W-20261017-003 **1부 레이어 연출 기준 카드 병합 후** 시안을 만든다.

## 화면 구성

1. **머리말**: 제조사명, 공식 소개에 근거한 한 문단, 비교표와 설계 가이드로 가는 페이지 내부 링크. 소개 문구는 시안 착수 때 공식 자료 문장을 대조해 작성한다.
2. **시리즈 카드 4개**: Aquilon RS·C(카드 안에서 RS/C 두 하위 묶음), Alta 4K, Midra 4K, 컨트롤러. 현재 카탈로그의 Analog Way 16항목 중 프로세서 15종과 컨트롤러 RC400T 1종을 모두 담는다. 모델 ID 목록은 내비게이션 순서만 결정하고 수치를 저장하지 않는다. 카드의 모델 이름·상세 링크는 카탈로그와 제품 JSON에서 읽는다.
3. **시리즈별 모델 비교표**: Aquilon RS 7종, Aquilon C 4종, Alta 2종, Midra 2종을 나눠 제시한다. 열은 입력, 물리 출력/프로그램 출력, 4K 화면 수, 4K 믹싱 레이어(화면당/장비 전체), RU, 전원. 단위·전제(BTO 최대, 미러링, Mixer/Matrix/Blend 모드)를 셀 또는 열 머리에서 밝힌다. 각 행의 모델명을 `detail/?product=<slug>`로 연결한다. 390px에서는 표 내부만 가로 스크롤하고 페이지 `scrollWidth`는 390을 유지한다.
4. **화면·레이어 설계 가이드**: W-019의 계산기와 예시를 재사용하며 같은 계산 함수를 두 번째로 구현하지 않는다. 종합 페이지에서는 짧은 설명과 가이드 진입을 우선하고, 실제 카드 재사용·마운트 방식은 W-003 1부 병합본의 API를 보고 확정한다.
5. **레이어 연출 기준**: W-003 1부가 제공하는 카드의 시리즈별 규칙과 예시를 재사용한다. 제품별 숫자와 규칙을 새 문장으로 복제하지 않는다. 1부 병합 전에는 자리와 흐름만 설계한다.
6. **문서 모음**: 제품 `documents`의 실제 `Brochure`·공용 `User Manual` 링크만 시리즈별로 모으고 `url` 또는 `file` 기준 중복을 제거한다. `MISSING`/링크 없음은 제외한다. 로컬 PDF는 `docs/manifest.json`과 기존 `resolveDocumentAction`의 보기·다운로드·잠금 규약을 따른다. 새 PDF를 게시하지 않는다.

## 데이터 읽기 계약과 불일치 시험

- 모델 진입점은 `beta/site/catalog.json`의 `brand === "Analog Way"`인 공개 장비다. 상세 JSON은 `beta/site/detail/data/<slug>.json`에서 읽고 `manufacturer`, 모델명, 링크용 slug를 대조한다. RC400T는 컨트롤러 카드에만 넣으며 프로세서 비교표에는 넣지 않는다. 현재 15개 프로세서의 모든 JSON에는 자기 slug와 일치하는 `layerPlan.models` 또는 `videoLayerPlan.models` 행이 **정확히 하나** 있다. 각 모델의 **자기 JSON 안의 자기 행만** 읽는다. 다른 제품 JSON에 복제된 동일 시리즈 행을 권위값으로 쓰지 않는다.
- Aquilon 11종: `layerPlan.models[slug]`에서 `inputs4k`, `outputConnectors4k`, `programOutputs4k`, `screens2x2`, `mixingLayers4kPerScreen`, `mixingLayers4k`를 읽는다. `screens2x2`는 **2×2·4출력 4K 화면 수**이지 일반적인 독립 출력 화면 수가 아니다. C 4종의 BTO 최대 구성 조건은 제품 사양의 `condition`과 함께 드러낸다.
- Alta·Midra 4종: `videoLayerPlan.models[slug]`에서 `maxPgm4kScreens`, `maxMixing4kPerScreenOneScreen`, `totalMixing4k`, `screenModes`를 읽는다. `Input/구성`과 `Output` 사양 원문을 출처로 사용해 미러링 단자를 독립 출력으로 합산하지 않는다. Midra의 1화면 Mixer/2화면 Matrix 및 Eikos Blend는 한 숫자로 합치지 않고 모드 조건을 표시한다. **서로 다른 시리즈의 “화면당” 의미를 동일 최대치로 오인하지 않도록** 열 머리와 주석을 구분한다.
- 모든 15종의 RU·전원은 제품 `specifications`에서 그룹과 이름(`Physical/크기(RU)` 또는 `Physical/랙 유닛`, `Power/전원` 또는 `Power/전원 입력`)으로 정확히 한 행씩 찾는다. 없는 값이나 이름이 둘 이상인 경우 추측해 채우지 않고 시험을 실패시킨다. 현재 실측은 **15/15 자기 플랜 행, 15/15 RU, 15/15 전원**이다.
- W-019 `analogway-layer-guide-data.mjs`의 `modelData`에는 모델별 수치가 별도로 있으나, 종합 페이지의 표 값 출처로 쓰지 않는다. 비교표 값의 권위는 제품 JSON이다. 가이드가 계산을 위해 가진 데이터와 차이가 생기면 숨기지 않고 별도 불일치로 보고한다.
- 시안 PR의 불일치 0 시험: (a) 카탈로그의 Analog Way 16 slug와 카드 배치 16 slug가 일치하고 중복이 없는지, (b) 비교표 15행의 각 셀에 `slug·JSON 경로·필드 경로`를 연결해 원본 JSON으로 독립 재계산한 문자열과 실제 렌더 셀 텍스트를 전수 비교하는지, (c) 모델 링크와 문서 링크가 실제 허용 경로로 열리는지 검사한다. 값 하나를 메모리에서 바꿔 놓은 부정 시험에서는 해당 행이 불일치로 실패해야 한다. JSON 전체를 과거 fixture로 바꾸는 shim은 쓰지 않는다. W-003 병합 후 새 모델이 들어오면 명시적 멤버 목록에 없는 slug를 실패로 잡아 분류를 재검토한다.

## 기존 화면과 맞추는 방식

- `beta/site/index.html`·`app.js`: 홈의 제조사 칩과 `#series-browser`가 제품군 선택을 담당한다. Shure·Samsung은 `brand-series.mjs`의 명시 그룹, RTCOM은 동기화된 `rtcom/raw/index.json.groups`와 제품별 group으로 그룹·순서를 만든다. 현재 독립 제조사 랜딩은 없으므로 새 페이지도 `pg.css`의 상단 바·카드·표·버튼 스타일과 기존 상세 URL 규약을 따른다. 시안 단계에서는 홈 제조사 칩·메뉴를 변경하지 않는다.
- RTCOM 상세의 `rtcom-embed.mjs`는 별도 구성기 원본 화면을 iframe으로 보여 주고 포털 카드와 중복을 접는다. Analog Way는 같은 저장소의 제품 JSON과 W-019/W-003 카드를 조합하므로 iframe이 아니라 데이터 구동형 자체 페이지가 적합하다. RTCOM 원본·어댑터·기존 제조사 탐색을 바꾸지 않는다.
- 1단계 후보 위치는 `beta/site/analogway/`의 메뉴 미연결 시안이다. **PR은 W-003 1부 병합 후** 만들고, Work가 캡처를 사용자에게 보여 승인받기 전에는 병합·공개 배포하지 않는다. 승인 뒤 2단계에서만 카탈로그/제조사 진입 링크를 연결한다.
