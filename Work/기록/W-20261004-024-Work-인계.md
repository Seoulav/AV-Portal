# W-20261004-024 Work 인계

## 완료한 범위

삼성 MPF `mp008f`·`mp012f`·`mp016f`에 삼성전자 미국의 각 SKU 페이지 갤러리에서 받은 정면 사진을 `Main`으로 등록했다. 각 목록 카드와 상세 02에 사진이 보이고 확대 보기가 열린다. 원본 URL·SHA-256·모델 대응·픽셀 피치 대조는 [사진 근거표](W-20261004-024-MPF-사진-근거표.md)에 기록했다. 미국 페이지는 **사진 식별 근거로만** 사용했다. 기존 국내 사양·단자·`keyFacts`·Port Map은 변경하지 않았다.

공식 개별 페이지는 모델명과 판매 코드를 `MP008F / LH008MPFAAA/GO`, `MP012F / LH012MPFAAA/GO`, `MP016F / LH016MPFAAA/GO`로 직접 병기한다. 선택 SKU의 픽셀 피치 0.84·1.26·1.68 mm도 기존 국내 값과 맞는다. 국내 가이드 17쪽과 제품 JSON에는 캐비닛 크기·캐비닛 해상도가 없어 두 항목은 **미대조**다. 포장 박스 크기를 캐비닛 크기로 대체하지 않았다. 이는 사용자와 임시 기획·리뷰 담당자가 2026-10-05 승인한 대체 식별 기준이며 지역별 사양 전체의 일치를 뜻하지 않는다.

`mp012f`와 `mp016f`의 모델별 갤러리는 **바이트가 같은 정면 사진**을 제공한다. 제품별 파일은 Pages 이미지 참조 1:1 검사 때문에 각각 두되, `alt`·`note`·`sources`·화면에 제품군 공통 이미지임을 밝히고 전용 실물 사진으로 단정하지 않았다. 세 사진을 인위적으로 다르게 가공하지 않았다.

## 검증

- 전용 검사: 사진 등록 전 RED 1 fail, 등록 후 GREEN. 실제 WebP 3장의 1920×1280 크기와 012·016 동일 해시를 검사한다.
- 전체 검사: `node --test --test-concurrency=1 tests/*.test.mjs` 340 tests / 339 pass / 0 fail / 1 기존 skip. 기본 병렬 `npm.cmd test`에서는 기존 Windows `rtcom-sync` 임시 폴더 `rename EPERM` 1건이 재현됐다. `node beta/verify-pages.mjs` **257 장비·250 상세·394 WebP·107 PDF**. 검색 인덱스 `--check` 및 읽기용 카탈로그 생성 통과.
- 기존 상세 247종, 카탈로그의 다른 항목 254건은 불변이다. W-030에서 사진이 없던 `ie015a-e`·`ie020a-e`·`if015r-m`도 그대로다.
- 1280px·390px에서 목록과 세 상세의 전후 화면을 [캡처 폴더](W-20261004-024-screens/)에 기록했다. 로컬 상세의 확대 보기를 6회 열어 원본 크기 1920×1280 및 JS 오류 0건을 확인했다.
- 독립 리뷰: Critical·Important 0건. 리뷰가 지적한 상세 수량 표기를 247종으로 바로잡고 임시 검사 폴더를 커밋에서 제외했다.

## 기준 보정과 남은 일

명세의 242종/무사진 3종/완료 후 무사진 0종은 W-030 전 수치다. 착수 때 **257·250·391·107**, 무사진 6종이었고 이번에 MPF 3종만 채워 무사진은 W-030 LED 3종으로 남는다. 명세의 ‘사진 3장이 서로 달라야 한다’는 조건도 삼성 공식 갤러리 원본 012·016이 동일하므로 사실에 맞게 적용하지 않았다. 사용자 위임에 따른 임시 기획·리뷰 담당자가 2026-10-05 제품군 공통 이미지임을 밝히는 적용 방식을 판단했다. 이를 사용자의 별도 기술사실 확정으로 기록하지 않는다.

캐비닛 크기·해상도는 국내 원본에 없어 비교하지 못했고, 미국 기술 사양은 국내 데이터로 옮기지 않았다. W-030 신규 LED 3종 사진은 정확한 모델 자료를 별도로 확보해야 한다. 다음 대기열은 **W-032 → W-033 → W-025 → W-026 → W-028 → W-20261005-002**이며 RTCOM은 마지막이다.
