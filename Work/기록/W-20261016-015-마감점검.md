## 3. 측정 방법과 한계

1. 공개 복사본 `beta/site/detail/detail-enhancement-view.mjs`의 실제 `portMapGeometry`·`renderPortMap`을 사용했다. 사진 원본 치수와 measuredImage 치수 일치를 검사했다. 일반 제품 지도 검증 오류·미러 불일치 0.
2. crop 뒤 보이는 사진 사각형으로 SVG 선분을 잘라 사진 안 부분만 측정했다. **같은 방향의 한 직선 중간에 via 점이 있어도 연속 구간으로 합쳤다.** 점을 하나 더 넣어 긴 선이 짧은 두 선으로 오집계되지 않게 했다.
3. 수평 지시선 연속 길이가 사진 폭의 25%를 넘으면 검출했다. 사진의 흰 바탕도 이미지 영역에 포함하되, 승인된 패널 띠 예외는 별도로 대조했다.
4. 평행하고 투영 구간이 겹치는 서로 다른 번호의 **지시선 ↔ 지시선/괄호**만 검사했다. 괄호끼리는 제외하므로 가장자리 8px 끝다리끼리도 제외된다. **지시선 ↔ 끝다리**는 사용자 6px 범위에 해당하므로 포함했다. 중심선 거리에서 양쪽 선 반두께(합계 1.5px)를 뺀 빈 간격을 썼다. 기존 [segment 검사](../../tests/portmap-segment-audit.mjs)와 같은 정의다. 음수는 선 두께가 서로 겹친다는 뜻이다.
5. 위 수치는 원본 이미지 픽셀이 아니라 **SVG 좌표 px**다. 760px 캡처에서는 SVG 전체를 폭 760으로 표시하므로 좌우 lane이 늘어난 지도는 함께 축소된다. 수치는 SVG 기준으로 고정해 비교했고, 6px 경계 미달을 원본 좌표의 6px로 오판하지 않았다. 390px 문서 넘침은 별도로 실제 CSS 크기로 쟀다.
6. 390px 검사는 해당 main의 공개 페이지 코드를 로컬 서버로 열고 지도 이미지 썸네일마다 전환해 검사했다. 선택 이미지·원 개수·양쪽 스크롤의 문서 폭을 모두 대조했다. 이번 결과를 CDN의 모든 페이지를 접속해 검사한 것으로 표현하지 않는다.
7. 이 자동 측정은 사진 내용의 단자·인쇄 글자를 인식하지 않는다. 따라서 전체 185지도의 관통/오인 0을 새로 보증하는 검사는 아니다. 검출된 17지도는 760px 캡처를 직접 확인했다. 실제로 Work가 공개 Zenith 100의 #9 PGM 출력 3·4가 입력 카드를 가리키는 오류를 발견했으며, 이 의미상 오인은 자동 측정에서 검출되지 않아 세션 B가 별도로 수정 중이다(2026-10-17).
