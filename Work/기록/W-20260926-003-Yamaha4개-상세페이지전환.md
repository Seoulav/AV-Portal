# W-20260926-003 — Yamaha 4개 제품 상세페이지 신규 조사·전환 기록

작성: 2026-09-26, Claude Code 세션(Work/Codex 역할 동일 세션 대행)

## 배경

W-20260926-002(소형 브랜드 6곳 13개 제품 상세페이지 전환)에 이어, 사용자가 "다음 배치도 작은 브랜드부터 해줘"라고 지시했다. 남은 브랜드 중 제품 수가 가장 적은 곳은 Sony(4개)와 Yamaha(4개)로 동률이었다.

Sony의 공식 페이지는 `pro.sony` 도메인인데, 이 프로젝트 전체 기간 동안 반복적으로 403이 확인된 이력이 있다. 이번에도 `curl`로 `https://pro.sony/ko_KR/products/ptz-network-cameras/srg-x40uh`를 직접 요청해 403을 재확인했고, 대안으로 WebFetch 도구를 통한 우회도 시도했으나 동일하게 403 Forbidden이 반환되었다. 반면 Yamaha의 `kr.yamaha.com`은 curl로 200을 확인해 접근 가능했다. 따라서 이번 배치는 Yamaha 4개 제품(Tio1608-D2, DM3, Rio1608-D3, Rio3224-D3)으로 진행하고, Sony는 보류로 남겼다.

## 조사 방법

### Yamaha 공식 웹사이트 구조 파악
공식 제품 페이지(`kr.yamaha.com/.../<제품>/`)는 최초 페이지 로드 시 "개요" 탭만 정적 HTML에 포함되고, "사양" 탭 내용은 별도 URL(`.../<제품>/specs.html`)에 있다는 점을 발견했다. curl에 일반 브라우저 User-Agent 헤더를 추가하니(별도 우회 기법 아님, 표준 브라우저 헤더) 별 문제 없이 200이 반환되어 이 방식으로 개요·사양 페이지를 모두 확보했다.

### Tio1608-D2
개요 페이지에서 제품 설명·특징(Dante 스테이지 박스, D-PRE 프리앰프, QUICK CONFIG/AUTO CONFIG 자동 구성 등)을 확인했고, `specs.html`에서 General/Analog Input/Analog Output/Digital I/O 전체 사양표를 확인했다. 카탈로그에 이미 연결된 공식 Owner's Manual PDF(`data.yamaha.com`)에서도 122페이지의 Specifications 섹션이 웹 사양 탭과 정확히 일치함을 교차 확인했다.

### DM3
`specs.html`이 "DM3"(Dante 지원)와 "DM3 Standard"(Dante 미지원) 두 변형을 나란히 표로 제공한다는 점을 확인했다. 카탈로그 항목명이 "DM3"이고, 제조사 웹페이지에서 확보한 대표 이미지 파일명도 `DM3-front_...`(Standard가 아님)이므로, Dante 지원 모델(DM3)의 사양값을 채택했다. 이 판단 근거를 이슈로 남겼다.

### Rio1608-D3 / Rio3224-D3
카탈로그에 이미 연결된 manual_link가 두 제품 모두 동일한 PDF(`Rio3224-D3_owners_manual_Ko_A1.pdf`)를 가리키고 있어, 이것이 데이터 오류인지 확인이 필요했다. PDF를 직접 다운로드해 `pdftotext`로 확인한 결과, 표지 페이지에 정확히 "Rio3224-D3 Rio1608-D3 사용 설명서"라고 두 모델명이 함께 표기되어 있었고, 본문 서두에도 "Rio3224-D3의 사양이 Rio1608-D3의 사양과 다른 경우 본 설명서에서는 Rio1608-D3에만 적용되는 사양을 중괄호 { } 안에 표시합니다"라는 명시적 안내문이 있었다. 즉 데이터 오류가 아니라 제조사가 의도적으로 채택한 두 모델 공용 매뉴얼 표기 방식임을 확인했다.

`specs.html`(`r-series-adda-3/specs.html`)에서 두 모델의 General/Analog/Digital 사양을 나란히 비교하는 표를 확인했고, PDF의 "사양" 섹션(14페이지)에서도 동일한 수치(치수·중량·전력·AES/EBU 출력 유무 등)를 교차 확인했다. AES/EBU 출력 8채널은 Rio3224-D3 전용 기능이며 Rio1608-D3에는 없다는 점도 PDF·웹 양쪽에서 일치했다.

### 사진 확보
4개 제품 공식 페이지의 정적 HTML에서 `<img src>` 태그를 직접 파싱해 모델별 전면·후면 사진 URL(`Tio1608-D2-front01_...jpg`, `DM3-front_...jpg`, `Rio1608-D3-front01_...jpg`, `Rio3224-D3-front01_...jpg` 등, 각 1200×1200)을 확보했다 — Blackmagic Design 때처럼 Playwright가 필요 없는 정적 렌더링 사이트였다. 전면·후면 이미지 모두 패널에 모델명이 직접 인쇄되어 있어(예: "Tio1608-D2", "DM3", "Rio1608-D3", "Rio3224-D3") 4개 전부 VERIFIED로 확인했다.

## 반영 방식

- 상세 JSON은 기존 스키마와 동일하게 직접 작성(Python 헬퍼 스크립트로 일괄 생성 후 `json.dump`).
- `beta/group1-images.mjs`: 4개 슬러그 추가(Front+Rear 각 1장, 기본 `image()` 헬퍼 사용).
- `beta/site/catalog.json`: 4개 항목에 slug·card_image 추가. manual_link는 기존 값을 그대로 유지(이미 정확한 공식 자료로 연결되어 있었음).
- `beta/manufacturer-hosts.mjs`: 변경 없음. `kr.yamaha.com`, `data.yamaha.com`, `manual.yamaha.com` 모두 기존 `Yamaha: ['yamaha.com']` 항목의 서브도메인 허용 규칙(`isAllowedHost`가 `.yamaha.com` 접미사 매치)으로 이미 통과.

## 발견 사항(이번 작업 범위 밖, 기록만)

- Sony `pro.sony`는 curl·WebFetch 양쪽 모두에서 여전히 403이 확인된다. 이 프로젝트 전체 기간 동안 일관되게 차단 상태이며, 이번 세션에서 시도한 다른 우회 방법(브라우저 User-Agent 헤더 추가)도 효과가 없었다. 향후 Sony 4개 제품(SRG-X40UH, SRG-A40, RM-IP10, RM-IP500) 작업 시 사용자 제공 자료가 필요할 것으로 보인다.
