## 실제 완료·검증

선택적 `AV_PORTAL_RESOURCE_REGISTER_PATH`를 사용해 기존 제품 목록과 별도로 로컬 수집대장을 읽는다. 제품 ID–자료 ID 관계를 검증한 뒤 `GET /api/products/:productId/resources`의 허용 필드만 상세에 전달한다. 자료를 제품/지원, 사양서/카탈로그, 매뉴얼, 제어, 기타로 묶고 같은 종류 안에서 명시적 한국어를 먼저 놓는다. 기존 공식·보조 출처와 원본 행은 유지하고 자료대장과 섞어 검증 상태를 바꾸지 않는다. 공유 자료를 각 제품에 연결하며 동일 제품–자료 관계는 한 번만 표시한다. 미설정, 연결 기록 없음, 수집대장 오류, 미등록 코드와 값 미확인을 구분한다. 제조사 직접 제공 자료는 로컬 보관과 파일 열기 미지원을 표시한다. 새 자료 API는 개인 경로와 `local_reference`를 전달하지 않고, 링크는 안전한 HTTPS만 허용한다.

Node.js v24.18.0에서 `npm test` 27/27, `npm run verify:local` 1/1, `npm run verify:resources:local` 통과. 실제 입력은 제품 338개, 원본 행 342개, 등록 제품 338개, 자료 455건, 연결 557건. 자료 API 호출 전후 `/api/catalog`의 제품 전체와 직접 읽은 목록을 대조해 동일함을 확인했다(카테고리 소속 1,045건 포함). 작업 전후 SHA-256은 제품 JSON `E0028FF1684F282712591DE3C846BEF28635AEAF5C6890D2FBF270391097960D`, 자료 수집대장 `C1D3644FAA1E1C0E67627FC7353828DA989D38FC327069DECE6BAB5751245476`으로 동일하다. 실제 브라우저에서 BLU-101의 별도 자료대장 5건 및 기존 출처·원본 행, 미설정 화면의 “자료대장 미연결”, XDM-36의 직접 제공 파일명 후보·본문 미확인·웹 링크 없음 표시를 확인했다.
