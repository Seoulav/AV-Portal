# W-20261004-012 — 삼성 영업자료 암호화 근거

- 기준: `origin/main` `a295d00cdb8cf806b45cd7e7aba1bcdbc820f865`, 2026-10-04.
- 대상: 삼성 영업자료 PDF 3건만. 비밀번호는 작업 대화에서 별도 전달받았으며 이 기록과 저장소에는 적지 않는다.
- 방식: 원본 PDF를 pypdf 6.19.0으로 복제한 뒤 AES-256으로 암호화했다. 게시본의 `/Encrypt`는 `V=5`, `R=6`, `Length=256`이다. 파일만 교체했으며 문서 연결 목록은 그대로다.

| 게시 파일 | 전 크기 | 후 크기 | 쪽 | 전 SHA-256 | 후 SHA-256 |
|---|---:|---:|---:|---|---|
| `samsung-115qhf-spec-ko.pdf` | 322,761 | 350,860 | 2 | `4be5f424f5d7…` | `b1773b9b39cc…` |
| `samsung-lcd-signage-product-guide-ko.pdf` | 4,645,291 | 5,849,449 | 47 | `2351a2b725d6…` | `0a0115178257…` |
| `samsung-videowall-product-guide-ko.pdf` | 2,387,519 | 2,618,281 | 18 | `3f5751cbcc8e…` | `da24b9fa9c1b…` |

세 파일 각각 올바른 비밀번호로 해제해 **전후 쪽 수, 각 쪽 크기, 추출 텍스트 SHA-256, 디코딩된 본문 스트림 SHA-256이 모두 같음**을 확인했다. 비밀번호 없이 본문을 읽으면 `FileNotDecryptedError`, 틀린 비밀번호는 거부됐다. PDF.js 전용 검사는 비밀번호 없이 열 때 세 파일 모두 `NEED_PASSWORD`가 나오고, 틀린 값 뒤에는 `INCORRECT_PASSWORD`로 다시 요청하는 것을 확인한다. 검사 코드에 실제 비밀번호는 없다.

공개 Git 저장소의 이전 커밋에는 암호화 전 PDF가 남아 있다. 따라서 **이번 암호화는 현재 게시본의 비밀번호 없는 열람을 막는 조치이며, 과거 Git 이력에서 원본을 회수하지 못하게 하는 보안 조치는 아니다.** 이력 재작성은 이번 범위에 없고 수행하지 않았다.

공개 뷰어의 기존 PDF.js 작업에 `onPassword`를 연결했다. 같은 팝업 안에 라벨이 있는 비밀번호 입력 폼을 보이고, 오입력 시 오류로 끝내지 않고 입력 폼을 다시 표시한다. 성공하면 입력값과 폼을 지우고 기존 페이지 렌더링을 이어간다. 닫거나 다른 파일을 열 때도 입력값을 지운다. 기존 `내려받기`는 암호화된 PDF 바이트를 그대로 내려준다. 암호 없는 PDF에서는 폼을 보이지 않는다. 사이트 의존성은 늘리지 않았다.

로컬 Chromium에서 [1280px 입력](W-20261004-012-screens/115qhf-prompt-1280.png), [오입력 재시도](W-20261004-012-screens/115qhf-retry-1280.png), [390px 입력](W-20261004-012-screens/115qhf-prompt-390.png), [390px 열림](W-20261004-012-screens/115qhf-open-390.png)을 확인했다. LCD 가이드와 비디오월 가이드도 각각 [입력·열림](W-20261004-012-screens/)을 캡처했다. 일반 [사용설명서](W-20261004-012-screens/plain-open-390.png)는 입력 없이 열렸다. 세 자료 모두 다운로드 바이트가 게시 암호본과 동일했다. 1280px·390px에서 가로 넘침과 페이지 JS 오류는 0이었다.

기준 `verify-pages`: 장비 249·상세 242·WebP 375·업로드 103. 암호화 후에도 같은 수치다. 다른 PDF 53건의 정렬된 파일명·바이트 SHA-256 합성 해시 `7d9e6ac1869ed1d4661a7e8232617894572f9953f60659888b98457cbca652a2`, 제품 JSON 242건의 LF 정규화 합성 해시 `3d331d708f8d1603975f9ba85fcd3944de8f3e82c9a0cfe2a392a082d0169701`, `manifest.json` 해시 `4c64584eb766ad94f2c5fac66f02d687bb81e4b2fce60d71a6149155cac1ddbb`가 기준과 일치한다. 과거 업로드 검사의 원본 SHA는 기록으로 유지하고 현재 게시 암호본의 SHA를 별도 대조한다.

전용 검사는 작성 직후 **RED: 2건 중 1 fail**, 암호화 후 재시도 검사까지 추가해 **GREEN: 3 pass / 0 fail**이었다. 전체 `npm test`: **304 tests / 303 pass / 0 fail / 기존 skip 1**. `node beta/verify-pages.mjs`, `node beta/build-search-index.mjs --check`, `node beta/build-readable-catalog.mjs` 통과.
