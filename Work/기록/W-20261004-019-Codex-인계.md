**그 그림은 단자 경로도였으니 맞습니다.** 사용자가 **처리 흐름도로 바꾸라**고 정했습니다.

## ★ AEC는 BLU-101 하나뿐입니다

BSS 5종 사양을 전부 읽었습니다. **데이터가 경계를 이미 그어 놨습니다.**

| 제품 | AEC 사양 | 블록 |
|---|---|:--:|
| **`blu-101`** | **`AEC 처리 채널 = 12 채널(독립 알고리즘)`** (`specifications[3]`, FOUND) | **넣음** |
| `blu-100` | **`AEC 지원 = 없음`** (`specifications[3]`, FOUND) | **안 넣음** |
| `blu-50v2` | **`AEC 입력 = 0`** | **안 넣음** |
| `blu-160` | `AEC 입력(최대) = 최대 16` — 카드 구성 의존 | **안 넣음** |
| `blu-dan` | 사양 없음 | **안 넣음** |

**`blu-100`과 `blu-101`은 뒷면이 같고 `io`도 같습니다.** 가르는 게 이 AEC입니다. 비슷하다고 같이 고치면 **없는 기능을 그리게** 됩니다.

`blu-160`은 **최대치이지 구성값이 아닙니다.** 지금 「카드 구성별 DSP」가 맞습니다.

근거는 `{ kind: 'spec', index: 3 }`이면 됩니다. `validEvidence`가 `VERIFIED`·`FOUND`만 보는데 **FOUND**입니다. 새 사실이 아닙니다.

## ★★ 지금 넣으면 03이 사라집니다

`detail-enhancements.mjs`

```js
// A crosspoint layout owns the central lane. Mixed/multiple matrices need a
// future layout contract; reject them rather than hiding overlapping blocks.
if (flow.processes.some(p => p.kind === 'matrix') && flow.processes.length !== 1) return false;
```

그리고

```js
if (!c.inputs.every(id => flow.connections.some(e => e.from === id && e.to === p.id))) return false;
if (flow.connections.some(e => e.to === p.id && !c.inputs.includes(e.from) || …)) return false;
```

**교차점 입력 12개가 매트릭스에 직접 이어져야** 합니다. `IN → AEC → 매트릭스`로 바꾸면 세 줄 다 걸립니다.

### 주석이 말하는 "future layout contract"를 이번에 씁니다

작성자가 **"겹치는 블록을 숨기느니 거절한다"**고 적어 놨습니다. **레이아웃이 없어서** 막은 겁니다.

**여는 범위를 좁히세요.**

| | |
|---|---|
| 엽니다 | 매트릭스 **앞단** 블록 |
| **계속 막습니다** | 매트릭스 **2개 이상** |
| **계속 막습니다** | 블록이 **겹쳐 그려지는** 경우 |

교차점 조건은 **"직접 이어짐"을 "앞단을 지나 닿음"으로** 바꿉니다. 푸는 게 아니라 **경로를 따라가 확인**하는 겁니다. 길이 없으면 **여전히 거절**, 교차점에 없는 입력에서 들어오면 **여전히 거절**입니다.

## 그림 자리

지금 가로 배치입니다.

```
x  12…152      198…418                 604…784      (W = 800)
   입력 12       매트릭스 12×8              출력 8
```

처리 블록은 **세로로 쌓이고**(`processY += h + 36`) 블록끼리는 **세로 화살표**입니다. `dci-4-600da`가 3단을 그렇게 그립니다.

**AEC를 그렇게 쌓으면 안 됩니다.** 매트릭스 가로줄이 **입력 칸 높이에 맞춰** 그려지는데(`ys = c.inputs.map(…)`) 정렬이 깨지고 **"입력 → AEC → 매트릭스"로 안 읽힙니다.**

### 입력과 매트릭스 사이 세로 띠로

```
   입력 12 ──┤ AEC ├── 매트릭스 12×8 ───── 출력 8
              12채널
```

- 12개 가로줄이 **AEC를 지나** 매트릭스로
- 입력 12행 **전체 높이**를 덮는 세로로 긴 둥근 사각형
- 폭이 좁으니 **글자 넣는 방법은 당신이 정하세요**

지금 입력 끝(152)과 매트릭스(198) 사이가 **46px뿐**이라 안 들어갑니다. **`W`를 넓히거나 매트릭스를 미세요.** **기존 8종이 안 변하는 쪽**으로요.

**알티컴에는 이 경우가 없습니다.** `ioFlowDiagram`은 매트릭스 앞단 블록을 안 그립니다. **선·색·글자 규격만 쓰고 배치는 새로** 만드세요.
