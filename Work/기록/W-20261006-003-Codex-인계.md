## 제가 5종을 전수 확인했습니다 — 다시 찾지 마세요

**등급은 전부 이미 `specifications`에 있습니다.** 새로 받을 자료가 없습니다.

| 제품 | 등급 |
|---|---|
| **BRC-AM7** | **PoE++** `IEEE 802.3bt Type 4 Class 8` |
| **SRG-A40** | **PoE++** `IEEE 802.3bt Type 4 Class 8` |
| **SRG-X40UH** | **PoE+** `IEEE802.3at` |
| RM-IP10 · RM-IP500 | **PoE 제품이 아닙니다. 건드리지 마세요** |

## 문제는 「없다」가 아니라 「안 보인다」입니다

단자 표에서 **셋이 똑같아 보입니다.**

```json
"signal": "Network/PoE"     ← 3종 전부 같음
```

**세 제품의 전원 요구가 완전히 다른데 구분이 안 됩니다.** PoE+ 스위치에 PoE++ 카메라를 물리면 켜지지 않습니다. **현장에서 바로 문제가 되는 정보입니다.**

## ★ 새 표기법을 만들지 마세요 — 선례가 있습니다

NETGEAR 번호 지도가 **등급을 라벨에 직접 박아** 뒀습니다.

```js
// tests/netgear-port-maps.test.mjs:23
gs108pp: ['RJ-45 1–4 · PoE+', …]
```

**같은 방식을 Sony에 적용합니다.**

## 할 일

`signal`을 **`Network/PoE++`·`Network/PoE++`·`Network/PoE+`**로 갈라 적고, `condition`에 **규격 번호를 덧붙입니다.** 기존 `condition` 문구는 **지우지 마세요.**

`srg-x40uh`의 **「LAN 속도 미명시」는 그대로** 둡니다. 아직 모르는 게 맞습니다. **PoE 등급과 LAN 속도는 다른 값입니다.**

**새 출처를 만들지 마세요.** 사양의 PoE 행이 쓰는 코드를 그대로 씁니다.

## 번호 지도

`srg-x40uh`만 `portMap`이 있고, 5번 항목이 **이미 `PoE+`를 적고 있습니다. 맞으니 고치지 마세요.** `brc-am7`·`srg-a40`은 `portMap`이 없고 **이번에 만들지 않습니다.**

## ★ `keyFacts`를 만들지 마세요

Sony 5종은 지금 **전부 0개**입니다. 렌더러는 **2개 미만이면 카드를 숨깁니다**(`detail-enhancements.mjs:116`). **PoE 하나만 넣으면 보이지도 않고**, 둘을 채우려면 다른 사실을 지어내야 합니다.

## 사양 행 이름은 그대로

행 이름이 제품마다 다릅니다(`PoE++` vs `PoE`). **보기엔 어긋나지만 값은 셋 다 정확합니다.** 통일은 **대기열 3번(말투 조정)에서** 다룹니다. **그 사실만 보고**해 주세요.
