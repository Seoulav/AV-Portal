## ★ 독립 검토를 받고 고친 곳이 세 군데입니다

초판에서 제가 틀린 것들입니다. **고친 뒤 판을 읽어 주세요.**

### 1 · 「합쳐도 순서가 같다」 — 틀렸습니다

초판에 **"묶음 제목줄이 없으니 115를 QHC로 옮겨도 순서가 같다"**고 적었습니다. **사실이 아닙니다.**

실제로 돌려 봤습니다.

```
지금 값              115 → 43QHC → 75QHC → …
115를 QHC로 옮기면    43QHC → 75QHC → 115 → …
```

묶음 안에서 `size` 오름차순이라(`app.js:44`) **115가 맨 뒤로 갑니다.**

> **결론은 그대로지만 이유가 바뀝니다.** `brandSort`를 안 건드리는 것은 **편해서가 아니라, 건드리면 승인된 "115 먼저"가 깨지기 때문**입니다.

### 2 · 「8묶음 번호가 전부 밀린다」 — 실행 코드 이야기로는 틀렸습니다

`filterCatalog`는 `order`를 **크기 비교에만** 씁니다(`app.js:40`). 띄엄띄엄이어도 돕니다.

**번호 연속을 요구하는 것은 `tests/catalog-order.test.mjs:30`입니다.** 구분해서 적었습니다.

### 3 · ★★ 어떤 화면인지 — **단계형으로 정했습니다**

가장 중요합니다. 초판은 **전체 목록 위에 칩을 얹는 필터**였습니다. 사용자가 말한 것은 **단계형 진입**입니다.

| 상태 | 보이는 것 |
|---|---|
| 삼성 + `series` 비었음 | **시리즈 칸만.** 카드 안 보임 |
| 삼성 + `series=all` | 전체 카드 |
| 삼성 + `series=qmc` | QMC 카드 |

**`filterCatalog`는 안 바뀝니다.** 카드를 숨기는 것은 **화면 쪽 판단**입니다. 거르는 일과 보여주는 일을 나눴습니다.

> `?brand=Samsung&sort=brand`의 **첫 화면이 카드 대신 시리즈 칸**이 됩니다. **호환 깨짐이 아니라 사용자가 요청한 변화**입니다. **캡처로 꼭 보여 주세요.** 뜻과 다르면 그때 고칩니다.

## ★ 「유지할 때」와 「풀 때」를 나눴습니다

초판에는 전부 **푸는 쪽**으로만 적었습니다. 그러면 **고른 시리즈가 자꾸 날아갑니다.**

| | |
|---|---|
| **유지** | 결과 안 검색 · 왼쪽 세부 분류 · 자료 · 정렬 |
| **푼다** | 제조사 칩 · 제조사 셀렉트 · 상단 검색 · 상위 분류 · 검색 제안 · 초기화 3종 |

그리고 **이력·스크롤 정책**이 초판에 아예 없었습니다. 시리즈 칸은 **`render(true)`로 이력에 쌓고**, 누르기 전에 **`saveScroll()`**, **같은 칸을 다시 누르면 쌓지 않습니다.**

## ★ 3판에서 고친 것 둘 — 둘 다 제 잘못입니다

### 1 · `all`이 정규화에 걸려 풀리는 모순

2판에서 `all`을 **예약어**로 정해 놓고, 버리는 규칙에는 **"묶음표에 없는 값은 버린다"**고 적었습니다. **그대로 만들면 `전체 보기`를 누르는 순간 풀립니다.**

**허용값을 먼저 적는 방식으로 바꿨습니다.**

| 최종 `brand` | 허용 |
|---|---|
| 묶음표 **있는** 제조사 | 빈 값 · **`all`** · 그 묶음표의 id |
| 묶음표 **없는** 제조사 · `brand` 없음 | 빈 값만. **`all`도 버립니다** |

`setFacets`가 `brand`를 지운 뒤(`app.js:136`) **고아 `series`도 함께 없어져야 합니다.**

### 2 · bfcache 설명이 사실과 달랐습니다

2판에 **"새로 읽기와 캐시 복원은 첫 로딩 경로로 들어온다"**고 적었습니다. **틀렸습니다.** bfcache는 **문서와 JS 상태를 되살려서 최초 로딩용 초기화가 다시 돌지 않습니다.** 「아무 일도 안 일어난다」는 뜻은 아닙니다 — 아래에서 관측하라는 `pageshow`가 바로 그 증거입니다.

**셋으로 나눴습니다.**

| 길 | 무엇이 도는가 |
|---|---|
| 같은 문서 뒤로가기 | `popstate` |
| 문서를 새로 읽음 | 최초 초기화 |
| **bfcache 복원** | **최초 로딩용 초기화만 안 돕니다.** 문서·JS 상태가 복원되고 **`pageshow` 같은 복원 이벤트는 일어납니다** |

확인은 `pageshow`의 **`event.persisted === true`를 실제로 관측**해서 합니다. 근거: <https://web.dev/articles/bfcache#observe_when_a_page_is_restored_from_bfcache>

> **리스너를 새로 만들라는 말이 아닙니다.** 지금 동작으로 선택·주소·카드·스크롤이 맞으면 **그대로 두세요.** 어긋날 때만 손대면 됩니다.
>
> **재현이 안 되면 「최초 로딩으로 확인했다」로 대신 통과시키지 마시고, 재현 못 했다고 적어 주세요.**
