## 좌·우 검증기와 화면

`validMarker`는 `top/bottom`의 `x1,x2[,y]`와 `left/right`의 `y1,y2[,x]`를 별도로 검증하고 필드 혼용·사진 범위 밖을 거부한다. `validMap`의 이미지 역할 목록은 `Front/Rear` 그대로다. 기존 가로 마커 51종은 동일한 유효 지도를 유지한다. 번호는 왼쪽 여백에 있어 사진을 가리지 않는다.

2026-10-04 사용자 추가 지시 **“115인치를 샘플 볼때 단자쪽 실사진볼때 원형돋보기 기능도 넣어줘”**, **“돋보기 기능은 제품은 단자쪽 보기위함이야”**에 따라, 기존 확대창의 **동일한 `.image-loupe`와 확대 계산**을 02 카드 안에서도 재사용했다. 새 스타일은 없다. 렌즈는 원본 사진만 확대하고 실제 사진의 보이는 경계 안에 가둬 사진 밖 번호 레일을 가리지 않으며, 포인터 이벤트를 받지 않아 번호·사진 조작을 끊지 않는다. Port Map이 없거나 다른 사진을 선택하면 숨긴다. 터치에서는 숨긴 채 기존 `확대 보기` 버튼과 팝업 돋보기를 유지한다. `.zoom-button {display:none !important}`는 **인쇄용 `@media print` 안**에만 있다.

[1280px 기본](W-20261004-010-screens/lh115qhfebgxkr-1280-gallery.png) · [390px 기본](W-20261004-010-screens/lh115qhfebgxkr-390-gallery.png) · [1280px 카드 돋보기](W-20261004-010-screens/lh115qhfebgxkr-1280-loupe.png) · [390px 카드 돋보기](W-20261004-010-screens/lh115qhfebgxkr-390-loupe.png) · [기존 팝업 확대](W-20261004-010-screens/lh115qhfebgxkr-1280-zoom.png). 카드 렌즈 180px은 팝업과 같지만 배율은 **1.2배**, 팝업은 기존 **3배**다. 카드 사진의 실효 표시 밀도가 원본보다 이미 높아 3배에서는 각인이 더 흐려졌다. 390px에서 1.2·1.5·2·3배를 비교했고 1.2배에서 [USB 2 (1.0A)](W-20261004-010-screens/lh115qhfebgxkr-390-loupe-usb2.png)·[HDMI 3 (ARC)](W-20261004-010-screens/lh115qhfebgxkr-390-loupe-hdmi3.png)·[RS232C](W-20261004-010-screens/lh115qhfebgxkr-390-loupe-rs232c.png) 각인을 읽을 수 있었다. 1280px도 [USB 2 표본](W-20261004-010-screens/lh115qhfebgxkr-1280-loupe-usb2.png)으로 확인했다.

**돋보기 없는 390px 판정:** 11개 번호와 단자 설명은 읽히지만, 작고 어두운 제품 각인은 독립 판독이 어렵다. **이 사진을 세로 패널로 길게 제시하는 방식은 390px에서 각인을 직접 읽는 용도에 맞지 않는다.** 돋보기를 쓰면 위 세 각인은 읽히지만, 이는 별도 보조 기능의 결과다. 따라서 38종 일괄 확대의 근거가 아니며 모델별로 실제 단자 노출·해상도·돋보기 없는 390px 가독성을 다시 판정해야 한다.

로컬 Chrome 1280px·390px에서 SVG 번호 11개, 설명 11개, 02 꼬리표 `— 실제 제품 사진 기준`, 03 숨김, 문서 가로 넘침 0, 이미지 오류 0, JS 예외 0을 확인했다. 390px의 **지도 내부 가로 스크롤 262px**는 기존 최소 지도 폭에 따른 것이며 페이지 가로 넘침은 아니다. 번호·사진·목록은 첫 위치에서 보이고 `↔` 안내가 있다. 팝업 확대와 마우스 돋보기는 두 폭에서 유지되고, 터치 탭으로 카드 돋보기가 열리거나 오류가 나지 않는다.
