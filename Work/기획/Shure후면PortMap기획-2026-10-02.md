## 1. 목적과 사용자 경험

### 해결하려는 문제

Product Detail의 `02` 카드는 기본적으로 제품 사진만 보여 준다. 사용자가 "이 수신기 뒤에 XLR이 몇 개이고 Dante 포트가 어디냐"를 확인하려면 사진을 확대해 눈으로 세고, 별도의 `03 연결 단자` 표와 머릿속에서 대조해야 한다. 사진과 표가 분리돼 있어 **어느 표의 행이 사진의 어느 구멍인지** 알 수 없다.

후면 Port Map은 이 간극을 메운다. 게시된 후면 사진 위에 번호를 찍고, 번호마다 "무엇에 연결하는 단자이며 핵심 조건은 무엇인가"를 한 줄로 붙인다. 시범 단계에서 ULXD4D·NovaStar H5·Crown DCi 4\|600DA·Epson EB-PQ2220B에 적용했고, 2단계 1차로 Crown 22종을 확대해 공개 검증까지 마쳤다. 이 기획은 **2단계 2차 대상으로 Shure를 다룬다.**

### 사용자가 얻는 것

| 사용 맥락 | 현재 | Port Map 적용 후 |
|---|---|---|
| 견적·설계 중 단자 확인 | 사진 확대 후 육안 계수 | 번호별 명칭·조건을 바로 읽음 |
| 현장 결선 | 표의 "XLR 2"가 어느 쪽인지 모름 | 사진 위 위치로 바로 식별 |
| 유사 모델 비교 | ULXD4 / ULXD4D / ULXD4Q 차이를 사양서로 추적 | 후면 구성 차이를 그림으로 비교 |
| 모바일 현장 조회 | 확대·스크롤 반복 | 번호 목록과 그림 내부 가로 이동 |

### 화면 동작 원칙

- 유효한 Rear 지도가 있으면 `02`가 **Port Map**으로 바뀌고, 정면으로 전환하면 제목이 **제품 사진**으로 돌아온다.
- 유효한 지도가 있는 제품은 `03`에서 같은 후면 사진을 반복하지 않는다. 단자 카드와 전체 단자 표는 그대로 둔다.
- 지도가 없거나 검증에 실패하면 기존 사진·단자 카드로 **조용히 되돌아간다**. 기능이 줄지 않는 것이 기본값이다.
- 확대·Esc·모바일 Home/End 사진 이동, `#io`·`#specifications`·`#documents`·`#sources`·`#gallery` 해시 진입은 유지한다.

### 명시적 비목표

제품 사양을 새로 만들지 않는다. Port Map은 **이미 저장소에 있는 사진과 PDF 근거를 읽기 쉽게 다시 배치**하는 작업이며, 새 기술값·호환성·수량을 생산하지 않는다.

## 2. 대상 9종 — 선정 이유와 자료 상태

### 선정 이유

[자료현황](../기록/W-20261001-001-Port-Map-자료현황.md)은 Rear 사진 보유 102종을 **가능 47 / 해상도 부족 17 / 근거 PDF 없음 38**으로 분류했다. 제조사별 '가능' 후보는 Crown 22, **Shure 9**, Yamaha 4, NETGEAR 2, Lumantek 2, NovaStar 2, Ross Video 2, 나머지 1종씩이다.

Crown 22종을 1차로 끝냈으므로 **남은 최대 묶음이 Shure 9종**이다. 한 제조사를 한 PR로 묶으면 공통 PDF·공통 단자 명명·공통 설명 문구를 한 번에 맞출 수 있고, 되돌리기 단위도 제조사 단위로 깔끔해진다. 또한 Shure는 ULXD4 / ULXD4D / ULXD4Q, SLXD4+ / SLXD4D+처럼 **채널 수만 다른 형제 모델**이 많아, 후면 구성 차이를 그림으로 보여 주는 가치가 특히 크다.

ULXD4D는 이미 Port Map을 가지고 있다. 새로 만들지 않고 **형제 모델과의 일관성 기준**으로 삼아 재검증한다. 따라서 이번 범위는 **신규 8종 + 재검증 1종**이다.

### 사본 보유 ≠ 검증 완료

**이 표의 "PDF 사본 후보"는 아직 근거가 아니다.** 자료현황이 파일명·제품 연결로 이어 둔 후보일 뿐이며, 해당 PDF 본문이 그 모델을 다루는지는 확인되지 않았다. 특히 6종은 **대상과 다른 모델명의 파일**을 가리킨다.

- `qlxd1-…` → QLXD4
- `slxd1-plus-…` → SLXD4+, SLXD4D+
- `ulxd1-…` → ULXD4, ULXD4Q
- `mxcw640-…` → MXCWAPT-W

이것이 곧 오류를 뜻하지는 않는다. 제품 JSON의 출처 URL을 보면 이 자료들은 모델 단품 안내가 아니라 **시스템 단위 공식 안내**(QLX-D, SLXD4plus, ULXD/ULXD-DQ, MXCW)로 등록돼 있어, 한 문서가 여러 모델을 포함하는 구조일 수 있다. Crown 1차에서도 파일명이 `cdi-2-1200`인 사양서가 본문에서 12개 모델을 명시함을 확인하고 사용한 선례가 있다.

따라서 **파일명으로 판단하지 않고 본문으로 판정한다.** 그 절차가 3장이다.

## 3. 모델별 PDF 본문 적용·단자 페이지 판정 절차

> **2026-10-02 정정.** 이 문서가 UA864A를 "안테나 분배기"로 적은 것은 오류다. 제조사 PDF 1쪽은 `Wall-Mounted Active Directional Antenna`(벽부형 액티브 지향성 안테나)이며 분배기가 아니다. W-20261002-001 구현 중 Codex가 발견해 [근거표](../기록/W-20261002-001-Shure-Port-Map-근거표.md)에 기록했고, 공개 데이터에는 잘못된 표현이 들어가지 않았다. 아래 본문의 해당 표현은 원문 기록으로 보존하되 이 정정이 우선한다.

데이터 작성 **전에** 9종 각각에 대해 아래 순서를 수행하고 결과를 근거표에 기록한다. 이 절차를 통과한 모델만 작성 대상으로 확정한다.

### G1. 적용 모델 확인

PDF를 열어 **표지·적용 모델 목록·모델 표기 영역**에서 대상 모델명이 실제로 있는지 확인한다.

- 확인한 쪽 번호를 기록한다. 쪽 번호는 뷰어 쪽이 아니라 **인쇄 쪽 번호 체계**를 따르고, 둘이 다르면 둘 다 적는다.
- 시스템 안내가 "ULXD4, ULXD4D, ULXD4Q"처럼 모델을 나열하면 그 나열 자체를 근거로 기록한다.
- 모델명이 없으면 **G1 실패**로 판정한다. 비슷한 계열이라는 이유로 통과시키지 않는다.

### G2. 후면 단자 페이지 확인

그 PDF 안에서 **대상 모델의 후면 패널 그림 또는 단자 표가 실제로 있는 쪽**을 찾는다.

- 형제 모델이 한 문서에 섞여 있으면, 그림의 캡션·채널 수·패널 폭으로 **어느 모델의 그림인지** 구분한다. 캡션이 없으면 통과시키지 않는다.
- 단채널(ULXD4, SLXD4+)과 복수채널(ULXD4D, ULXD4Q, SLXD4D+)은 후면 단자 수가 다르므로 **같은 쪽을 양쪽 근거로 쓰지 않는다.**
- 안테나(UA864A — 벽부형 액티브 지향성 안테나)와 회의 시스템(MXCW640, MXCWAPT-W)은 수신기와 단자 체계가 다르므로 별도로 찾는다.
- 찾지 못하면 **G2 실패**로 판정한다.

### G3. 사진-모델 일치 확인

제품의 `Rear` 이미지가 **정확히 그 모델의 후면 사진**인지 제품 페이지·매뉴얼 그림과 대조한다.

- 형제 모델, 지역 suffix, 변형(W/B 등)을 서로 대체하지 않는다. 이는 [후면 사진 백필 계획](후면사진백필계획-2026-09-27.md)의 판정 규칙 7과 같다.
- 사진의 단자 배열이 PDF 그림과 좌우·개수에서 어긋나면 **G3 실패**다.
- MXCWAPT-W는 9종 중 유일하게 `Front`·`Other`·`Rear` 세 역할을 가지므로 `Rear`가 실제 후면인지 먼저 확인한다.

### G4. 이미지 크기 일치 확인

Rear WebP의 **실제 디코딩 크기**를 측정해 2장의 표와 제품 JSON의 `resolution` 값에 모두 일치하는지 확인한다.

이 확인은 선택이 아니다. 렌더러의 `portMapImageMatches`는 `measuredImage`가 없으면 `originalSize`와 `resolution`이 **둘 다** 실제 크기와 같아야 지도를 표시한다. 9종의 `originalSize`는 모두 `3000x3000`으로 게시 크기와 다르므로, **9종 전부 `measuredImage`를 반드시 넣어야 한다.** 기존 ULXD4D도 `measuredImage`(2000×291)를 가지고 있다. 값이 어긋나면 지도는 조용히 숨겨지고 fallback된다.

### G5. 확정

G1~G4를 모두 통과한 모델만 작성 대상으로 확정한다. 확정 목록과 탈락 목록·사유를 근거표 머리말에 적는다.

**통과 수가 9종보다 적어도 통과분만 진행한다.** 수량을 맞추려고 근거를 느슨하게 적용하지 않는다. 탈락 모델은 사유와 함께 다음 자료 보완 작업의 입력으로 넘긴다.

## 4. 불확실·불일치 시 처리

| 상황 | 처리 |
|---|---|
| PDF에 모델명이 없다 (G1 실패) | 그 모델 제외. 사유 기록. 다른 PDF를 추측으로 대입하지 않는다 |
| 모델명은 있으나 후면 그림이 없다 (G2 실패) | 그 모델 제외. "적용 모델 확인됨 / 후면 쪽 없음"으로 구분해 기록한다 |
| 형제 모델 그림인지 구분이 안 된다 | 제외. 캡션 없는 그림을 채널 수 추정으로 배정하지 않는다 |
| 사진과 PDF 그림의 단자 수가 다르다 | 지도를 만들지 않고 **불일치 이슈로 기록**한다. 사진·PDF·I/O 중 어느 것도 이번 작업에서 수정하지 않는다 |
| 사진에 보이는데 PDF에 설명이 없다 | 번호를 붙이지 않는다. 제외한 단자와 사유를 근거표 하단에 적는다 |
| PDF에 있는데 사진에 안 보인다 | 번호를 붙이지 않는다. 모델 전용 단자일 수 있으므로 사유를 적는다 |
| 기존 `io[]` 행과 지도 내용이 어긋난다 | 지도를 맞추지 말고 **둘 다 보존**한 뒤 이슈로 남긴다. 기존 검증 상태를 바꾸지 않는다 |
| `io[]`의 quantity가 비어 있다 | 매뉴얼 쪽 근거가 있을 때만 채울 수 있다. 변경 전/후와 쪽 번호를 표로 남긴다 |
| `io[]`의 quantity가 비어 있지 않다 | 바꾸지 않는다. 사진만으로 수량을 확정하지 않는다 |
| ULXD4D 재검증에서 기존 값과 근거가 어긋난다 | **사용자 확인 전 수정하지 않는다.** 기존 공개본이 이미 승인을 받았기 때문이다. 변경 전/후·쪽 번호를 별도 표로 제시한다 |

## 5. 좌표와 번호 원칙

### 데이터 계약 (렌더러 검증 기준)

`prototype/brc-am7/detail-enhancements.mjs`의 `validMap` / `validMarker`가 실제 판정자다. 아래를 벗어나면 지도는 표시되지 않고 fallback된다.

```text
portMap: {
  image: 'Front' | 'Rear',          # 이번 배치는 전부 'Rear'
  measuredImage: { file, width, height },   # 9종 전부 필수 (4장 G4)
  crop?: { top, bottom },           # 선택. 상하 여백 축소용
  items: [ { n, label, desc, x1, x2, y?, side? } ]
}
```

- `n`: 1 이상의 정수, 제품 안에서 **중복 금지**. 1부터 빠짐없이 연속하게 쓴다(Crown 1차 검사와 동일).
- `label`: 비어 있을 수 없다. `desc`: 문자열이며 빈 문자열 허용. 근거가 없으면 비운다.
- `x1`·`x2`: 게시 이미지의 **원본 픽셀** 가로 범위. `x1 ≥ 0`, `x2 > x1`, `x2 ≤ 이미지 폭`.
- `y`: 선택이지만 이번 배치는 **전부 기입**한다. `0 ≤ y ≤ 이미지 높이`.
- `side`: `top` 또는 `bottom`. 설명 말풍선이 붙는 방향이다.
- `crop`을 쓰면 모든 `items`의 `y`가 `crop.top` 이상 `높이 − crop.bottom` 이하여야 한다.
- **`items`에 `evidence` 필드를 넣지 않는다.** 허용 키가 아니므로 지도 전체가 거부된다. 근거(PDF 쪽)는 `Work/기록/W-20261002-001-shure-port-map-evidence.json`의 `markers[].pages`에 둔다. 제품 JSON과 근거 JSON은 `pages`를 뺀 나머지가 정확히 일치해야 한다.

### 측정 원칙

- 좌표는 **게시 WebP의 실제 디코딩 픽셀**을 열어 측정한다. 화면 표시 크기나 확대 배율로 환산하지 않는다.
- 원본 메타데이터(`originalSize`)를 고치지 않는다. 측정한 게시 파일과 크기를 `measuredImage`에 명시한다.
- 거울 반사상·그림자·제품 외부 영역에는 번호를 붙이지 않는다(Crown I-Tech 선례).
- `x1`~`x2`는 단자 구멍의 가로 폭에 맞춘다. 인접 단자와 겹치지 않게 한다.

### 번호 순서

**입력 → 출력 → 네트워크/제어 → 전원** 순으로 매긴다. 분리된 A/B·채널별 단자는 **각각 별도 번호**를 받는다. 기존 ULXD4D가 이 규칙의 기준 사례다.

```text
1 안테나 입력 A      2 안테나 입력 B        (입력)
3 오디오 출력 1      4 오디오 출력 2        (출력)
5 캐스케이드 출력 A   6 캐스케이드 출력 B     (출력 — 분배)
7 출력 1 MIC/LINE   8 출력 2 MIC/LINE      (출력 관련 스위치)
9 Dante Primary   10 Dante Secondary     (네트워크)
11 AC 전원 입력                            (전원)
```

형제 모델은 **같은 역할에 같은 명칭**을 쓴다. ULXD4(1채널) / ULXD4D(2채널) / ULXD4Q(4채널)의 "오디오 출력"은 채널 수만 다르고 표현이 달라지지 않아야 한다. SLXD4+ / SLXD4D+도 같다.

### 설명 문구

- 한 줄로 **연결 대상 + 핵심 조건**을 적는다. 예: `밸런스 XLR · 믹서 등의 마이크/라인 입력에 연결합니다.`
- 길이는 160자 이내(렌더러 제한). 실제로는 한 줄에 읽히는 길이를 쓴다.
- 전압·전류·거리 같은 수치는 **PDF 쪽 근거가 있을 때만** 쓴다. 없으면 연결 대상만 적는다.
- 사양서 문장을 그대로 옮기지 않고 연결 관점으로 다시 쓰되, 의미를 바꾸지 않는다.
