# 모델·추론 강도 선택 기준 — 토큰 절약 (2026-10-05)

- 상태: **사용자 지시로 적용**
- 상위 문서: [MODEL_ROUTING.md](../../MODEL_ROUTING.md) — **모델 선택** 원칙. 이 문서는 거기에 **추론 강도**를 더한다
- 사용자 지시 원문: 2026-10-05 **"토근아껴서 쓸수 있도록 사용 모델과 추론을 적절하게 판단해서 코딩을 시켜줘"**

## 왜 고치나 — 지금까지 전부 `high`였다

Work가 `Work/기록/`의 인계서를 세어 봤다.

```
49건  모델: 실행 `gpt-6-sol`(high).
```

**거의 전부가 `high`다.** 작업 난이도를 따져서 고른 게 아니라 **템플릿에 없으니 앞 건을 복사한 결과**다.

[MODEL_ROUTING.md](../../MODEL_ROUTING.md)는 모델 선택만 다루고 **추론 강도를 말하지 않는다.** 그런데 토큰은 **추론 강도에서 가장 많이 나간다.** 그 빈칸을 메운다.

> **원칙은 그대로다.** *Use the simplest model that can reliably complete the task.* 여기에 **「그리고 가장 낮은 추론 강도」**를 더한다.

추론 강도: `low` · `medium` · `high` · `xhigh` · `max` · `ultra`

## ★ 작업 유형별 기준

우리가 실제로 하는 일로 적었다. **인계서에 이 표의 줄을 근거로 적는다.**

| 작업 유형 | 실제 예 | 모델 | 강도 |
|---|---|---|---|
| **문서·기록만** | 종료 기록, 지시서 갱신 | `gpt-6-luna` | **`low`** |
| **한두 행 수정** | [W-005](../작업/W-20261005-005.md) ANT 1행 | `gpt-6-sol` | **`low`** |
| **기존 스키마에 제품 추가** | [W-006](../작업/W-20261005-006.md) 8종, [W-007](../작업/W-20261005-007.md) 2종 | `gpt-6-sol` | **`medium`** |
| **사진 등록만** | VARIA 측면·후면 | `gpt-6-sol` | **`medium`** |
| **Port Map 좌표 작업** | [W-008](../작업/W-20261005-008.md) NX, BSS 후면 | `gpt-6-sol` | **`high`** |
| **여러 자료 대조·충돌 판정** | 국내/해외 사양 행 단위 대조 | `gpt-6-sol` | **`high`** |
| **검사 실패 원인 추적** | RTCOM `EPERM` | `gpt-6-sol` | **`high`** |
| **번호 체계·렌더러 설계** | IN/OUT 묶음 번호 | `gpt-6-astra` | **`high`** — **설계 판단만.** 구현은 기본 모델로 되돌린다 |

### 왜 Port Map만 `high`인가

좌표를 **한 번 잘못 재면 번호가 엉뚱한 단자를 가리킨다.** 화면에 그대로 나가고, 사람이 다시 열어 보기 전에는 안 걸린다. **되돌리는 비용이 아끼는 비용보다 크다.**

반대로 **제품 추가는 검사가 잡아 준다.** 행 수·순서·해시가 다 고정돼 있어서 틀리면 바로 빨개진다. `medium`으로 충분하다.

> **기준은 「틀렸을 때 누가 잡아 주는가」다.** 검사가 잡아 주면 낮추고, 사람 눈이어야 하면 높인다.

## ★★ 가장 큰 절약은 모델이 아니다

**재작업이 제일 비싸다.**

[W-20261005-007](../작업/W-20261005-007.md)에서 Work가 PDF 글자 추출만 믿고 **"설명서에 `QM75C`가 없다"**고 단정했다. 틀렸다. Codex가 멈추고 보고 → Work가 2판 작성 → 재지시. **한 작업을 두 번 돌렸다.** 어떤 모델을 썼든 이게 더 비싸다.

| 절약 수단 | 효과 |
|---|---|
| **Work가 미리 조사해 표로 넣기** | Codex가 탐색에 쓰는 토큰이 줄어든다. 이미 하고 있다 |
| **멈춤 조건을 분명히** | 헛돌지 않는다 |
| **"하면 안 되는 것" 목록** | 범위 밖 작업을 막는다 |
| **Work가 단정하지 않기** | **재작업을 막는다. 이게 제일 크다** |

> **지시서 품질이 모델 선택보다 토큰을 더 아낀다.**

## 인계서에 적는 법

맨 아래 한 줄을 **근거와 함께** 적는다.

```
모델: 실행 `gpt-6-sol`(medium) — 기존 스키마에 제품 추가.
```

**근거 없이 강도만 적지 않는다.** 앞 건을 복사하지 않는다.

### 올리는 경우

Codex가 **같은 자리에서 두 번 막히면** 그때 올린다. 처음부터 올리지 않는다.

## 용량 초과 대응

`gpt-6-sol`이 용량 초과면 **같은 강도로** 바꾼다.

```
gpt-6-sol  →  gpt-6-astra  →  gpt-5.6-sol  →  gpt-6-luna
```

**용량 때문에 바꾼 모델을 다음 작업의 기본으로 삼지 않는다.** 풀리면 되돌린다.

## 사람 판단은 그대로다

[MODEL_ROUTING.md 7장](../../MODEL_ROUTING.md)이 그대로 산다. **Astra가 말했다고 정답이 아니다.** 스키마·분류·구조 변경은 **사용자 승인 없이 진행하지 않는다.**

그리고 [8장](../../MODEL_ROUTING.md)도 그대로다 — **단자 종류·수량·해상도·대역폭·전원·치수·호환성은 추측해서 만들지 않는다.** 강도를 낮추는 것과 지어내는 것은 다르다.
