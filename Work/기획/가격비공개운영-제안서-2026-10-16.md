- 작성: Claude Code (사용자 soojhann 요청)

## 한 줄 요약

견적 앱의 **판매 단가(1,468품목)가 지금 인터넷에 공개돼 있다. 원가는 공개돼 있지 않다.** 판매가는 고객 견적서에도 품목별로 찍혀 나가는 값이라 **공개해도 괜찮을 수 있다.** 그래서 먼저 "이 판매가가 비밀인가"를 정하고,
- **비밀이 아니면** → 지금처럼 두고, 원가만 각자 PC에 보관하게 편하게 만든다(**공개 유지안**).
- **비밀이면** → 판매가도 저장소에서 빼고 각자 PC에서 가격표를 불러오게 한다(**A안**).

어느 쪽이든 비용은 0원이고 포털·Builder 공개는 그대로다.

## 1. 현재 상황

| 항목 | 사실 (2026-10-16 확인) |
|---|---|
| 공개된 것 | `cpq/data/approved/prices.json` — 1,468품목의 **판매 단가(재료비 단가)**만. 품목코드와 숫자뿐이다 |
| 공개 주소 | `https://seoulav.github.io/AV-Portal/cpq/data/approved/prices.json` 이 누구에게나 열린다(HTTP 200) |
| 저장소 | `Seoulav/AV-Portal`은 **공개 저장소**. 2026-10-12 커밋 `3de8448b`부터 이력에 있다. 포크 0건 |
| 공개되지 않은 것 | **원가·매입처·제조사/구매처·영업비고**. 원래 저장소에 넣지 않았고, 원가는 "내 PC 원가 확인"에서 매번 파일을 골라 그 화면에서만 쓴다 |
| 고객 견적서 | 고객용 Excel(2단계)은 설명·제조사/구매처·영업비고·품셈·노임 열을 지우지만 **품목별 판매 단가는 그대로 보여 준다** |
| GitHub 요금제 | Seoulav 조직은 **Free** |

## 2. 먼저 정할 것: 이 판매가는 비밀인가?

### 공개돼도 괜찮을 수 있는 이유

- 공개된 것은 **판매가**다. 회사의 마진을 드러내는 **원가·매입처는 공개되지 않았다.**
- 판매가는 **견적서를 받은 고객이 이미 보는 값**이다. 우리가 보낸 견적서마다 품목별 단가가 적혀 있다.
- 공개해 두면 **직원·협력사가 설정 없이 바로** 가격이 붙은 견적을 볼 수 있다. A안은 PC마다 가격표를 한 번 불러와야 한다.

### 그래도 비밀로 해야 할 수 있는 이유

- 견적서 몇 장과 **1,468품목 전체 단가표**는 다르다. 경쟁사가 한 번에 받아 가면 우리 가격 정책 전체가 보인다.
- 고객마다 **할인·협상가**를 주고 있다면, 정가표가 공개돼 있는 것이 협상에 불리할 수 있다.
- 공급사·대리점과 **"가격 비공개" 약정**이 있는 품목이 섞여 있을 수 있다.
- 이 가격표를 만드는 원본(표준품셈 xlsx)이 **사내 자료**라면, 거기서 뽑은 숫자도 사내 자료로 볼 수 있다.

### 판단 기준 (아래 중 하나라도 "예"면 비밀로 본다)

1. 고객마다 판매가를 다르게 주는가(할인·협상)?
2. 공급사·대리점과 가격을 공개하지 않기로 약정한 품목이 있는가?
3. 경쟁사가 전체 단가표를 갖게 되면 곤란한가?

셋 다 "아니오"면 **공개 유지안**이 더 편하다.

## 3. 판매가가 비밀일 때의 위험

1. **누구나 우리 판매 단가 전체를 받아 갈 수 있다.** 주소만 알면 경쟁사·고객도 내려받는다.
2. **지워도 과거 기록에서 다시 나온다.** 공개 저장소의 Git 이력은 영구 보관된다. 지금 지워도 2026-10-12 이후 커밋에서 꺼낼 수 있다.
3. **AI 에이전트가 가격을 읽는다.** 이 저장소에서 일하는 Claude·Codex·Gemini가 파일을 열면 가격이 대화 기록과 외부 서비스 로그에 남는다.

공개 유지로 정해도 남는 위험이 하나 있다.

4. **원가를 쓰기 불편하다.** 원가는 매번 파일을 다시 골라야 해서, 누군가 원가를 저장소에 올리고 싶어질 수 있다. 그러면 1~3번 위험이 **원가**로 번진다. 원가는 어느 경우든 반드시 비공개다.

## 4. 원인

- 견적 앱은 **GitHub Pages 정적 사이트**다. 서버도 로그인도 없어서, 앱이 읽는 파일은 모두 공개 주소가 된다. "앱에 넣는다"가 곧 "인터넷에 공개한다"이다.
- 처음 설계에서 판매가를 품목 목록(`products.json`)과 **분리해 두었다**(결정 D3, 나중에 뺄 수 있게). 공개 여부를 정하지 않은 채 배포됐다.
- 저장소를 비공개로 바꿔도 해결되지 않는다.
  - Free 요금제에서는 비공개 저장소의 **Pages가 꺼진다** → 포털·Builder·견적 앱이 모두 닫힌다.
  - 유료(Team, 1인 월 $4)로 올려도 **사이트 자체는 공개**다. 로그인을 걸려면 Enterprise Cloud(1인 월 약 $21)가 필요하다.
  - 비공개여도 저장소에서 일하는 AI는 가격을 그대로 읽는다.

## 5. 해결 방안

### 공개 유지안 — 판매가가 비밀이 아닐 때

- `prices.json`은 **지금처럼 둔다.** 견적 앱은 열자마자 판매가가 붙는다.
- 이 결정을 문서로 남긴다: "판매가는 공개 자료, 원가·매입처는 비공개". 나중에 누가 같은 걱정을 하지 않게 한다.
- **원가만** B-20261016-06 방식으로 바꾼다. 원가 파일을 한 번 불러오면 이 PC 브라우저에 기억하고, 원가 파일이 저장소에 들어오지 못하게 막는다(`.gitignore`·자동 검사·`AGENTS.md`).

### A안 — 판매가도 비밀일 때

**가격은 저장소에 두지 않는다. 직원 PC의 브라우저 안에만 둔다.**

```
[직원이 가진 가격표 파일]  →  견적 앱 "가격표 불러오기"  →  이 PC 브라우저에 저장
     (표준품셈 원본 xlsx)          (파일은 어디로도 전송 안 됨)      (다음 방문 때 자동 적용)
```

하는 일:
1. `prices.json`을 저장소와 웹사이트에서 **뺀다.**
2. 견적 앱에 **가격표 불러오기 / 지우기** 단추를 둔다. 1순위 가격표는 회사가 이미 가진 **표준품셈 원본 xlsx**(원가 열·판매가 열 포함)다. 원본이 없으면 앱이 주는 빈 서식(4시트)에 채워 쓴다.
3. 가격표가 없으면 금액 칸은 **"단가 미등록"**으로 비운다(0으로 채우지 않는다). 품목·수량·노무비 계산은 그대로 된다.
4. 품명·규격이 우리 품목과 다른 행은 가격을 붙이지 않고 **"확인 필요"**로 표시한다(판이 다른 파일을 잘못 맞추지 않게).
5. 가격표 파일이 다시 저장소에 들어오지 못하게 `.gitignore`·자동 검사·AI 작업 규칙(`AGENTS.md`)을 둔다. 시험은 가짜 가격으로만 한다.

직원이 쓰는 법:
- **처음 한 번**: 견적 앱 → 가격표 불러오기 → 파일 선택 → (처음만) 원가 열·판매가 열 확인
- **그다음부터**: 그냥 견적 앱을 열면 가격이 붙어 있다
- **가격이 바뀌면**: 새 파일을 다시 불러온다
- **공용 PC를 쓰면**: 끝나고 "가격표 지우기"

## 7. 한계 (숨기지 않고 알린다)

- **이미 공개된 과거 판매가(2026-10-12 이후 커밋)는 A안으로도 되돌리지 않는다.** 이력을 다시 쓰려면 강제 push가 필요하고, 남이 받아 간 사본까지 지울 수는 없다. 2026-10-04 영업자료 사건 때와 같은 결정이다(AGENTS.md 「비공개 자료는 올리기 전에 암호화한다」). 따라서 A안의 효과는 **앞으로 바뀌는 가격**을 지키는 데 있다.
- A안에서는 가격표가 PC·브라우저마다 따로 있다. 브라우저 데이터를 지우면 다시 불러와야 한다.
- 가격표를 나눠 주는 일(메일·사내 공유폴더)은 앱 밖에서 한다. 공유 서버는 이번 범위가 아니다.

## 8. 확인받을 사항 (새 담당자에게)

1. **판매가를 공개해도 되는가?** — 2절 판단 기준 3가지로 답한다. 이 답이 공개 유지안과 A안을 가른다.
2. (A안이면) 1순위 가격표로 **표준품셈 원본 xlsx**를 쓰는가, 앱이 주는 **빈 서식**에 따로 관리하는가
3. (A안이면) 과거 이력에 남은 판매가는 그대로 두는 데 동의하는가
4. (선택) 나중에 B안(암호화 게시)을 더할지 — 지금은 범위 밖

## 이어받는 에이전트 안내

이 제안서를 받은 에이전트는 바로 코드를 고치지 않는다. 다음 순서를 따른다.

1. **최신 상태 확인**: `git fetch origin` 후 `origin/main`에서 아래를 확인한다. 하나라도 이미 바뀌었으면 이 문서의 「현재 상황」을 최신 값으로 고쳐 말한다.
   - [B-20261016-06](../빌더/작업/B-20261016-06.md) 상태와 승인 칸(이미 공개 여부가 정해졌거나 진행·완료됐으면 재구현하지 않는다)
   - `cpq/data/approved/prices.json`이 아직 있는지, 공개 주소가 아직 200인지(`curl -s -o /dev/null -w '%{http_code}' <주소>`)
   - 열린 PR 중 `cpq/`를 건드리는 것이 있는지(`gh pr list`)
2. **설명**: 상대에게 이 순서로 짧게 말한다 — 「판매가는 지금 공개돼 있고 원가는 아니다 → 판매가는 견적서에도 나가니 공개해도 될 수 있다 → 비밀이어야 하는 경우 3가지 → 비밀이면 A안, 아니면 공개 유지안 → 저장소 비공개 전환은 왜 답이 아닌가」. 금액 예시는 들지 않는다.
3. **확인**: 8절 질문을 묻고 답을 받는다. 답은 B-20261016-06 명세의 승인 칸에 날짜와 함께 적는다. 공개 유지로 정하면 명세의 「공개 판매 단가 제거」 항목을 빼는 변경을 같은 기록에 남긴다.
4. **착수**: B-20261016-06 명세의 「할 일」「검증」대로 구현한다(공개 유지안이면 원가 부분만). 작업 흐름은 `AGENTS.md`(전용 워크트리, `claude-feat/`·`codex/` 브랜치, PR)를 따른다.
5. **금지**: 실제 가격표·원가 파일을 열거나, 요청하거나, 저장소에 넣지 않는다. 시험은 가짜 가격으로만 한다. 공개 노출을 확인할 때도 파일 내용은 열지 않고 응답 코드만 본다.
