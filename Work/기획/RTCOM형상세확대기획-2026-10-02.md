## 2. "완전 적용"을 다시 정의한다

235종에 네 요소를 전부 채우는 것은 **달성 불가능한 목표**다. 근거가 구조적으로 없는 경우가 있기 때문이다.

- `portMap`: Rear 사진이 없는 **138종**은 원천적으로 불가능하다.
- `signalFlow`: 디스플레이 **38종**은 렌더러가 유형 자체를 거부한다. `validFlow`가 첫 줄에서 `isDisplayProduct(product)`를 검사해 바로 반환하므로 **관례가 아니라 코드로 막혀 있다.** 잘못 입력해도 03 연결 단자로 fallback한다. 1단계 Signal Flow 보완에서 `projector-display-input` 유형을 제거한 것도 같은 이유다. 2026-10-02 사용자가 이 판단을 확인했다.
- `settings`: EDID·DIP·모드 표가 실제로 있는 제품에만 해당한다.

그래서 "모든 칸을 채운 제품 수"를 목표 지표로 쓰면 영원히 미달로 보인다. 대신 **제품별 적용 완료**를 이렇게 정의한다.

> **적용 완료** = 그 제품에 적용 가능한 요소를 모두 채우고, 적용 불가능한 요소는 **사유와 함께 "해당 없음"으로 기록**한 상태.

| 요소 | 적용 대상 판정 | 해당 없음 사유 예 |
|---|---|---|
| 01 한눈에 보기 | **전 제품**. 기존 VERIFIED/FOUND 사양·I/O와 기존 `sources`로 작성 | 근거 행이 전혀 없는 제품 |
| 02 Port Map | Rear 사진 + 근거 PDF의 단자 쪽이 있을 때 | Rear 사진 없음 / 해상도 부족 / 근거 PDF 없음 |
| 03 Signal Flow | **해석이 필요한 5개 유형만** — switcher·video-processor·audio-dsp·mixer·matrix (27종) | 그 외 전부. 앰프·스피커·디스플레이·무선마이크·마이크·카메라·네트워크·제어·전원 등 |
| 06·07 설정 | EDID·DIP·모드·표 데이터가 공식 자료에 있을 때 | 해당 설정이 없는 제품 |

이 정의에 따라 각 배치는 **처리한 제품 수 = 채운 수 + 해당 없음으로 확정한 수**를 보고한다. 미처리와 해당 없음을 섞지 않는다.

근거가 제품 밖에 있지 않다는 점이 핵심이다. `lead`는 기존 `overview`를 두 문장으로 압축하고, `keyFacts`는 기존 `specifications`·`io`의 **VERIFIED/FOUND 행에서만** 최대 4개를 고른다. 새 PDF 독해가 필요 없어 배치 크기를 크게 잡을 수 있다(제조사별 10~20종).

이전 계획은 비디스플레이 202종 중 '가능' 68종을 대상으로 봤다. **그 계획은 이 지시로 대체된다.** [대응표](../기록/W-20261001-001-Signal-Flow-자료현황.md)의 유형 분류는 그대로 쓰되 대상만 좁힌다.

## 5. 공통 규칙 (모든 트랙)

기존 승인 범위에서 이미 확정된 규칙을 반복한다. 배치 명세는 이 절을 참조만 하고 다시 쓰지 않는다.

1. **추측 금지.** 정보 없음 / 0 / 미지원 / 해당 없음을 구분한다. 근거 없는 값은 비운다.
2. **기존 값 불변.** `portMap`·`signalFlow`·`lead`·`keyFacts`·`settings`는 선택 필드로만 추가한다. 기존 사양·I/O·검증 상태·사진·출처는 바꾸지 않는다. 매뉴얼 쪽 근거가 있는 **빈** quantity만 예외로 채울 수 있다.
3. **파일명이 아니라 본문으로 판정.** 공통 시리즈 PDF가 대상 모델을 포함하는지, 해당 모델의 쪽이 실제로 있는지를 사람이 확인한다. [Shure 기획 3장](Shure후면PortMap기획-2026-10-02.md#3-모델별-pdf-본문-적용단자-페이지-판정-절차)의 G1~G5를 트랙 공통 절차로 쓴다.
4. **`measuredImage`를 넣는다.** 게시 이미지의 `originalSize`가 게시 크기와 다른 제품이 많아, 생략하면 지도가 조용히 숨겨진다. Track A 15종 중 11종이 여기 해당한다.
5. **렌더러 허용 키만 쓴다.** `portMap.items`의 허용 키는 `n, label, desc, x1, x2, y, side`뿐이다. `evidence`를 넣으면 지도 전체가 거부된다. 근거는 별도 evidence JSON에 둔다.
6. **새 웹 조사 금지.** 저장소에 이미 있는 공개 자산만 쓴다. 부족하면 Track E로 넘긴다.
7. **이미 승인된 공개본 보존.** 시범 5종과 Crown 22종의 기존 값은 재검증 중 어긋나는 점이 나와도 **사용자 확인 전에 수정하지 않는다.**
8. **기존 값과 충돌하면 둘 다 보존**하고 이슈로 기록한다. 지도를 맞추려고 I/O를 고치지 않는다.
9. **반복 단자는 묶는다.** 같은 `label`·`desc`가 5회 이상 반복되면 번호 하나가 그 단자 블록 전체를 덮도록 `x1`~`x2`를 넓히고 범위·수량을 표기한다. 블록이 떨어져 있으면 블록마다 따로 묶는다. 2026-10-02 DM7에서 번호 63개 중 48개가 설명까지 같은 사례가 나와 추가한 규칙이며, 수정 작업은 [W-20261002-004](../작업/W-20261002-004.md)다. 채널별 번호 분리는 2채널 수신기 기준으로 쓴 규칙이었고 상한이 없어 120채널 콘솔에서 폭발했다.

## 6. 작업량 — 기존 추정을 어떻게 볼 것인가

[잔여 235종 작업량 추정](../기록/W-20261001-001-후속작업량.md)은 **268~536 작업시간**이다. 다만 그 표는 시범 5종 시점에 만든 보수적 검토 예산이고, 그 뒤 Crown 22종이 실제로 한 PR로 처리됐다. 같은 문서도 "첫 승인 배치 완료 후 실제 시간을 나눠 측정해 재산정"을 제안하고 있다.

따라서 이 기획은 **총 시간을 다시 약속하지 않는다.** 대신 배치마다 다음을 기록해 재산정 근거를 쌓는다.

- 게이트 통과/탈락 종수
- 채운 항목 수와 해당 없음 확정 수
- 전용 검사 RED→GREEN 시점
- 재작업이 발생한 항목과 원인

Crown 22종과 Shure 9종의 실측이 모이면 Track A 기준 종당 비용이 나온다. 그 값으로 Track B·C 추정을 갱신한다.

## 7. 모델 운영 제안

[MODEL_ROUTING.md](../../MODEL_ROUTING.md)는 **"Use the simplest model that can reliably complete the task"**를 원칙으로 두고, "기존 Schema에 제품 데이터 추가"를 **Astra 사용하지 않는 작업**으로 명시한다. 이 확대 작업의 본체는 정확히 그 범주다.

현재 Paseo codex 공급자에서 고를 수 있는 모델은 `gpt-6-astra`(frontier, 기본값), `gpt-6-sol`(이전 세대 주력), `gpt-6-luna`(빠르고 저렴), `gpt-5.6-sol` / `gpt-5.6-terra` / `gpt-5.6-luna`, `gpt-5.5`다. 추론 수준은 low / medium / high / xhigh / max(일부 ultra)를 고를 수 있다.

| 작업 | 제안 모델 | 추론 | 근거 |
|---|---|---|---|
| Track A·B 데이터 입력 배치 | **`gpt-6-sol`** | high | 기존 패턴 반복. 규칙이 명세에 고정돼 있어 frontier 추론이 필요 없다 |
| Track C Signal Flow '가능' 분 | **`gpt-6-sol`** | high | 유형·연결 규칙이 렌더러 검증으로 고정돼 있다 |
| Track C '일부' 131종, 카드·모듈형(NovaStar·Analog Way·AMX) | **`gpt-6-astra`** | high | 여러 자료를 동시에 대조하는 §3.2 복합 추론 |
| 배치 완료 후 독립 리뷰 | **`gpt-6-astra`** | high~xhigh | §3.5 중요 데이터 무결성 검증 |
| 집계·목록화(Track D 후보 수집) | **`gpt-6-luna`** | medium | 기계적 수집 |

**현재 설정에 대한 구체적 제안이 하나 있다.** Shure 배치를 맡은 세션은 `gpt-6-astra` / medium이고, "코덱스 제안/리뷰" 세션은 `gpt-6-sol` / high다. MODEL_ROUTING 기준으로는 **역할이 뒤바뀌어 있다.** 실행은 `gpt-6-sol`, 독립 리뷰는 `gpt-6-astra`가 정책에 맞는다. 정책 §6 Partial Escalation의 "어려운 분석·리뷰에만 상향하고 통상 구현은 기본 모델로"가 이 경우다.

진행 중인 Shure 배치의 모델을 중간에 바꾸는 것은 권하지 않는다. **다음 배치부터** 위 배치를 적용하기를 제안한다. 모델 선택은 사용자 결정 사항이며 이 기획이 확정하지 않는다.
