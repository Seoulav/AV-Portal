## 목표와 현재 상태

공개 상세 5개의 `images`가 모두 `[]`여서 갤러리가 비어 있다. **렌더링 코드는 전부 살아 있다.**

`beta/site/detail/app.js`에 다음이 이미 구현돼 있다.

| 기능 | 위치 |
|---|---|
| 대표 이미지 선택·교체 | `selectImage(index)` — `featured.src = './images/' + item.file` |
| 썸네일 목록 + 역할 라벨 | `data.images.entries()` 순회, `aria-pressed` 관리 |
| 확대 다이얼로그 | `#image-dialog`, `zoomButton`, Esc·초점 복귀 |
| Rear 바로가기 | `data.rearIndex` |
| 로드 실패 대체 | `featured` `load`/`error` 핸들러, 썸네일 개별 대체 |
| 출처·권한 표시 | `#image-provenance`, `#image-source-link` |

즉 **이미지 파일과 `images[]` 데이터만 넣으면 갤러리가 동작한다.** 막고 있는 것은 공개 게이트 세 곳이다.

| 위치 | 현재 | 바꿀 것 |
|---|---|---|
| `beta/verify-pages.mjs:9` | `detail/`에 `app.js`·`data`·`index.html`·`product-detail-model.mjs`·`styles.css`만 허용 | `images` 디렉터리 허용 |
| `beta/verify-pages.mjs:82` | `assert.deepEqual(product.images, [], 'No image binaries or hotlinks')` | 규칙 검사로 교체 |
| `beta/verify-pages.mjs:43-47` | 제품별 상세 JSON SHA-256 고정 | 갱신 필요 |

`imageStatuses`는 그대로 둔다. BRC-AM7은 `Main`·`Front`·`Rear`·`Perspective`가 `FOUND`, `Other`가 `REVIEW REQUIRED`다. 게시한 이미지와 아직 확인 중인 역할을 구분해서 보여주는 장치이므로 없애지 않는다.

## 범위

### 1. 이미지 파일 배치

- 경로: `beta/site/detail/images/<slug>/<role>.<ext>` — `app.js`가 `./images/` + `file`을 쓰므로 `file`에 `<slug>/<role>.<ext>` 또는 상대 경로를 담는다. 어느 쪽이든 **기존 `selectImage`의 경로 조립을 바꾸지 않는 형태**를 우선한다.
- 원본은 Git에 없다. 사용자가 제공하는 로컬 폴더에서 가져온다. 경로는 `--images <dir>` 인자 또는 `AV_PORTAL_PRODUCT_IMAGES` 환경변수로 받는다. `AV_PORTAL_GROUP1_PACKAGES`와 같은 방식이다.
- 형식: **WebP 우선**, 없으면 JPEG. PNG는 스크린샷·도면에만.
- 한 장당 **400KB 이하**, 가로 **1600px 이하**. 초과하면 빌드가 실패하고 무엇이 초과했는지 알린다.
- 파일명은 소문자·하이픈만.

### 2. `images[]` 데이터

각 항목은 다음을 가진다. `app.js`가 이미 읽는 키를 그대로 쓴다.

| 키 | 필수 | 설명 |
|---|---|---|
| `file` | ✅ | `images/` 기준 상대 경로 |
| `role` | ✅ | `Main`·`Front`·`Rear`·`Perspective` 등. `imageStatuses`의 역할명과 일치 |
| `alt` | ✅ | 한국어 대체 텍스트. **제품명 반복이 아니라 무엇이 보이는지** 적는다 |
| `note` | | 캡션 |
| `provider` | | 이미지 제공처 |
| `rights` | ✅ | 사용 근거. `OWN_PHOTO` / `DEALER_AGREEMENT` / `PARTNER_PORTAL` / `MANUFACTURER_GRANT` / `OWN_ARTWORK` 중 하나 |
| `sourceUrl` | | 공식 출처 URL |

`rights`는 **자산 출처 기록**이다. 값이 없거나 허용 밖이면 배포 검사가 실패한다. 실수로 근거 없는 파일이 섞이는 것을 막는 장치다.

### 3. 공개 게이트 전환

`verify-pages.mjs`에서 이미지 차단을 **규칙 검사**로 바꾼다. 유출 방지 강도를 낮추지 않는다.

- `detail/images/` 디렉터리를 허용하되 **그 안만** 허용한다. 다른 위치의 이미지는 여전히 차단
- 허용 확장자: `.webp`·`.jpg`·`.jpeg`·`.png`. **PDF는 계속 차단**
- 파일 크기·해상도 상한 검사
- `images[]`의 모든 `file`이 실제로 존재하고, 디렉터리의 모든 파일이 어느 `images[]`에서 참조되는지 **양방향 대조**
- 모든 항목에 `alt`가 비어 있지 않고 `rights`가 허용값인지
- `sourceUrl`이 있으면 기존 URL 규칙(HTTPS·자격정보 없음·제조사 호스트) 적용
- 금지 표식 정규식은 그대로

### 4. 새 디자인 갤러리 (선택 범위)

사용자가 제시한 시안의 좌측 갤러리 형태로 맞춘다. 기존 요소를 재배치하는 수준으로 하고, 새 기능을 만들지 않는다.

- 큰 이미지 + 좌우 이동 버튼
- 하단 썸네일에 역할 라벨(`Front`·`Rear`·`Perspective`)과 선택 테두리
- 좌상단 제조사 뱃지, 우상단 확대 아이콘
- 데스크톱 2열(갤러리 ǀ 정보), 모바일 1열
- **이미지 0장인 제품은 갤러리 영역을 만들지 않는다** — W-015에서 확정한 동작 유지

이 4번은 1~3번이 끝난 뒤 같은 PR에서 이어서 한다. 1~3번만으로도 갤러리는 동작한다.

## 미결 사항·의존성

- **이미지 원본은 사용자가 제공한다.** 파일이 없으면 이 작업은 시작할 수 없다. 어떤 제품의 어떤 역할이 제공됐는지 먼저 확인하고, 일부만 있으면 있는 것만 게시하고 나머지는 `imageStatuses`로 남긴다.
- `rights` 값의 실제 근거는 사용자 판단이다. 이 작업은 값을 기록하고 비어 있으면 막을 뿐, 근거의 타당성을 판정하지 않는다.
- W-017이 `verify-pages.mjs`를 규칙 기반으로 바꾼다. **같은 파일이다.** 둘 중 하나를 먼저 병합하고 나머지를 최신 main 위에서 진행한다. 순서는 W-017 → W-020을 권한다. W-017의 규칙 기반 구조 위에 이미지 규칙을 얹는 편이 깔끔하다.
- 시안의 6탭 구조 적용은 별도 작업이다. 이 작업은 현재 2탭 구조 위에서 갤러리만 켠다.
