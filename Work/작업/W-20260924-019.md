## 범위

- 변경할 파일: `beta/site/index.html`, `beta/site/detail/index.html`, `prototype/brc-am7/index.html`(정본), `beta/site/detail/app.js`·`prototype/brc-am7/app.js`, 아이콘 파일, `Work/지시서.md`
- 변경하지 않을 영역: 제품 데이터 값, 화면 구조·레이아웃, Library 27개, 검증 상태 표기

### 1. 정적 메타

- Library `index.html`에 `description`과 기본 OG 태그(`og:title`·`og:description`·`og:type`·`og:url`·`og:site_name`)를 넣는다.
- 상세 `index.html`에도 기본값을 넣는다. 상세는 JSON 로드 전에는 제품을 모르므로 기본값이 필요하다.

### 2. 제품별 동적 메타

- 상세 `app.js`가 제품 데이터를 읽은 뒤 `og:title`·`og:description`·`og:url`과 `meta description`을 제품 값으로 갱신한다.
- `og:title`은 `<제조사> <모델>`, `description`은 `english`(없으면 `korean`의 첫 문장)를 쓴다. **값을 지어내지 않는다.**
- `og:url`은 현재 주소의 정규화된 형태를 쓴다.

**한계를 명시한다.** 대부분의 메신저·SNS 크롤러는 JavaScript를 실행하지 않으므로 동적 갱신이 미리보기에 반영되지 않을 수 있다. 정적 기본값이 최소한의 표시를 보장한다. 제품별 정적 메타가 필요하면 제품마다 HTML을 생성해야 하며, 이는 현재의 공통 렌더러 구조를 바꾸는 별도 작업이다. **이번 범위에서 결론짓지 않고 한계를 기록한다.**

### 3. favicon

- SVG 또는 작은 PNG 아이콘을 추가하고 두 HTML에서 참조한다.
- **제조사 로고나 외부 자산을 쓰지 않는다.** AV Portal 자체 표식만 쓴다.
- `beta/verify-pages.mjs`의 파일 목록 assert에 아이콘 파일을 반영한다. 이미지 바이너리 유입 금지 규칙과 충돌하지 않도록, 인라인 SVG 등 텍스트 형식을 우선 검토한다. 바이너리를 추가해야 하면 그 사실과 근거를 기록한다.

### 4. OG 이미지

- 제품 사진은 **재게시 권한이 미확인**이므로 `og:image`에 쓰지 않는다. 공개 5개 제품의 `images`는 모두 비어 있다.
- 필요하면 제품 사진이 아닌 자체 제작 이미지만 쓴다. 이번 범위에서는 `og:image` 없이 진행해도 된다.
