## ★★ 핵심 발견 — 렌더러를 바꿀 필요가 없다

대기열 문서는 "묶음 번호는 번호 체계 변경이라 렌더러·검증기에 영향"이라고 적었다. **Work가 알티컴 원본 데이터를 열어 확인한 결과, 틀린 걱정이었다.**

사용자가 가리킨 알티컴 `qms-44ux`의 실제 `portMap`이다.

```json
{ "n": 1, "label": "INPUT 1–4",  "desc": "HDMI 소스 4대 연결",              "x1": 640,  "x2": 1200 },
{ "n": 2, "label": "OUTPUT 1–4", "desc": "임의의 입력을 매트릭스로 전환해 출력", "x1": 1285, "x2": 1805 },
{ "n": 3, "label": "RS-232C",    "desc": "외부 제어",                       "x1": 270,  "x2": 390 }
```

**번호(`n`)는 그대로 1·2·3… 순차다.** 바뀌는 것은 **같은 종류 단자 여러 개를 범위 마커 하나로 묶고, 라벨에 `INPUT 1–4`처럼 묶음 이름과 범위를 적는 것**뿐이다.

| | |
|---|---|
| `validMarker` | **이미 범위 마커(`x1`·`x2`, `y1`·`y2`)를 받는다.** 그대로 쓴다 |
| 렌더러 | **변경 없음** |
| 선례 | NETGEAR가 이미 같은 방식이다 — `'PoE+ RJ-45 1–24'` (`tests/netgear-port-maps.test.mjs:25`) |

> **이것은 새 체계가 아니라, 알티컴·NETGEAR가 이미 쓰는 라벨 규약을 나머지 제품에 적용하는 것이다.**

## 라벨 규약

| 상황 | 라벨 | 예 |
|---|---|---|
| 입력 묶음 | `INPUT <범위>` | `INPUT 1–4` |
| 출력 묶음 | `OUTPUT <범위>` | `OUTPUT 1–4` |
| 종류가 중요한 묶음 | `<단자> <범위>` 또는 병기 | `OMNI OUT 1–8` · `INPUT 9–16 (콤보)` |
| 단독 단자 | 지금처럼 단자 이름 | `LAN` · `RS-232C` · `DC 12V` |

| | |
|---|---|
| 범위 구분자 | **`–`(en dash).** 알티컴·NETGEAR 표기와 같다 |
| `desc` | 묶음이 **무엇을 하는지** 한 문장. 알티컴처럼 쓴다 |
| 번호 순서 | **입력 묶음 → 출력 묶음 → 제어·네트워크 → 전원.** 사진 배치가 크게 다르면 사진 흐름을 따르고 보고한다 |

> **`io`에 없는 단자에 번호를 달지 마라.** 사진에 보이는데 `io`에 없으면 **번호 없이 보고만** 한다. 반대로 `io`에 있는데 사진에서 자리를 못 찾으면 그 행은 비우고 보고한다.
