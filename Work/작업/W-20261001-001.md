## 목표와 현재 상태

제조사 Product Detail JSON은 현재 240개다. 이 가운데 시범 5종에 RTCOM QMS-88UX 상세의 정보 구조를 적용하고, 나머지 235개도 기존 값만으로 깨지지 않게 표시할 공통 템플릿을 만든다. RTCOM의 코드나 디자인을 통째로 복제하지 않고, AV Portal의 밝은 공통 디자인과 기존 검색·상세 URL·검증 상태를 유지한 채 카드 순서와 정보 밀도만 같은 원칙으로 정리한다.

최신 main에는 RTCOM `rtcom.products.v1` 마지막 정상본과 참고 `rt-pg-*` 스타일이 이미 있다. 따라서 별도 상세 경로나 두 번째 렌더러를 만들지 않고, 현재 제조사 Product Detail 렌더러가 선택 필드를 해석하도록 확장한다.

검토한 접근은 다음과 같다.

1. **기존 렌더러의 점진적 확장 — 채택.** 선택 필드가 있으면 RTCOM형 01~07 카드를 표시하고, 없으면 기존 `overview`, `features`, `specifications`, `io`, `documents`, `sources`로 안전하게 축약 표시한다. 하나의 URL·렌더러·테스트를 유지할 수 있다.
2. RTCOM `products.js`를 제조사 상세에 그대로 복사 — 제외. RTCOM 그룹·시리즈 전용 분기와 문서 뷰어까지 중복되어 유지보수와 회귀 위험이 크다.
3. `detail-v2` 별도 경로 — 제외. 240개 상세의 공유·새로고침·검색 연결이 둘로 갈라지고 단계 2 이행 비용이 늘어난다.

## 구현 구조

### PR 1 — 공통 상세 템플릿

기존 제조사 상세 렌더러와 생성물 동기화 구조를 유지하면서 아래를 구현한다.

- `01 한눈에 보기`: `lead`를 최대 두 문장으로 표시한다. Markdown은 `**굵게**` 한 곳만 허용하고 나머지는 HTML 이스케이프한다. `keyFacts`가 2개 이상 있을 때 최대 4개를 2×2로 표시한다. 값은 크게, 단위는 작게 표시한다.
- `02 Port Map`: `portMap.image`와 일치하는 기존 제품 이미지를 사용한다. Front/Rear 전환은 기존 `images`에서 해당 역할이 실제 존재할 때만 제공한다. 번호 위치는 원본 픽셀 좌표 `x1`·`x2`를 이미지의 `naturalWidth`에 비례해 그린다. 유효한 Port Map이 없으면 현재 02 제품 사진 카드를 그대로 사용하여 정면·후면 전환과 확대를 보존한다. 기존 이미지도 없을 때만 종전 빈 상태 규칙을 따른다.
- `03 Signal Flow`: `signalFlow.type`에 따라 입력 → 처리 → 출력의 공통 SVG를 만든다. 허용 유형은 하단 2026-10-01 Signal Flow 확장 보완의 23개 유형이다. 배열에 적힌 문구만 렌더링하고 I/O 수나 기능을 추정하지 않는다. 유효한 signalFlow가 없으면 현재 03 연결 단자 카드(단자 카드 + 전체 단자 표)를 그대로 보여준다.
- `04 제품 사양`: 현재 사양 전체를 보존한다. 별도의 영문 대문자 그룹 소제목 줄을 만들지 않고 각 행의 분류 색 점으로 구분하는 밀도 높은 표를 사용한다. 색 점에는 접근 가능한 분류명도 제공한다. 각 행의 `source` 코드는 본문에서 반복하지 않고 하단 기록 영역에서 확인한다.
- `05 주요 기능`: 기존 `features` 전체를 보존하되 카드 안에서 읽기 쉬운 목록으로 표시한다.
- `06·07 설정 카드`: `settings`에 데이터가 있을 때만 순서대로 표시한다. `kind`는 `modes`, `edid`, `dip`, `table`만 허용한다. 각 종류는 제목과 데이터 배열만 렌더링하고 빈 설정은 카드와 번호를 만들지 않는다.
- 기존 문서, 연결 단자, 출처·검증 정보는 삭제하지 않는다. 01~07의 핵심 흐름 아래 기록·자료 영역으로 유지하고, 기존 `#specifications`, `#io`, `#documents`, `#sources` 직접 진입을 깨뜨리지 않는다.
- 선택 필드가 전혀 없는 제품도 오류 없이 기존 데이터로 01, 02 제품 사진, 03 연결 단자, 04, 05와 기록 영역을 구성한다. 빈 Port Map·Signal Flow 대신 기존 사진·연결 단자 카드를 유지하고, 빈 설정 카드는 만들지 않는다.
- 1280px와 390px에서 가로 넘침이 없어야 하며 키보드 포커스, 이미지 대체 텍스트, reduced motion을 유지한다.

PR 1에서는 시범 5종의 선택 데이터 값을 넣지 않는다. 렌더러·스타일·검증·테스트와 필요한 생성물만 변경한다.

### PR 2 — 시범 5종 데이터

PR 1이 main에 병합된 뒤 최신 main에서 시작한다. 다음 파일에 선택 필드만 추가한다.

- `beta/site/detail/data/novastar-h5.json`
- `beta/site/detail/data/ulxd4d.json`
- `beta/site/detail/data/dci-4-600da.json`
- `beta/site/detail/data/eb-pq2220b.json`
- `beta/site/detail/data/aquilon-rs1.json`

기존 값은 수정·삭제하지 않는다. 단, 새 선택 필드와 기존 값 사이의 명백한 충돌이 발견되면 새 필드를 비우고 검토 기록에 남긴다. 공개 이미지·PDF는 이미 저장소에 있는 정확 모델 자료만 사용하고 새 웹 조사를 하지 않는다.

추가 가능한 필드는 다음과 같다.

```text
lead: string                         # 두 문장, **굵게** 한 곳까지
subtitle: string
keyFacts: [{ label, value, unit }]   # 최대 4개
portMap: {
  image: 'Front' | 'Rear',
  items: [{ n, label, desc, x1, x2, side? }]
}
signalFlow: {
  type,
  inputs: [string],
  outputs: [string],
  notes: [string]
}
settings: [{
  kind: 'edid' | 'dip' | 'modes' | 'table',
  title: string,
  columns?: [string],
  rows?: [[string]],
  items?: [{ name, summary, detail? }]
}]
```

`portMap` 좌표는 기존 원본 이미지의 실제 픽셀을 열어 측정하고, 이미지 해상도와 측정 방법을 검증 기록에 남긴다. 좌표나 역할을 추정하지 않는다. 근거가 없는 `lead`, 핵심 수치, 흐름 단계, 설정값은 비워 둔다.

각 선택 필드의 근거는 기존 `sources`의 코드와 PDF 쪽 번호로 `Work/기록/W-20261001-001-근거대조.md`에 제품별로 기록한다. 필요하면 `sources` 항목에 기존 값을 바꾸지 않는 범위에서 `page`만 추가할 수 있다. 화면의 하단 기록 영역에서도 같은 출처 코드와 쪽을 확인할 수 있어야 한다.

### 구조와 의미

공통 renderer는 제품 ID를 읽어 분기하지 않는다. 입력/출력, 처리 블록, 명시적 연결, 보조 경로를 각각 그린다. `type`은 제품군 분류이고 `processes[].kind`는 실제 확인된 처리 동작이다. 타입만으로 처리 단계나 연결을 자동 생성하지 않는다. 카메라/마이크/스피커의 입력·출력은 빛·음향 등도 가능하며 물리 포트 수를 뜻하지 않는다.

유형: matrix, switcher, distribution, extender, converter, video-processor, processor-card, recorder, camera, camera-controller, amplifier-channel, audio-dsp, mixer, audio-interface, network-bridge, wireless-microphone, rf-distribution, loudspeaker, microphone, conferencing, network-switch, control, power.

`projector-display-input`은 제거한다. 디스플레이 38종은 선택 flow가 잘못 입력되어도 03 연결 단자로 fallback한다. 액세서리·케이블 3종은 승인 대기 후보이며 제외하지 않는다. 현재 202종 대응표는 [자료현황](../기록/W-20261001-001-Signal-Flow-자료현황.md)에 있다.

### 임시 UI 선택 필드 (최종 제품 Schema 아님)

- `type`: 위 23개 값 중 하나.
- `description`: 그림 대체 설명, 필수. `notes`: 확인된 조건/설명 배열.
- `inputs`, `outputs`: `[{id,label,signal,group?,caption?,tag?,evidence}]`. 수량에서 자동으로 노드를 만들지 않는다. tag는 매트릭스 축의 근거 있는 짧은 표기(최대 8자)이며 없으면 임의 번호를 만들지 않는다.
- `processes`: `[{id,kind,label,caption?,crosspoints?,evidence}]`. kind는 matrix/select/split/convert/scale/encode/decode/record/capture/sense/control/amplify/dsp/mix/bridge/rf/transduce/conference/switch/power/module. 여러 일반 처리 단계는 배열 순서대로 명시적으로 연결한다. 역순/순환 연결은 거부하며 양방향 경로는 앞 단계에서 뒤 단계로 기록하고 direction: both로 표현한다. matrix는 중앙 격자를 단독으로 사용하는 1개 처리 블록만 지원한다. 복합 matrix/다른 블록과의 혼합은 잘못 겹쳐 그리는 대신 fallback한다.
- `connections`: 주 신호 `[{from,to,signal,label?,direction?,evidence}]`.
- `auxiliary`: 같은 구조의 보조 신호. 항상 점선. 긴 경로 label은 그림 아래의 경로별 설명 목록에서 줄바꿈하여 보존하고 그림/문구가 겹치지 않게 한다. `direction`은 forward(기본) 또는 both. 화살표로 방향을 표시한다. 오디오 추출·멀티뷰·제어·급전·네트워크 오디오 중 근거 있는 경로만 넣는다.
- `groups`: `[{id,label,caption?,evidence}]`. 출력 그룹 이름·적용 설명을 보존한다.
- `band`: 선택 `{label,detail?,evidence}`. 기술값을 알아서 만들지 않는다.
- `legend`: `[{signal,label}]`. 입력 파랑, 출력 보라, 보조 경로 점선; 색상 외 텍스트/화살표도 사용한다.
- signal: video/audio/network/control/rf/power/usb/optical/acoustic.
- matrix 처리만 `crosspoints:{inputs:[입력 id],outputs:[출력 id],examples:[{input,output}]}`를 갖는다. 예시 점은 항상 **선택 예시**로 표시하고 현재 라우팅이나 기본 설정으로 주장하지 않는다.

### 근거·검증 규칙

각 입력·출력·처리·그룹 캡션·경로·대역에 evidence를 반드시 붙인다. 허용 참조:

- `{kind:'io',index:0}` — 이 제품 io 배열의 0부터 시작하는 행 번호.
- `{kind:'spec',index:0}` — 이 제품 specifications 배열의 0부터 시작하는 행 번호.
- 위 두 참조는 실제 행이 있고 verification이 VERIFIED 또는 FOUND인 경우만 허용한다. REVIEW REQUIRED/CONFLICTED/PARTIAL/MISSING 값으로 확정 그림을 만들지 않는다.
- `{kind:'pdf',source:'M',file:'docs/example.pdf',page:12}` — 이 제품 sources의 코드와 저장소 beta/site 아래 PDF 사본 및 실제 인쇄/뷰어 페이지 번호를 기록한다. manuals/ 하위 공개 사본도 허용한다. 자료 입력자가 페이지 체계와 모델 적용을 대조해야 한다.
- 페이지 번호는 양의 정수, 경로는 docs 또는 manuals의 단일 PDF 파일명이다. Pages 검사는 파일 존재·PDF 서명을 확인한다. **기계 검사는 해당 페이지 내용이 문구를 뒷받침하는지까지 판단하지 못한다.** 데이터 PR에서 PDF 쪽/모델·변형을 사람이 대조한다.
- 존재하지 않는 ID/근거, 중복 ID, 자기 연결, 잘못된 방향/신호/유형, 고립 노드, matrix 축과 입력/출력·주 연결 불일치, 중복 선택 출력은 거부한다. 허용하지 않은 필드도 거부한다.
- 노드 입력/출력 각 1–32, 처리 1–6, 주 연결 1–96, 보조 0–32, 그룹 0–16, matrix 축 각 1–16, 예시 점 0–16, 범례 0–9, notes 0–12. 문구는 160자/보조 캡션 240자 이내. 초과는 잘라 그리지 않고 fallback한다.
- 실데이터가 없거나 검증 실패면 기존 03 연결 단자 카드·전체 표를 보존한다. 기존 240개 JSON에는 Signal Flow가 없으므로 화면을 바꾸지 않는다.
