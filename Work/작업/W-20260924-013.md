## 목표와 현재 상태

현재 스펙은 모든 그룹이 접혀 있어 스펙 탭에 들어와도 값이 보이지 않는다. 그룹을 처음부터 펼쳐 사양을 바로 읽게 하고, 넓은 화면에서는 항목명·값을 가까운 두 열로, 좁은 화면에서는 위아래 순서로 정돈한다. 그룹은 필요하면 접을 수 있게 유지한다.

## 범위

- 공통 상세 렌더러의 Specifications 렌더링과 해당 CSS만 변경한다. `prototype/brc-am7/` 원본과 `beta/site/detail/` 공개본을 함께 갱신한다.
- 기존 제품별 데이터에 있는 그룹 이름·순서·값·단위·조건·출처·검증 상태는 그대로 표시한다. VERIFIED는 보조 정보로, REVIEW REQUIRED/CONFLICTED는 구분 가능한 상태로 유지한다.
- 첫 화면에서 각 그룹의 값이 보이도록 하되 사용자가 그룹을 다시 접을 수 있다. 불필요한 카드 간격을 줄이고 각 행의 값 우선순위를 높인다.
- 이미지·문서·특징·I/O·Sources·Library, 제품 JSON 5개, 공개 범위·권한 정책은 변경하지 않는다. W-011 DRAFT의 Library/URL/데이터 계약 재설계는 제외한다.

## 완료 조건

- [ ] 공개 상세 5개에서 스펙 그룹이 초기부터 펼쳐지고, 각 항목명·값·단위·조건·출처·검증 상태가 보존된다.
- [ ] 그룹을 클릭하거나 키보드로 접고 다시 펼칠 수 있다.
- [ ] 390px와 1440px에서 스펙을 읽을 수 있고 가로 넘침이 없다. 값이 화면 끝에 불필요하게 멀리 떨어지지 않는다.
- [ ] 스펙 27/16/16/13/16개 및 Features·I/O 수량이 유지된다. REVIEW REQUIRED/CONFLICTED를 VERIFIED처럼 표시하지 않는다.
- [ ] `node beta/verify-pages.mjs`, `npm test`, 실제 브라우저 확인을 수행한다.

## 검증 방법

루트에서 위 두 명령을 실행한다. 전체 `beta/site`를 제공하는 로컬 정적 서버에서 BRC-AM7과 다른 4개 상세를 1440px·390px로 확인한다. 그룹 첫 표시·접기/열기·수량·검증 상태·가로 넘침을 확인한다. 공개 제품 데이터·Library 파일과 공개 바이너리 변경 여부를 Git diff 및 공개 검증 명령으로 확인한다.
