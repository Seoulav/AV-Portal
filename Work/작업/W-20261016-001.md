## 1) TOGGLE DOCK 2×1 — 호스트 전환 도크 (io 9행 근거)

공식 사이트 사실(W-20261014-008 근거표)과 기존 io를 그대로 그린다:
- **호스트 1(PC 1)**: USB-C 1개(USB 3.0 + DP Alt Mode + **100W PD 전원 공급**) — 케이블 하나로 영상·USB·노트북 충전
- **호스트 2(PC 2)**: **USB-B 3.0(USB 호스트) + HDMI 2.0 입력** — 영상과 USB가 별도 케이블
- **공유 주변기기**: USB 3.0 Type-A 3개(전환된 호스트에 연결), 전력 1.8A 공유
- **출력**: HDMI 2.0 1개 — 선택된 호스트의 영상을 디스플레이로(4K60, 5Kp30 21:9)
- **제어**: RS-232·LAN/IP·GPI(접점 2개)·버튼 키트(옵션) — 보조 경로로 표시
- **전원 입력**: DC 24V(io[8]) — 호스트 1의 USB-C PD 전원 공급과 별개이므로 혼동하지 않게 표기
- 그림 구성 제안: ① 호스트 1(노트북, USB-C 한 줄) ② 호스트 2(노트북, USB-B+HDMI 두 줄) → **TOGGLE DOCK 2×1(자동/수동 전환)** → ③ HDMI 출력(TV/모니터) + USB 주변기기 3(키보드·마우스·웹캠 등은 **예시**) + 제어(점선). **선택된 호스트 한 쪽만 활성**임을 표시(전환 개념: 활성 경로 실선, 비활성 경로 흐린 선 또는 시나리오 탭으로 "호스트 1 선택 / 호스트 2 선택").

## 2) U-BRIDGE 3 — 랜 케이블 USB 3.0 확장기 (io 7행 근거)

- **PC HOST 측 유닛**: 호스트 PC USB-C(io[0], 잠금 나사 구멍) ↔ **CAT6A U/FTP 1가닥(최대 100m, USB 3.2 Gen 1 연장 링크 RJ-45)** ↔ **DEVICE 측 유닛**: USB-A 2 + USB-C 1(주변기기, io[1][2], 1.8A를 DEVICE 포트 간 공유)
- **RS-232 패스스루**(io[4], VISCA 등 카메라 제어 — PC HOST ↔ DEVICE 양쪽 4핀 단자대)와 **모듈 관리 USB-mini**(io[5])는 보조 경로
- **전원**: DC 24V(io[6]) — **PC HOST 또는 DEVICE 한쪽에서 공급, PoC로 CAT6A를 통해 반대쪽 유닛에 전달**(공식 페이지 사실). 전원 경로를 별도 색으로.
- 그림 구성 제안: 노트북/PC → [PC HOST 유닛] ══CAT6A 100m══ [DEVICE 유닛] → 회의실 USB 카메라 등(예: 화상회의 카메라, 마이크 — **페이지 호환 목록 브랜드 중 일반 예시만, 모델 창작 금지**). 시나리오 탭으로 "전원: DEVICE 쪽 공급 / PC HOST 쪽 공급" 두 경우 가능.

## 포털 구현 방식

HDF-CCF와 동일하게 제품 JSON `signalFlow`(`validFlow`·`flowTypes`) — 의미상 맞는 type 선택(TOGGLE DOCK은 `switcher`, U-BRIDGE는 `extender` 계열, 기존 렌더러가 지원하는 범위). `evidence`는 io 행 인덱스(위 표기)를 가리킨다. **새 flow type·렌더러 변경은 최소로**, HDF-CCF가 쓰는 scenarios 렌더를 재사용하고 부족하면 보고. 다른 제품 화면 불변을 증명한다.
