## 목표와 기준

제품 상세의 문서를 알티컴 제품정보 사이트(https://seoulav.github.io/rtcom-configurator/)처럼 **화면 안 PDF.js 팝업으로 보고, 바로 내려받을 수 있게** 한다. 제조사 사이트의 PDF는 대부분 다른 사이트에서 화면 안 읽기를 막으므로(2026-09-29 조사: PDF 101개 중 34개만 허용), PDF 사본을 AV Portal에 두고 같은 주소에서 연다.

[사용자 승인 보정 명세](W-20260929-001-보정명세.md) 7장이 이 작업의 결정 기준이다. 2단계에서 만든 `07 문서` 카드와 머리 문서 버튼에 붙인다.

## 범위

1. **사본 수집 스크립트** `beta/mirror-docs.mjs`(권고 경로)
   - 상세 JSON의 `documents` 중 FOUND·VERIFIED·READY이고 `url`이 있는 항목을 받는다. 응답이 PDF(`Content-Type` 또는 파일 앞 5바이트 `%PDF-`)일 때만 저장한다.
   - 저장 위치: `beta/site/docs/`(권고). 파일명은 `<slug>-<문서종류>[-n].pdf` 규칙(영문 소문자·숫자·하이픈)으로 정한다. 같은 URL은 한 파일만 두고 여러 제품이 함께 쓴다.
   - 대응표 `beta/mirrored-docs.mjs`(권고)에 `{ url, file, sha256, bytes, fetchedAt, sourceHost }`를 기록한다. **상세 JSON과 `catalog.json`은 고치지 않는다.** 화면은 대응표로 원본 URL을 사본 주소로 바꿔 연다.
   - 크기 기준: 파일 1개 50MB 초과는 저장하지 않고 원본 링크로 남기며 보고한다(GitHub 경고 기준). 사본 전체가 Pages 사이트 1GB 한도를 넘지 않도록 현재 `beta/site` 용량과 합산해 보고한다.
   - 다시 실행할 때: SHA가 같으면 그대로 두고, 달라졌으면 교체하고, 받기에 실패하면 **이전 사본을 유지**한다. 원본에서 사라진 문서의 사본은 삭제하지 않고 보고한다.
   - 기존 `beta/user-manuals.mjs`·`beta/site/manuals/` 구조(파일명 규칙, `%PDF-` 확인, 목록과 폴더 일치 검사)를 재사용하거나 같은 방식으로 맞춘다.
2. **PDF.js 뷰어**
   - PDF.js는 RTCOM 저장소의 `src/vendor/pdfjs/`(`pdf.min.mjs`, `pdf.worker.min.mjs`, `LICENSE`, Apache 2.0)와 같은 판을 `beta/site/vendor/pdfjs/`(권고)에 넣는다. 외부 CDN에서 불러오지 않는다.
   - 동작은 RTCOM 0.124~0.126과 같게 한다: 버튼을 누르면 화면 안 팝업, **보이는 쪽만** 그림, PC 기본 폭 1040px, 좌우 가장자리 끌어서 폭 조절(이 브라우저에 기억, 두 번 누르면 기본 폭), "넓게" 버튼으로 화면 폭까지, 폭이 바뀌면 쪽을 다시 맞춤. 휴대폰은 전체 화면. `Esc`·닫기 버튼·팝업 바깥 누르기로 닫고, 닫으면 원래 버튼으로 초점을 돌린다.
   - 팝업 머리: 문서 제목, 쪽 이동, 확대·축소, **내려받기**, **원문 링크 ↗**(제조사 원본 URL).
3. **버튼 규칙**(2단계 `07 문서` 카드·머리 문서 버튼)
   - 사본이 있는 PDF: `보기`(팝업) + `↓ 내려받기`(같은 주소라 `download` 속성으로 바로 저장)
   - 사본이 없는 문서(웹페이지·오류·50MB 초과): `제조사에서 열기 ↗`(새 탭). 지금처럼 동작한다.
   - MISSING 문서는 버튼을 만들지 않는다(보정 명세 2장 5번 유지).
4. **검사**: `beta/verify-pages.mjs`의 배포 폴더 허용 목록에 `docs/`·`vendor/`를 추가하고, 대응표와 폴더 일치·`%PDF-`·파일명 규칙·파일 크기 상한을 검사한다. 필요한 테스트를 추가한다.

- 현재 이 PR에서는 문서만 반영한다. 위 경로는 승인 후 구현 예정 범위다.
- 제외: 다른 단계 구현, 상세 JSON·`catalog.json` 값 변경, 웹페이지형 문서를 PDF로 바꾸기, 내부 자료 공개.
- 후속 단계 착수는 자동 승인되지 않는다.

## 미결 사항·의존성

- 2단계 `07 문서` 카드 구조에 의존한다. 3단계(홈)와는 독립이며, 기본 순서는 2단계 → 이 작업 → 3단계로 한다. 순서를 바꾸려면 사용자에게 묻는다.
- 사본 약 460MB가 저장소와 Pages 배포에 더해진다. 문서가 바뀔 때마다 새 사본이 Git 기록에 쌓인다. 저장소가 1GB에 가까워지면 Git LFS나 별도 저장소 분리를 사용자에게 제안한다(이번 범위에서 도입하지 않음).
- 사본 저장 시 [자료 게시 운영 정책](../기획/자료게시운영정책-2026-09-29.md)의 기록 조건(원본 URL·받은 날짜·SHA-256, 원문 링크 표시)을 따른다.
