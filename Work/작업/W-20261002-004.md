## 문제

DM7의 Port Map 번호가 **63개**다. 그중 48개가 설명까지 완전히 같다.

- `아날로그 입력` 32개 — 전부 `밸런스 XLR · 마이크 또는 라인 레벨 소스를 연결합니다.`
- `OMNI OUT` 16개 — 전부 `밸런스 XLR · 아날로그 오디오를 출력합니다.`

번호가 사진을 덮어 단자가 보이지 않고, 아래 설명 목록은 같은 문장을 48번 반복한다. 정보가 아니라 소음이다.

원인은 Work의 규칙이다. [W-20261002-001 명세](W-20261002-001.md)에 "분리된 A/B·채널별 단자는 별도 번호를 받는다"고 적었는데, 이는 2채널 수신기 기준이었고 **상한을 두지 않아** 120채널 콘솔에서 그대로 폭발했다. Crown 1차는 "한 설명은 채널 쌍 등을 묶을 수 있다"로 이미 묶고 있었으므로 규칙이 서로 어긋나 있었다.

## 대상 — 43종 중 3종

전체 43종의 평균 번호 수는 10.6개로 문제가 없다. **같은 `label`·`desc`가 5회 이상 반복되는 제품은 3종뿐**이다.

| 차수 | 제조사 | slug | 현재 | 목표 | 묶을 대상 |
|---:|---|---|---:|---:|---|
| **1차** | Yamaha | `dm7` | 63 | **17** | 아날로그 입력 ×32, OMNI OUT ×16 |
| 2차 | Lumantek | `vs10` | 26 | 12 | SDI 입력 ×8 |

**이 명세는 1차 Yamaha만 착수를 승인한다.** 2·3차는 1차 결과를 사용자가 확인한 뒤 각각 지시를 받는다. 나머지 40종은 건드리지 않는다.

## 묶는 방법

같은 커넥터가 줄지어 있으면 **번호 하나가 그 줄 전체를 덮는다.**

```text
이전:  { n: 1,  label: "아날로그 입력 1",  x1: 850, x2: 880 }
       { n: 2,  label: "아날로그 입력 2",  x1: 885, x2: 915 }
       ... 32개
이후:  { n: 1,  label: "아날로그 입력 1–32", desc: "밸런스 XLR 32개 · 마이크 또는 라인 레벨 소스를 연결합니다.",
         x1: <첫 단자 왼쪽 끝>, x2: <마지막 단자 오른쪽 끝> }
```

`portMap.items`는 이미 `x1`~`x2` 가로 범위를 지원하므로 **렌더러·스타일 코드를 고치지 않는다.** 데이터만 바꾼다.

- 묶음 `label`에 범위를 표기한다(`1–32`). 수량은 `desc` 앞부분에 적는다(`밸런스 XLR 32개 · …`).
- 수량은 **사진에서 세지 않고** 기존 근거(PDF 쪽 또는 기존 `io` 수량)로 확인한 값만 쓴다. 확인되지 않으면 범위 표기 없이 묶기만 한다.
- 물리적으로 떨어져 있는 블록은 **블록마다 따로 묶는다.** 한 번호가 사진의 빈 구간을 가로지르지 않게 한다.
- 번호를 다시 1부터 연속으로 매긴다. 순서는 기존대로 입력 → 출력 → 네트워크/제어 → 전원.
- 묶이지 않는 단자(AES/EBU, 워드 클록, Dante, GPI, 전원 등)는 **그대로 둔다.**
