## 왜 묶음인가

48포트 스위치에 **똑같이 생긴 RJ45가 40개**다. 번호를 40개 달면 화면에서 안 읽히고, 읽어도 쓸모가 없다. **"1번 RJ45, 2번 RJ45…"는 정보가 아니다.**

```
전      1 RJ45 · 2 RJ45 · … · 40 RJ45 · 41 SFP+ · … · 48 SFP+
후      1 RJ-45 1–40 (PoE+)      2 SFP+ 41–48      3 콘솔
```

## ★★ 규칙을 고쳤다 — `io` 행 수가 번호 수가 아니다

Work의 초안은 **"번호 하나 = `io` 행 하나"**였다. **틀렸다.** 리뷰 담당이 짚었고 Work가 확인했다.

### 콘솔이 한 행에 둘이 들어 있다

| 제품 | `io` 행 | 뜻 |
|---|---|---|
| `gsm4230p` · `gsm4248p` · `xsm4216f` | **한 행**: `USB Type-C / RJ45-DB9` · 수량 `1` · 조건 **`구성품에 콘솔 케이블 2종 포함`** | **단자가 하나인가 둘인가?** |
| `gsm4212p` | **두 행**: `RJ-45`(RS232 Console) · `USB Type-C`(Console) | **둘이다** |

**같은 M4250 계열인데 한쪽은 두 행, 한쪽은 한 행**이다. `gsm4212p`가 둘로 쪼개 적은 것을 보면 나머지 셋도 **물리 단자는 둘일 가능성이 높다.**

초안 규칙대로 하면 **단자 둘에 괄호 하나**를 치게 된다.

### 고친 규칙 — 다만 "여러 단자 = 여러 번호"는 아니다

**초안의 고침도 다시 고쳤다.** 리뷰 담당이 짚었다.

> *"한 행에 단자가 여러 개면 번호도 여러 개"는 **RJ45 40개에도 적용된다.**"*

**그러면 묶으라는 사용자 지시와 정면으로 부딪친다.** 묶음을 하자면서 40개를 달게 된다.

#### 가르는 기준은 "같은 것이 줄지어 있나"다

| 경우 | 번호 |
|---|---|
| **같은 종류·기능·조건**이 **한 구역에 줄지어** 있다 (`RJ-45 ×40`) | **하나로 묶는다** |
| **종류나 기능이 다른 것**이 한 행에 묶여 있다 (`USB Type-C / RJ45-DB9` 콘솔) | **사진에 둘로 보이면 둘** |
| 같은 종류라도 **떨어진 구역**에 나뉘어 있다 | **구역마다 하나** |
| 사진에서 **가려져 몇 개인지 모른다** | **보류하고 보고한다.** 추측하지 않는다 |

> **묶음이 기본이다. 쪼개는 것은 종류·기능·조건이 다르거나(PoE와 비PoE처럼) 구역이 떨어졌을 때뿐이다.**

### ★★ 지도 하나는 한 면만 덮는다 — 다 담을 수 없다

**리뷰 담당이 Work의 완료 조건 두 개가 서로 모순임을 찾았다.** Work가 9종을 전부 훑어 확인했다.

`condition`에 **배치가 적혀 있다.** 면별로 세면 이렇다.

| 제품 | 전면 | 후면 | **배치 미기재** |
|---|---:|---:|---:|
| `gs728tppv3` | **3** | **2** | 0 |
| `gsm4212p` | **2** | **7** | 0 |
| `gs108pp` · `gs116pp` | 0 | 0 | **1** |
| `gsm4230p` · `gsm4230px` | 0 | 0 | **4** |
| `gsm4248p` | 0 | 0 | **3** |
| `gsm4248px` · `xsm4216f` | 0 | 0 | **2** |

**`portMap`은 그림 하나만 받는다.** 두 면에 걸친 제품은 **한 면밖에 못 덮는다.**

#### `gs728tppv3` — 초안이 모순이었다

| | |
|---|---|
| 전면 | `RJ-45 ×24` · `SFP ×4` · `USB ×1` |
| 후면 | `고객 사용 불가 ×1` · `AC 전원 ×1` |

Work는 **"포트면(전면)을 쓰라"**고 적어 놓고 동시에 **"`고객 사용 불가` 단자에 번호를 달라"**고 적었다. **그 단자는 후면에 있다. 둘 다 할 수 없다.**

**전면을 쓰고 `io` 3행에 번호를 단다.** 후면 2행은 **값을 그대로 두고 번호를 달지 않으며, 보고한다.**

#### `gsm4212p` — Work의 다른 주장도 틀렸다

초안에 **"지금 16개가 `io` 9행 중 7행만 덮어서 `USB Type-A`와 `USB Type-C(용도 미상)`에 번호가 없다"**고 적었다.

**그 둘은 전면 단자다.** 후면 지도가 안 덮는 것이 **맞다.** 빠진 것이 아니다.

```
전면 2행 — USB Type-A · USB Type-C(LED EXT)
후면 7행 — RJ-45 ×8 · ×2 · SFP ×2 · OOB · 콘솔 2 · IEC C14
```

**후면 지도는 7행을 덮는다. 전면 2행은 번호를 달지 않는다.**

#### 나머지 7종은 배치가 아예 안 적혀 있다

**`io`에 전면인지 후면인지 기록이 없다.** 사진을 보고 판단해야 한다.

- **판단한 면을 보고하라.** `io`에 적어 넣지 마라 — 이번 범위가 아니다
- 포트가 **양면에 걸쳐 있으면** 어느 쪽을 골랐는지와 **덮지 못한 행**을 적어라

### 규칙

> **지도는 한 면이다. 그 면의 `io` 행에만 번호를 단다.**
> **다른 면의 행은 값을 보존하고 번호 없이 두며, 제품별로 보고한다.**

## ★ "후면"이 아니라 "포트가 있는 면"이다

Work가 지시를 잘못 내렸다가 바로잡은 자리다. **기존 데이터에서 "후면"의 뜻이 제품마다 다르다.**

| 제품 | **지금 `Rear` 지도에 찍힌 번호** |
|---|---|
| `gsm4212p` | **16개** — RJ45 12 · SFP · 콘솔 · 전원 |
| `gs728tppv3` | **1개** — `AC 전원 입력`뿐 |

**사진에 무엇이 있는지가 아니라 지금 번호가 몇 개 찍혀 있는지**다. 후면 패널에 다른 것이 더 있을 수 있다.

Work가 `GS116PP`의 "후면" 사진을 받아 보니 **켄싱턴 락 · 통풍구 · DC 전원 잭뿐이고 RJ45가 하나도 없었다.**

**포트가 늘어서 있는 면을 쓴다. 앞이든 뒤든 상관없다.**

### ★ 이미지 역할을 제대로 적어야 지도가 산다

`validMap`은 `image`를 **`Front`·`Rear`·`Diagram`만** 받는다(`detail-enhancements.mjs:26`).

**6종이 지금 `Main`밖에 없다.** 사진을 받아 `Main`으로 등록하면 **지도가 통째로 탈락한다.** 조용히 안 나온다.

사진마다 **역할 · `resolution` · `measuredImage`(`file`·`width`·`height`)**를 정확히 채운다. `portMapImageMatches`가 셋을 다 본다.

## 기존 2종도 묶음으로 바꾼다

사용자가 정한 것은 **NETGEAR 전체 규칙**이다.

### `gsm4212p` — 16개에서 줄인다. 면은 그대로 후면

후면 7행을 덮는다. 지금 16개는 **포트를 하나씩** 단 것이라 `RJ-45 1–8` · `RJ-45 9–10` · `SFP 11–12`로 묶으면 **12개가 3개**가 된다.

**몇 개가 될지는 사진을 보고 정한다.** 콘솔 2행이 후면에 **몇 개로 보이는지**에 달렸다.

**전면 2행(`USB Type-A` · `LED EXT`)은 번호를 달지 않는다.** 빠뜨리는 것이 아니라 **다른 면**이다.

### `gs728tppv3` — `Rear` 1개에서 **전면**으로

| | |
|---|---|
| 전면 | `RJ-45 ×24` · `SFP ×4` · `USB ×1` — **번호를 단다** |
| 후면 | `고객 사용 불가 ×1` · `AC 전원 ×1` — **번호 없음. 값은 보존** |

`Front`·`Rear` 이미지가 둘 다 있으니 **새로 받을 것이 없다.**

**덮는 행이 1개에서 3개로 늘고, 후면 2행은 지도에서 빠진다.** 손익이 분명하니 **전후를 나란히 보여 사용자가 판단하게 하라.**

### 보이는 것이 바뀐다

**두 제품은 전후 캡처를 나란히 내라.**

## 미결 사항

- **`gsm4248px`의 `io` 2행**이 형제 제품보다 적다. **기록 공백이지 단자가 없는 것이 아니다.** 이번에 채우지 않는다.
### ★ 사진 좌표 — Work가 틀리게 알고 있었다

Work는 **"사진 포트맵 51종에 사람 눈 말고는 지키는 장치가 없다"**고 말해 왔다. **틀렸다.** 리뷰 담당이 바로잡았고 Work가 코드를 확인했다.

```js
// tests/port-map-height.test.mjs:45
test('all 51 earlier Port Maps retain their exact pre-change geometry', …)
assert.equal(sha(JSON.stringify(geometry)), expected.geometrySha256, `${slug} full geometry`);
```

**51종 전체의 배치 해시가 고정돼 있다.** `tests/bss-port-map-alignment.test.mjs`도 단자 경계와 사진 해시를 본다. 관련 검사 **14개가 통과**한다.

**있는 것과 없는 것을 가려 적으면 이렇다.**

| | |
|---|---|
| **있다** | **값이 바뀌는 것을 막는 장치.** 누가 좌표를 건드리면 검사가 깨진다 |
| **없다** | **처음 값이 맞는지 보는 장치.** 틀린 채로 들어오면 그대로 고정된다 |

**QMC 사고가 정확히 두 번째였다.** 처음부터 틀렸고, 해시 검사는 **틀린 값을 충실히 지켜 줬다.**

### 어떻게 메울지는 별도로 다룬다

리뷰 담당이 안을 냈다.

| 단계 | |
|---|---|
| 기준 확인 | 번호 없는 사진과 제조사 자료로 **단자 영역을 따로** 검토 |
| 사진 고정 | 사진 SHA · 실제 크기 · 전후면 · 크롭 기록 |
| 좌표 검사 | 괄호의 **가로·세로 양축**과 번호·단자 대응 비교 |
| 화면 검사 | PC·모바일 승인 화면과 차이 비교 (Playwright) |
| **검사 검증** | **좌표 이동·번호 교환·사진 교체를 일부러 넣어** 검사가 실패하는지 |

**핵심 경고도 그대로 옮긴다.**

> **기존 좌표를 그대로 복사해 "정답"으로 등록하면 최초 오류도 그대로 고정된다.**

**이번 W-026에 끼워 넣지 않는다.** 별도 작업으로 다룬다. 끼워 넣으면 범위가 두 배가 되고, 급한 것은 NETGEAR 지도다.
- `gs108pp` · `gs116pp`는 **번호가 적어** 지도의 값이 낮을 수 있다. 결과를 보고 사용자가 정해도 된다.
- **콘솔 복합 행**(`USB Type-C / RJ45-DB9`)이 실제로 몇 개인지 확인되면, `io`를 쪼갤지는 **별도 판단**이다. 이번에는 `io`를 건드리지 않는다.

## Codex 인계

최신 `origin/main`에서 브랜치를 만든다.

**번호 수는 사진이 정한다. `io` 행 수를 믿고 넘기지 마라. 이미지 역할이 `Main`이면 지도가 조용히 사라진다. 회귀 검사 두 곳의 기대값을 함께 고친다.**
