- 담당 세션: D
- **배경**: 예약 동기화(매일 1회, `.github/workflows/sync-rtcom.yml`)가 2026-10-16 실행에서 실패했다. 원인: RTCOM 원본에 새 제품 `xdm-mr4s`(XDM-MR4S)가 추가됐는데 동기화 자체 시험의 기대 목록(스냅샷 대조표)에 없어 deepStrictEqual이 실패. 실제 수신 데이터는 accepted: true(사진·검증 통과)였다.
- 승인 근거: RTCOM 공개 제품정보는 단일 원본(index.json)을 그대로 수신하는 기존 승인 범위(AGENTS.md). 신규 제품 수신은 동기화 정책 그대로이며, 이 작업은 대조표 갱신과 수신 확인만 한다.

## 할 일

1. 실패한 시험(기대 목록에 `rtcom-xdm-mr4s` 누락)을 찾아 기대 목록에 추가한다. 값은 실제 수신 결과(accepted: true, errors: [], crop: false)와 일치시킨다.
2. 로컬에서 `node beta/sync-rtcom.mjs` 실행 → 새 제품 수신 확인 → `node beta/build-search-index.mjs`·`node beta/build-readable-catalog.mjs` 재생성 → `node beta/sync-rtcom.mjs --check`·검색 인덱스 `--check`·`node beta/verify-pages.mjs` 통과.
3. 수신된 XDM-MR4S의 포털 화면(상세 유무·카드)을 확인해 PR에 기록한다. 데이터 내용은 원본 그대로 두고 수정하지 않는다.
4. PR 병합 후 `gh workflow run sync-rtcom.yml`로 예약 작업을 수동 1회 실행해 초록 확인.

## 하면 안 되는 것

- RTCOM 원본 데이터 수정, 다른 제품 JSON 변경, 동기화 검증 로직 약화(기대 목록 갱신만).
