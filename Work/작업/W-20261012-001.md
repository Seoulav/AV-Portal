## 목표

Port Map이 있는 **74종 673개 표식 전부**에 대해 다음을 확인하고, 틀린 것을 고친다.

1. **가리키기** — 괄호선 높이(`y`, 좌우 변은 `x`)가 실제 단자 몸체 위에 있는가
2. **덮는 범위** — `x1`~`x2`(좌우 변은 `y1`~`y2`)가 라벨이 말하는 단자(묶음이면 묶음 전체)를 **빠짐없이, 남는 것 없이** 덮는가
3. **정체** — 덮은 단자가 라벨·`desc`가 말하는 종류·개수와 같은가 (패널 인쇄 글자가 보이면 대조)

그리고 이 절차를 **`portmap-audit` 스킬**로 남겨 새 Port Map이 생길 때마다 같은 방법으로 돌린다.

## 판정 기준

| 판정 | 뜻 | 처리 |
|---|---|---|
| **OK** | 높이가 단자 몸체 위, 구간이 단자 테두리와 맞음 | 그대로 |
| **좌표 수정** | 정체는 맞는데 구간이 이웃 단자까지 덮거나, 단자 일부를 놓치거나, 높이가 단자를 벗어남 | 고친 값과 근거를 점검표에 적고 수정 |
| **확인 요청** | 덮은 단자의 종류·개수가 라벨과 다름, 사진에 해당 단자가 안 보임 | 고치지 않고 사용자 확인 |
| **판정 불가** | 사진 해상도·각도로 단자 경계를 못 읽음 | 사유 기록 |

허용 오차(스킬에 고정): 구간 끝이 단자 테두리에서 **단자 폭의 15% 또는 이웃 단자와의 간격의 절반 중 작은 값** 안이면 OK. 촘촘한 단자에서 렌더러가 번호를 여러 줄로 쌓는 것(`lane`)은 결함이 아니다. 위아래 두 줄로 쌓인 단자의 같은 가로 좌표(`ki-pro-go2`·`vs10`, [10-04 점검](../기획/포트맵좌표점검-2026-10-04.md))는 높이 `y`로 줄이 갈리면 OK.

판정은 **사진을 직접 열어** 한다. 숫자 검사만으로 OK를 주지 않는다.
