## 모양 — 기존 두 흐름과 똑같이

`brc-am7.json`의 `signalFlow`가 본보기다.

```json
"signalFlow": {
  "type": "camera",
  "description": "…",
  "inputs":  [ { "id", "label", "signal", "evidence": [{ "kind": "io", "index": n }] } ],
  "outputs": [ … ]
}
```

- **`evidence`는 해당 제품 `io` 행 인덱스를 가리킨다.** `io`에 없는 단자를 흐름에 만들지 마라
- 촬영 장면(`scene`) 입력은 BRC-AM7처럼 `kind: "spec"` 근거로 둘 수 있다
- `description`은 **명사형 아님** — 흐름 설명문은 기존 두 제품과 같은 문체를 유지한다 (말투 정리 범위는 `features`·`portMap.desc`였다)

## 제품별 재료 — Work가 `io`를 읽어 뒀다

### `srg-x40uh` (io 7행)

| 방향 | 단자 (`io` 인덱스) |
|---|---|
| 입력 | 촬영 장면(spec) · VISCA IN(2) · LAN 제어·PoE+(4) · IR(6) · DC 12V(5) |
| 출력 | HDMI(0) · USB-C UVC(1) · VISCA OUT(3) · LAN IP 스트리밍(4) |

> LAN(4)은 **제어·전원·IP 영상이 한 단자**다. BRC-AM7이 같은 상황을 어떻게 그렸는지 보고 **같은 방식**으로 다뤄라. 전원(5)·IR(6)을 흐름에 넣을지도 **기존 두 제품의 선례를 따른다** — BRC-AM7이 뺐으면 빼라.

### `tr335` · `tr315` (io 4행, 두 제품 동일 구성)

| 방향 | 단자 (`io` 인덱스) |
|---|---|
| 입력 | 촬영 장면(spec) · RS-232/422·CGI 제어(2) · PoE+/Ethernet(3) |
| 출력 | 3G-SDI·HDMI·IP·USB 동시 출력(0) · USB3.0 UVC(1) |

> `io[0]`이 **네 매체를 한 행**에 담는다(수량 4). 출력 노드를 쪼갤지 한 노드로 둘지는 **`evidence`가 행 단위**라는 제약 안에서 정하라 — 쪼개면 네 노드가 같은 `index: 0`을 가리키게 된다. 둘 다 유효하니 **보기 좋은 쪽을 고르고 근거를 보고**하라.
>
> **두 제품의 차이(줌 배율 등)는 사양이지 흐름이 아니다.** 흐름이 같아도 된다. 다만 **복사했다면 복사했다고 근거표에 적어라.**
