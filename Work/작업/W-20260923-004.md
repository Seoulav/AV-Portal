## 목표와 실제 현재 상태

사용자가 기존 제품 상세에서 관련 문서를 종류별로 찾고, 공식·보조·제조사 직접 자료 및 확인 수준을 구분하도록 한다. 자료 검색·업로드·편집 기능을 함께 만들지 않는다.

PR #4는 로컬 JSON 기반 검색·브랜드/복수 카테고리 필터·공식/보조 링크·직접 제공 참조·원본 행 표시를 구현했다. 현재 `app/server.mjs`의 GET `/api/catalog`는 제품 목록을 읽고 `app/public/app.js`가 제품 상세를 구성한다. 자료 수집대장 자체의 조인·문서 종류별 표시는 없다. 인계의 테스트 14/14와 로컬 검증 1/1은 당시 결과이며 이번 명세 작성 중 재실행한 결과가 아니다.

## 최소 설계와 선택 이유

기존 제품 JSON에 수집대장 전체를 복제하는 방식, 별도 읽기 전용 어댑터, DB 도입 중 **별도 읽기 전용 어댑터**를 선택한다. 제품 목록의 식별·분류를 유지하고 공유 문서를 자료 ID로 연결하며, 원본의 개인 경로를 브라우저로 보내지 않기 위함이다. 최종 Schema/Architecture 결정은 아니다.

1. 선택 설정 `AV_PORTAL_RESOURCE_REGISTER_PATH`로 이 PC의 수집대장 JSON 절대 경로를 지정한다. 미설정 시 기존 목록 기능은 그대로 동작하고 상세에 “자료대장 미연결”을 표시한다. 저장소에 로컬 자료가 포함됐다고 가정하거나 자동으로 웹에서 가져오지 않는다.
2. 서버 어댑터가 제품 목록의 `id`와 수집대장의 `product_id`, `resource_id`를 연결한다. `product_resource_links`를 표시 관계의 기준으로 삼고 `products.resource_ids`와 대조한다. 이름 유사도 기반 연결·제품 추가·브랜드/카테고리 재분류는 하지 않는다.
3. GET `/api/products/:productId/resources`에서 필요한 표시 필드만 반환한다. 응답 상태는 `not_configured`, `available`, `unavailable`로 구분한다. 알려진 제품에 자료가 없으면 available과 빈 목록, 없는 제품 ID는 404, 설정된 파일의 읽기/파싱/구조 오류는 500과 일반화된 오류 메시지를 반환한다. 자료대장 실패가 `/api/catalog`와 검색·필터를 중단시키지 않는다. 미설정 응답은 200이며 설정·절대 경로를 노출하지 않는다.
4. 제품의 기존 상세 펼침 동작에서 자료를 읽는다. 같은 제품의 상세에서 기존 목록 출처는 유지하되 새 자료대장은 별도 “자료대장” 영역으로 표시하여 두 집계가 다른 입력임을 밝힌다. 원본 URL들을 자동 합쳐 검증 상태를 덮어쓰지 않는다.
5. 자료를 제품 페이지 / 사양서·카탈로그 / 매뉴얼 / 제어 자료 / 기타로 묶는다. 원문 `kind`는 보존하고 알려지지 않은 값은 기타로 표시한다. 자료 행은 제목, 출처 구분, 언어, 개정 정보, 확인일, 확인 수준, 제품 적용 범위와 허용된 웹 링크를 표시한다. 값이 없으면 “미확인”으로 표시한다. 종류가 휴리스틱 추정이면 `kind_basis`를 통해 “제목·URL 기준 분류”임을 표시한다.
6. 언어가 명시적으로 ko인 자료를 우선하고 en, 기타, 미확인 순으로 안정 정렬한다. URL만 보고 언어·공식성을 새로 확정하지 않는다. 같은 자료 ID가 여러 제품에서 보여도 정상이며 한 제품 안의 동일 관계는 중복 표시하지 않는다.
7. 새 API는 `resource_id`, 안전한 제목, `authority`, `kind`, 선택적 `kind_basis`, `language`, `revision`, `verification`, `checked_on`, 관계의 `applicability`, 허용된 HTTPS URL만 선별한다. `folder`, `local_reference`, 감사 파일 경로, 원본 JSON 전체, 개인 절대 경로는 반환하지 않는다. 직접 제공 자료는 “로컬 보관 · 파일 열기 미지원”으로 표시한다. 경로형 제목은 안전한 일반 제목으로 대체한다. 파일 다운로드·ZIP 추출·파일 URL·임의 경로 조회는 제공하지 않는다.

## 입력 계약과 로컬 접근 한계

GitHub에서 확인 가능한 근거는 위 인계서의 필드·상태 요약과 코드다. `hkkim/` 및 `outputs/` 원본은 GitHub에서 읽을 수 없고 워크트리에도 자동 복사되지 않는다. 구현자는 자기 PC의 로컬 입력을 지정해야 한다. 실제 자료를 Git에 올려 이 문제를 해결하지 않는다.

| 입력 배열 | 사용 필드 | 역할 |
|---|---|---|
| 제품 목록 `products` | `id`, 기존 제품·원본 행·카테고리 | 화면 제품 기준 |
| 수집대장 `products` | `product_id`, `resource_ids` | 참조 일관성 대조. `folder`는 서버 내부에서도 파일 접근 근거로 사용하지 않음 |
| `resources` | `resource_id`, `title`, `authority`, `kind`, `url`, `language`, `revision`, `verification`, `checked_on`, 선택적 `kind_basis` | 자료 표시 투영 |
| `product_resource_links` | `product_id`, `resource_id`, `applicability` | 제품–자료 다대다 연결 |

`authority`는 OFFICIAL / MANUFACTURER_DIRECT / SUPPLEMENTAL을 각각 공식 / 제조사 직접 제공 / 보조로 표시한다. 미등록 상태값은 안전한 원문과 “해석 미등록”을 함께 표시하며 확인 완료로 취급하지 않는다. 필수 배열·ID·참조 관계 손상과 새 상태명은 구분한다. 추가 필드는 무시하고 원본은 수정하지 않는다.

작성자가 이 PC에서 별도로 읽은 로컬 요약: 제품 338개, 자료 455개, 연결 557개. 수집대장 SHA-256 `c1d3644faa1e1c0e67627fc7353828da989d38fc327069dece6bab5751245476`. 인계 당시 338/120/154와 해시가 다르며 이는 후속 로컬 조사 결과다. 실제 값·URL·개인 경로를 이 PR에 포함하지 않는다. 현재 `kind`에는 DATASHEET, DOCUMENT, SUPPORT_INDEX, PRODUCT_FAMILY_INDEX, SUPPLEMENTAL_DOCUMENT가 추가됐고 `verification`에는 OPENED_MODEL_TEXT_MATCH, OPENED_APPLICABILITY_UNCONFIRMED, SEARCH_MODEL_MATCH_OPEN_FAILED, SEARCH_MODEL_MATCH_ONLY가 추가됐다. 이 요약도 구현 시작 시 실제 파일과 재대조한다.

CONTENT_VIEWED는 열람 사실, OPENED_MODEL_TEXT_MATCH는 모델명 출현 사실만 뜻한다. 검색 색인·열람 실패·파일명 일치·제품군/별칭 후보는 정확 SKU·호환성·사양·공개 준비 완료가 아니다. 제품별 `applicability`를 자료의 `verification`과 별도로 표시한다.

구조 손상, 중복 resource_id/product_id, 존재하지 않는 참조 ID, `resource_ids`와 관계 배열의 불일치는 수집대장 unavailable로 처리하고 제품 목록은 유지한다. 완전히 같은 관계 중복만 화면에서 한 번 표시한다. 같은 ID 쌍에 상충하는 applicability가 있으면 unavailable로 처리한다. 오류 메시지에는 원본 값·파일 경로를 복사하지 않는다.

## 검증 방법

1. `npm test`: 기존 검색·복수 카테고리·출처 테스트와 신규 어댑터/API/UI 변환 테스트. 실제 로컬 파일 없이 합성 자료만으로 CI에서 통과해야 한다.
2. 합성 fixture: 두 제품이 공유하는 문서, 자료 없음, null 선택값, 새 상태값, 파일 없음·손상 JSON, ID 중복·dangling 참조·역색인 불일치·상충 관계, HTML 제목, `file:`/`javascript:`/자격증명 포함 URL, Windows·POSIX 경로를 포함한다. 경로 비노출은 정상 및 오류 응답 전체와 상세 DOM에서 검사한다. 유효 HTTPS만 안전한 외부 링크로 표시한다.
3. 기존 `npm run verify:local`과 신규 `npm run verify:resources:local`을 각각 실제 제품 목록·수집대장 경로로 실행한다. 신규 명령은 구현 범위에 포함한다. 실제 입력이 없으면 이유를 기록하고 실제 연결 검증은 미완료로 둔다. 자료 수 120 또는 455를 코드에 고정하지 않는다.
4. 브라우저: 설정 있음/없음, 공유 자료, 한국어 우선, 미확인 정보, 파일명 후보·열람 실패·제품군 후보, 안전한 외부 링크를 확인한다. 조회 전후 파일 SHA-256과 제품 ID·원본 행·카테고리 집합을 대조한다.
5. `git diff --check`, `git diff --cached --check`, `git diff --check origin/main...HEAD`, PR 파일 목록에서 원본·로컬 자료 제외를 확인한다.
