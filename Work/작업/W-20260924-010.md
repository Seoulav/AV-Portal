## 목표와 현재 상태

W-20260924-009 명세는 수정 대상으로 `beta/site/detail/app.js`와 `beta/site/detail/styles.css`만 지목했다. **이 두 파일은 원본이 아니라 생성물이다.**

`beta/build-group1-pages.mjs:77-100`은 다음을 복사·치환해 공개 산출물을 만든다.

| 원본 | 생성물 | 방식 |
|---|---|---|
| `prototype/brc-am7/index.html` | `beta/site/detail/index.html` | 문자열 치환 8건 |
| `prototype/brc-am7/app.js` | `beta/site/detail/app.js` | 문자열 치환 5건 |
| `prototype/brc-am7/styles.css` | `beta/site/detail/styles.css` | `copyFile` |
| `prototype/brc-am7/product-detail-model.mjs` | `beta/site/detail/product-detail-model.mjs` | `copyFile` |
| `prototype/group1/group1-links.js` | `beta/site/detail-links.js` | `copyFile` |
| `prototype/group1/group1.css` | `beta/site/detail-links.css` | `copyFile` |

실제 관행은 두 쪽을 같은 커밋에서 함께 고치는 것이다. `fd20219`(PR #42)는 `beta/site/detail/app.js`·`styles.css`와 `prototype/brc-am7/app.js`·`styles.css`를 동시에 변경했다. 현재 두 파일은 위 치환 규칙을 적용하면 완전히 일치한다.

그러나 **이 동기화를 강제하는 검사가 없다.** `tests/`·`scripts/`·`beta/` 어디에도 두 쪽을 대조하는 코드가 없다. `beta/verify-pages.mjs`는 공개 산출물만 본다. `tests/product-detail-template.test.mjs`는 `prototype/brc-am7/product-detail-model.mjs`를 검사하므로 공개본 쪽은 검사 대상이 아니다.

결과적으로 W-009를 명세대로만 수행하면 다음에 `beta/build-group1-pages.mjs`를 실행하는 순간 수정이 되돌아간다. W-009가 고치는 `content.json` fallback 자체가 이 복사 구조로 프로토타입에서 옮겨온 결함이다.

## 범위

- 추가할 변경
  - `prototype/brc-am7/app.js` — W-009의 1·2·3번 수정을 공개본과 동일하게 적용
  - `prototype/brc-am7/styles.css` — W-009의 `.source-item` `scroll-margin-top` 보완 적용
  - `prototype/brc-am7/index.html` — W-009가 공개본 `index.html`의 `?v=`를 바꾸는 경우, 치환 규칙이 유지되도록 대응
  - 원본과 생성물의 일치를 검사하는 테스트 1건 추가
- 변경하지 않을 영역
  - `beta/build-group1-pages.mjs`의 빌드 방식 자체 (별도 구조 작업에서 다룬다)
  - `prototype/brc-am7/content.json` — 프로토타입에서는 이 파일이 실제로 사용되므로 삭제하지 않는다
  - `prototype/group1/`, W-009의 제외 범위 전체
- 유지해야 할 결정
  - 공개 아티팩트에 파일을 추가하지 않는다. `verify-pages.mjs`의 `detail/` 파일 목록 assert가 그대로 통과해야 한다.

## 검증 방법

```text
npm test
node beta/verify-pages.mjs
```

새 테스트는 `beta/build-group1-pages.mjs`가 사용하는 치환 규칙을 그대로 재사용하거나 같은 값을 공유해야 한다. 규칙을 테스트에 손으로 다시 적는 방식은 빌드가 바뀔 때 함께 틀어지므로 피한다.

프로토타입 회귀 확인은 `node prototype/brc-am7/serve.mjs`로 띄워 `?product=` 없는 진입이 `content.json`으로 정상 렌더되는지 본다. 이 확인을 수행하지 못하면 이유를 기록한다.
