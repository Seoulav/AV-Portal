## A — 비디오월 2종 (가장 쉽다)

`lh55vhcrbgbxkr` · `lh55vmcrbgbxkr`

**설명서 자체가 55인치 4종(VH55C-R · VM55C-R · VH55C-E · VM55C-E) 전용**이라 도면이 하나뿐이다. **두 제품이 같은 도면을 쓴다.**

쪽 제목은 `각부의 명칭 — 뒷면 설명`이고, **왼쪽 세로 도면 + 오른쪽 `단자 / 단자 설명` 2열 표**로 QMC 20쪽과 똑같은 짜임이다.

단자 13개(위→아래):

```
IR OUT → IR IN → DVI IN → HDMI IN 1 → HDMI IN 2 → DP IN →
AUDIO OUT → AUDIO IN → RS232C OUT → RS232C IN → DP OUT(LOOPOUT) → SERVICE → RJ45
```

표는 **12행**이다. `HDMI IN 1, HDMI IN 2`가 **한 행에 묶여 있다.** 설명 글은 그 행에서 가져오되 **번호는 단자마다 따로** 붙인다.

### ★ 번호를 붙이지 않을 것이 하나 있다

`lh55vhcrbgbxkr`의 `io` **13행 중 1행이 `미지원(사양표 "No")`**이다. `isAbsentConnector()`가 걸러 내는 값이고, **Work가 전에 두 번 틀린 자리**다.

> **`io` 행이 있다고 단자가 있는 것이 아니다. `availability`를 본다.**

**실제 도면에 보이는 단자에만 번호를 붙인다.** 도면이 기준이다.

## B — 전자칠판 2종

`lh55wmfwbgcxkr`(55인치) · `lh75wmfwlgcxkr`(75인치)

**쪽이 나뉘어 있다.**

| 제품 | 쪽 | 쪽 소제목 |
|---|---|---|
| 55인치 | **13쪽** | `WM55FX/WM65FX` |
| 75인치 | **14쪽** | `WM75FX/WM85FX` |

**두 쪽의 단자 구성과 순서가 같다.** 그래도 **쪽을 각각 떠라.** 115인치 때 QMC 도면을 가져다 쓰면 안 됐던 것과 같은 이유다.

단자 7개(위→아래):

```
HDMI(출력) → LAN → SERVICE → HDMI(입력) → 음향 출력 → USB(1A) → TOUCH
```

**전원 커넥터는 도면에 따로 표시되지만 단자 표에는 없다.** 번호를 붙이지 않는다.

### 모델명이 다른 것에 대해

쪽 제목은 **`WM55FX`**인데 우리 모델은 **`LH55WMFW…`**다. **글자가 다르다.**

Work가 확인했다. **`io` 행의 설명 문구가 설명서 표와 글자까지 일치한다.**

| 우리 `io` | 설명서 13쪽 |
|---|---|
| `후면 USB 허용 전류 최대 1.0 A` | `USB 단자 허용 전류용량 최대치는 1.0A` |
| `10/100 Mbps · CAT 7(STP) 케이블 권장` | `10/100 Mbps … CAT 7(*STP 타입)` |
| `별도 기능 없음 · 연결하지 않도록 주의` | `별도 기능이 없는 서비스 전용 단자입니다. 단자에 연결하지 않도록 주의하세요.` |

**이미 확인된 연결이다.** 추측이 아니다.

### 번호를 못 붙이는 행이 2개 있다

`io` **9행 중 2행**이 이렇게 적혀 있다.

> **`매뉴얼 후면 단자표에 없음 · 전면/옵션 트레이 여부 미확인`** · `REVIEW REQUIRED`

**뒷면 도면에 없는 단자다.** 번호를 붙이지 않는다. **번호 7개가 맞다.**

## C — 호텔TV 3종 (★ 두 가지 함정)

`hg43u800fnfxkr` · `hg50u800fnfxkr` · `hg65u800fnfxkr`

### 함정 1 — 한 쪽에 두 모델의 도면이 있다

12쪽에 **위는 `[HG**U800F* 모델만 해당]`, 아래는 `[HG**U700F* 모델만 해당]`** 도면이 나란히 있다.

**우리 제품은 U800F다. 위 도면만 쓴다.**

13쪽 번호 목록 ①~⑫는 **두 도면을 합친 공통 목록**이다. 아래 셋은 **U700F 전용**이라 우리 제품에 없다.

```
⑩ HP-ID      ⑪ HEADPHONE JACK      ⑫ SERVICE     ← 붙이면 안 된다
```

Codex가 [W-20261004-017](W-20261004-017.md) 때 이미 이것을 발견해 물었던 자리다. **같은 함정이다.**

### 함정 2 — 단자가 두 구역에 나뉘어 있다

U800F 도면은 이렇게 생겼다.

```
세로 띠                    별도 묶음
──────                    ────────
① USB ×2                  ⑤ DATA   ⑥ EX-LINK   ⑦ 옵티컬
② HDMI ×3                 ⑧ VOL-CTRL   ⑨ VARIABLE
③-1 LAN(입력)
③-2 LAN(출력)
④ 안테나 ×2
```

**지금 Port Map은 그림 하나에 한 변으로 번호를 단다.** 두 구역은 **지금 구조로 표현할 수 없다.**

**★ C는 바로 만들지 마라.** A·B를 끝낸 뒤 **어떻게 할지 의견을 먼저 보고하라.** 생각해 볼 수 있는 것들이다.

| 안 | |
|---|---|
| 두 구역을 **한 그림에** 넣고 `left`·`right`를 섞어 쓴다 | 지금 구조로 되나? |
| **세로 띠만** 번호를 달고 나머지는 03 단자 카드로 | 정보가 빠진다 |
| **위아래로 이어 붙여** 한 세로 그림으로 만든다 | 원본을 손대는 것이 된다 |
| 구조를 넓힌다 | 범위가 커진다 |

**Work가 정하지 않는다. 실제로 그려 보고 판단하라.**

### 번호는 매뉴얼 번호를 그대로 쓰지 않는다

`validMarker`가 `n`을 **양의 정수**로만 받는다(`detail-enhancements.mjs:13`). **`③-1`을 넣을 수 없다.**

**우리가 1부터 다시 매긴다.** QMC도 그렇게 했다. 매뉴얼 번호는 **참고일 뿐**이다.

### `io`에 단자가 아닌 행이 있다

`hg65u800fnfxkr`의 `io` 13행 중

| 행 | 내용 | |
|---|---|---|
| 1 · 2 | `Android 6+/iOS 14+ …` · `iOS 17.3 이상 …` | **화면 미러링 기능이지 단자가 아니다** |
| 12 | `매뉴얼 11쪽은 DATA 케이블(RJ12)을 설명함 · DATA와 동일 여부 미확인` · `REVIEW REQUIRED` | **미확인** |

**`io` 행 수를 번호 수로 삼지 마라. 도면이 기준이다.**
