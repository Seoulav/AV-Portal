## 목표와 현재 상태

2026-09-24 독립 검증에서 공개 상세의 **진입 경로 결함 2건**과 **CI 검증 범위 누락 1건**을 확인했다. 세 건 모두 제품 데이터·검증 상태·공개 범위를 바꾸지 않고 수정할 수 있다.

1. **쿼리 없는 `/detail/` 진입이 항상 실패한다.** `beta/site/detail/app.js:53`은 `product` 파라미터가 없으면 `./content.json`을 요청한다. 이 파일은 프로토타입(`prototype/brc-am7/content.json`)에만 있고 공개 아티팩트에는 없다. `beta/verify-pages.mjs`가 `detail/`의 파일 목록을 정확 일치로 assert하므로 구조적으로 영원히 404다. 결과는 "제품 상세 데이터를 읽을 수 없습니다." 경고와 빈 본문이며 Library로 돌아갈 수단은 헤더 링크뿐이다.
2. **섹션 해시가 붙은 URL로 직접 진입하거나 새로고침하면 엉뚱한 위치에 착지한다.** 본문은 JSON fetch 이후 주입되는데, 브라우저는 문서가 비어 있는 파싱 시점에 해시 스크롤을 확정한다. 이후 삽입된 내용이 대상 섹션을 아래로 밀어낸다. `?product=brc-am7#io` 직접 진입 시 실측: 1440px에서 `scrollY=1611`인데 `#io .section-title`은 뷰포트 상단 +1167px, 390px에서는 +1945px에 위치한다. 페이지 내 탭 클릭은 `scroll-margin-top:100px`이 적용되어 정상(`headTop=100`)이다.
3. **CI가 `npm test`를 실행하지 않는다.** `.github/workflows/pages.yml`은 저장소의 유일한 workflow이며 `node beta/verify-pages.mjs`만 실행하고 곧바로 배포한다. `verify-pages.mjs`는 공개 경계 검사에 특화되어 앱 동작을 검사하지 않으므로, 43개 테스트가 잡는 회귀가 검증 없이 공개될 수 있다.

부수적으로 `beta/site/detail/app.js`가 `import`하는 `./product-detail-model.mjs`에는 캐시 갱신 쿼리가 없다. W-20260924-008에서 확인한 캐시 문제와 같은 종류이므로 이번에 함께 정리한다.

## 검증 방법

저장소 루트에서 실행한다. Node.js 20 이상, 추가 npm 패키지 설치 없음.

```text
node beta/verify-pages.mjs
npm test
```

화면 검증은 `beta/site` **전체**를 쿼리 문자열과 함께 제공하는 정적 서버로 한다. `beta/serve.mjs`는 초기 Library 파일만 제공하므로 이 검증에 사용하지 않는다. 확인 대상 URL과 뷰포트는 다음과 같다.

| URL | 기대 결과 |
|---|---|
| `/detail/` | Library로 이동 |
| `/detail/?product=` | Library로 이동 |
| `/detail/?product=nope` | 오류 안내 + Library 링크 |
| `/detail/?product=BRC-AM7` | 형식 오류 안내 + Library 링크 |
| `/detail/?product=brc-am7#io` | I/O 제목이 상단 약 100px, 새로고침 후 동일 |
| `/detail/?product=<5종>` | Quick 4칸·수량·I/O 즉시 표시 유지, 가로 넘침 0 |

뷰포트는 Desktop 1440px·Mobile 390px 두 가지를 모두 확인한다. 측정은 `getBoundingClientRect().top` 값으로 기록하고, 추정치가 아닌 실측치를 `Work/지시서.md`에 남긴다. 수행하지 않은 검증은 통과로 적지 않는다.

## 미결 사항·의존성

- **공개 배포 승인은 이 명세로 발생하지 않는다.** main 병합과 Pages 재배포는 사용자의 별도 승인 후에 진행한다.
- 이번 독립 검증에서 실제 공개 URL(`seoulav.github.io`)은 네트워크 정책 차단으로 확인하지 못했다. 배포본이 `main`의 `beta/site`와 동일하다는 전제는 독립 검증되지 않았으므로, 병합 후 공개 URL 확인을 Codex 기록에 남긴다.
- 제조사 사양의 진위와 사진·PDF 재게시 권한은 이번 범위 밖이며 미확인 상태를 유지한다.
- 다음 후속 검토 후보(별도 작업 ID 필요, 이번 범위 아님)
  - 상태 배지 명암비 WCAG AA 미달: `.spec-meta .state-verified` 2.42:1, `.quick-card .state-verified` 3.10:1, `.state-conflict` 4.16:1, `.state-review` 4.32:1, `.state-missing` 4.35:1. `CONFLICTED`·`REVIEW REQUIRED`·`MISSING`처럼 오해하면 안 되는 표시가 특히 읽기 어렵다. 8px 글자 크기도 함께 검토한다.

  - `beta/site/detail-links.js`가 카드의 표시 텍스트 문자열 매칭에 의존하고 이를 검사하는 테스트가 없다. 카탈로그 표기가 바뀌면 상세 링크 5개가 조용히 사라진다.
  - Library(`beta/site/index.html`)의 `styles.css`·`app.js`·`detail-links.js`에는 캐시 갱신 쿼리가 없다.
