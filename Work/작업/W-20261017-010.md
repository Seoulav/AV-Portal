# W-20261017-010 — 문서 웹 뷰어: 보기(웹)와 다운로드 분리

- 명세 상태: **READY**
- 작성 담당: Work
- 작성일: 2026-10-17
- 담당 세션: A
- **승인 근거** (2026-10-17): 사용자 지시 "https://seoulav.github.io/AV-Portal/analogway/#standards 문서보기가 되서 웹으로 보였으면해, 다운로드 별도로 되고."
- 배경: 현재 "보기 ↗"는 PDF를 새 탭으로 직접 연다. 컴퓨터 브라우저는 내장 뷰어로 보여 주지만 휴대폰(삼성 브라우저 등)은 내려받기로 처리해 "웹으로 보기"가 안 된다. 사용자는 휴대폰으로 확인한다.
- 선행 조건: W-20261017-009(LED 연동) 병합 후 착수(같은 analogway 페이지 파일).

## 목표

문서 카드의 동작을 둘로 나눈다: **[보기] = 휴대폰에서도 페이지 안에서 읽히는 웹 뷰어**, **[다운로드] = 파일 저장**.

## 할 일

1. **공용 PDF 웹 뷰어 도입**: Mozilla PDF.js 배포본을 `beta/site/pdfjs/`(또는 공용 위치)에 벤더링하고, 뷰어 주소 `…/pdfjs/web/viewer.html?file=<PDF 경로>` 형태로 연다. 외부 CDN 의존 금지(공개 Pages 정적 호스팅 안에서 동작). 라이선스 파일(Apache-2.0)을 함께 둔다.
2. **아날로그웨이 종합 페이지 문서 모음**: 각 문서 카드에 [보기]와 [다운로드] 단추를 분리한다. [보기]는 뷰어로, [다운로드]는 `download` 속성을 붙인 직접 링크로. 제조사 사이트로 가는 외부 링크(예: "공개 데이터시트 보기")는 기존 그대로 둔다.
3. **제품 상세의 문서 절도 같은 패턴 적용**: 상세 페이지(beta/site/detail) 문서 목록의 "보기"도 같은 뷰어를 쓰게 한다. 변경 범위가 크면 아날로그웨이 15종 우선 적용 후 전체 적용 여부를 Work에 보고한다.
4. **잠긴 PDF 12건**: 파일·암호 처리 변경 금지. 뷰어로 열리면 PDF.js의 암호 입력 창이 뜨는 동작 그대로 두고, 비밀번호를 어디에도 적지 않는다.
5. 시험·검증: 뷰어 페이지가 存在하고 대표 문서가 열리는지(경로 검사), verify-pages에 pdfjs 폴더 허용 추가(필요 시), 전체 검사·검색 인덱스 `--check`. 390px 모바일 뷰어 화면 캡처 포함.

## 하면 안 되는 것

- 외부 뷰어 서비스(구글 문서 뷰어 등) 사용 금지(외부 전송), 잠긴 PDF 12건의 암호 해제·재암호화 금지, 비밀번호 기록 금지, 제품 JSON 변경 금지, PDF 원본 수정 금지.
