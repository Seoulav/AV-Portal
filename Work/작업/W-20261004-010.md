### `g3`에서 읽은 단자 순서 (위 → 아래)

```
USB 2 ⚡(1.0A) → USB 1 ⚡(0.5A) → 🔊→ → HDMI 3(ARC) → HDMI 2 → HDMI 1
→ DP↵ → RJ45 → RS232C↵ → RS232C↱ → IR↵
```

**11개다.** 매뉴얼 15쪽 도면과 **순서가 완전히 일치**한다. 서로 다른 두 출처가 같은 결과를 냈다.

## ★★ 모델별로 단자 배치가 다르다

사용자가 비교용으로 QHC 시리즈(`LH55QHCEBGCXKR`) 뒷면 사진을 함께 제시했다. 순서가 **다르다.**

```
QHC    : USB2 → USB1 → 🔊 → DP → HDMI3(ARC) → 2 → 1 → RJ45 → RS232C×2 → IR
115QHF : USB2 → USB1 → 🔊 → HDMI3(ARC) → 2 → 1 → DP → RJ45 → RS232C×2 → IR
                                                   ↑ DP 위치가 다르다
```

**비슷해 보인다고 다른 제품 사진을 쓰면 틀린다.** 반드시 그 제품 페이지에서 받은 것만 쓴다. `LH32QMRN`·`BLU-50` 때와 같은 함정이며, 이번에는 **사진끼리** 섞일 뻔했다.

## 우리 `io`와 대조해 두었다

| 사진 | `io` |
|---|---|
| USB 2 · USB 1 | `2 x USB-A USB` **한 행** |
| 🔊→ | `아날로그 오디오 출력` 1 |
| HDMI 3(ARC) · 2 · 1 | `3 비디오/오디오 입력 [HDMI]` **한 행** |
| DP · RJ45 · RS232C↵ · RS232C↱ · IR | 각 1행 |
| — | `아날로그 오디오 입력` — **`absentConnectors`**(`미지원(사양표 "No")`) |
| — | `무선 화면 공유(스마트 뷰+)` — 물리 단자 없음 |

**빠진 것도 남는 것도 없다.** 표시 단자 9행이 사진 11개로 펼쳐진다.

## 코드로 해야 할 일 하나 — 좌·우 마커

**단자가 세로로 쌓여 있다.** 가로 괄호(`x1`~`x2`)로는 표시할 수 없다.

[W-20261004-001](W-20261004-001.md)에서 **렌더러는 이미 좌·우 세로 괄호를 그릴 수 있게 옮겨 두었다.** 검증기만 막고 있다.

필드가 방향별로 다르다.

| `side` | 필수 | 선택 |
|---|---|---|
| `top` · `bottom` | `x1` · `x2` | `y` |
| **`left` · `right`** | **`y1` · `y2`** | **`x`** |

`validMarker`를 **분기**로 고친다. 한쪽 필드 묶음만 허용하고 **섞이면 거부**한다.
