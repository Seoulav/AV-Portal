## 목표와 현재 상태

W-010·W-011로 Analog Way 11개 비디오 프로세서(Aquilon RS alpha·RS1~RS6, Zenith 100·200, Pulse 4K·Eikos 4K)의 상세 페이지에는 "레이어 구성" 해설 카드(2×2 4K60 화면 예시, 모델 비교표)가 있다. 그러나 사용자가 **원하는 화면 구성(화면 수·출력 수·레이어 수·AUX·입력 수)을 넣으면 어떤 모델이 가능한지** 알려 주는 설계 단계는 없다. RTCOM 구성기가 프레임·카드를 고르면 구성이 완성되듯, Analog Way도 "화면 연출 개수 → 모델"로 가는 설계 가이드를 만든다.

조사에서 확인하지 못한 것(가이드에 "미확인"으로 표시):
- Aquilon에서 한 화면의 링크를 VPU 두 개에 나눠 쓸 수 있는지(W-010 미확인 유지). 가이드는 **화면 하나는 VPU 하나 안에 들어가야 한다**고 가정한다.
- 용량 1(HD) 레이어와 용량 2 레이어를 섞을 때의 비용(매뉴얼 69쪽 권고대로 가이드는 용량 2 레이어만 계산).
- Alta 4K에서 레이어가 출력 경계를 넘을 때 추가 자원(W-011 미확인 유지).
- Midra·Alta 시뮬레이터 데이터시트는 2026-10-16 접속 실패(503)로 미확인.

## 설계(가이드 동작)

1. **입력**: 화면 목록(행 추가·삭제). 행마다 구성(출력 1개 4K60 / 출력 2개 2×1·1×2 / 출력 3개 / 2×2 4출력), 레이어 종류(믹싱 / 분할), 레이어 수(0~8). 그 아래 AUX(1080p/4K 보조) 출력 수, 4K 입력 소스 수.
2. **계산**(순수 함수, 모델별):
   - **Aquilon**: 화면마다 출력 링크 = 출력 수 × 2, 소스 링크 = 믹싱 × 2 + 분할 × 1(용량 2 기준, 매뉴얼 66쪽). 출력 링크 > 8 또는 소스 링크 > 8이면 그 화면은 "VPU 1개 초과 · 미확인". 화면을 VPU에 첫 적합(first-fit)으로 담아 필요한 VPU 수를 구한다. 조건: 필요 VPU ≤ 모델 VPU, 4K PGM 출력 합 ≤ 모델 PGM 출력, PGM + AUX ≤ 출력 커넥터, 입력 ≤ 4K 입력. AUX는 처리 자원을 쓰지 않는다(데이터시트).
   - **Alta 4K**: 화면마다 자원 = 믹싱 + ceil(분할 ÷ 2). 조건: 자원 합 ≤ 3/4, 화면별 출력 수 ≤ 3/4, PGM 출력 합 ≤ 3/4, AUX ≤ 2/4, PGM + AUX ≤ 4/6, 입력 ≤ 11/14(4K).
   - **Midra 4K**: 화면 1개(출력 1) → Mixer 모드(믹싱 ≤ 2 또는 분할 ≤ 4, AUX ≤ 1). 화면 2개(각 출력 1) → Matrix 모드(화면마다 믹싱 ≤ 1 또는 분할 ≤ 2, AUX 0). 출력 2개 화면 1개 → Blend 모드(Eikos 4K만, 믹싱 ≤ 2 또는 분할 ≤ 4, AUX 0). 그 밖은 불가. 입력 ≤ 8(4K).
3. **출력**: 모델별 판정표(가능 / 불가 + 이유, 사용 자원·남는 자원). 가능한 모델 중 가장 작은 모델을 "추천"으로 표시(순서: Pulse 4K → Eikos 4K → Zenith 100 → Zenith 200 → RS alpha → RS1 → RS2 → RS3 → RS4 → RS5 → RS6). 현재 보고 있는 제품 행을 강조한다. 근거 쪽 번호와 미확인 가정을 표 아래에 적는다.
4. **예시 버튼**: "8K LED월 1면(2×2) + 믹싱 4", "4K 화면 3개 + 믹싱 2씩 + AUX 2", "4K 화면 1 + 분할 4 + AUX 1"처럼 RTCOM 가이드처럼 바로 눌러 볼 수 있는 예시 3개.
5. **위치**: Analog Way 비디오 프로세서 11종 상세의 보조 카드(`.supplemental-cards`)에 "화면·레이어 설계 가이드" 카드로 둔다. RC400T에는 두지 않는다. 카드는 `#analogway-layer-guide`로 깊은 링크된다.
