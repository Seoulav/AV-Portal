## 목표

승인 후 DM7 1개만 로컬에서 검토 가능한 상세 시안으로 구현해 실제 정보 밀도·누락·출처·확대·반응형 동작을 검증한다. 이번 Work에서는 원고만 완성하며 코드·테스트를 작성하지 않는다.

## 범위

후속 구현 대상은 별도 preview/dm7-detail/ 등 배포 아티팩트 beta/site 밖의 독립 화면이다. 최종 경로는 READY 검토 시 기존 앱 구조와 대조한다. 콘텐츠 패키지의 확정 원고·16개 사양·15개 I/O 행·6개 문서 카드와 출처 상태를 사용한다.

공개 beta/site·catalog.json·배포 워크플로·기존 앱·다른 24개 상세·RTCOM 로직·Builder·LED는 변경하지 않는다. 전체 조사·DB·Final Schema·Storage Vendor 확정·자동 자료 수집·CAD 핫스폿·제품 추가·공개 배포는 제외한다.

## 검증 방법

문서 원고와 화면의 수치/단위/조건·모델을 대조한다. 문서 0/1/6개, 이미지 0/1/4개·요청 실패를 별도 검토 데이터로 확인하며 실제 카탈로그 값은 바꾸지 않는다. 기존 저장소 검증은 README의 명령에 따라 변경 영향 범위만 실행한다. 공개 입력은 beta/verify-pages.mjs와 파일 해시로 불변 확인한다. 증빙을 공개 PR에 첨부할 때 이미지 재게시 조건을 먼저 확인한다.

## 선행 조건·사용자 승인 필요 여부

1. **필요:** 사용자에게서 DM7 한 개 로컬 시안 구현 승인. 이번 자료 준비 요청은 구현 승인이 아님.
2. **필요:** 로컬 이미지 사용 방식 확인. 재게시/핫링크 허가는 미확인이며 외부 공개는 제외. 사용할 수 없는 자산은 권한 대기 상태로 처리하는 범위를 정한다.
3. **필요:** 기획 보강·명세·인계서의 main 반영. 현재 main push는 자동 Pages 배포이므로, 이번 재배포 금지 중에는 병합하지 않는다. 재배포 없는 병합 절차를 별도 승인 범위에서 마련하거나 사용자에게 배포 허용 범위를 확인한다. 워크플로를 임의 수정하지 않는다.
4. **필요:** 구현 PC에서 공개 문서 URL과 허용된 로컬 자산의 열람 확인. hkkim/outputs는 GitHub에서 접근 불가.
5. C1 USB 표기 차이·C2 최신성·C4 CAD 미검증은 상태 표시로 유지할 수 있으며 해결 전 전체 VERIFIED 처리 금지. 부족한 Quick Start 등은 착수 전 필수 확보 대상으로 만들지 않는다.
