## 범위

이번 승인 범위는 **대응표 작성만**이다. `beta/site/catalog.json`과 `beta/site/detail/data/*.json`을 읽어 카테고리·사양 그룹·연결 단자 그룹의 현재 이름, 보수적인 정리 이름, 사용 횟수를 적는다. 카테고리는 카탈로그와 상세를 구분해 제품 수를 세고, 사양·단자는 행 수를 센다. 애매한 이름은 변경 안 함과 사용자 확인 필요로 남긴다.

대응표 승인 후 별도 지시가 있어야 데이터의 이름 필드 적용과 검색 인덱스·읽기용 목록·공개 snapshot·고정 해시 검사 정합화를 시작한다. `direction` 빈칸 채우기와 다른 값 변경은 계속 제외한다.

- 이번 명세 PR에서는 이 명세와 인계서만 반영하고, 다음 대응표 PR에서도 대응표·진행 기록만 반영한다. 제품 데이터·생성물·코드·테스트는 수정하지 않는다.
- 제외: 다른 단계 구현, 미확인 사양 생성, 기존 RTCOM 구성 로직 변경, 내부 자료 공개, DB/최종 Schema 확정.
- 단계별 별도 구현 PR, 이전 단계 사용자 확인 후 진행. 후속 단계 착수는 자동 승인되지 않는다.

## 검증 방법

현재 main의 JSON에서 이름과 사용 횟수를 다시 산출해 대응표와 대조한다. PR 파일 목록으로 제품 데이터·생성물이 바뀌지 않았음을 확인하고 Markdown 링크·차이를 점검한다. 데이터 적용 단계의 `npm test`, `node beta/verify-pages.mjs`, 생성물 일치 검사와 UI 확인은 이번 문서 작업에서 수행했다고 주장하지 않는다.

## 미결 사항·의존성

Input/Output만으로 신호 유형 추측 금지. direction 보완은 **이번 범위 제외**로 사용자 확정. 기존 값과 충돌하거나 정확한 동의어가 불확실하면 변경 안 함·사용자 확인 필요로 남긴다. **대응표 승인과 데이터 적용 지시가 모두 있기 전에는 이름도 실제로 변경하지 않는다.**

## Codex 인계

**Codex는 명세 PR 병합 후 대응표 작성에만 착수 가능.** 실제 데이터 적용·코드 구현은 이번 READY에 포함되지 않는다. 대응표 PR은 사용자 확인을 위해 열어 두고 승인 전 병합하거나 적용하지 않는다.
