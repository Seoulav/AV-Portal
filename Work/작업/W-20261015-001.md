## 본보기 — 구성기 XDM-CTR100 PSE 시그널 플로우 (Work가 렌더 코드 `pseDiagram`을 직접 읽고 확인)

1. 한 줄 = **소스 기기 → 왼쪽 장비 → 케이블 → 오른쪽 장비 → 디스플레이**. 양끝에 소스·디스플레이 아이콘, 장비는 뒷면 박스+단자 그림, 위에 제목·역할 라벨, 아래에 한 줄 보조 설명.
2. 케이블은 **신호선과 전원선이 겹친 모양**, 전원은 **주황색**으로 방향이 보이게. 케이블 위 알약 라벨과 아래 방향 한 줄("전원 → RX(PD) · 신호 TX → RX").
3. 줄(조합)마다 소제목("조합 1 · … / 조합 2 · …")으로 두 구성을 위아래로 표시.
4. 색 범례(입력/신호/전원/출력), 그림 설명 접이식 단계 목록, "크게 보기" 버튼, 가벼운 흐름 애니메이션.

## 그릴 내용 — 근거: 사용자 제공 HDF-CCF 매뉴얼 5쪽 Application Scenarios·4쪽 Connection Instructions·3쪽 사양표

- **시나리오 2 · 허브 연동(사용자 요청의 중심)**: 노트북(SOURCE, USB-C) → **HDF-CCF** → **USB-C 허브·프레젠테이션 스위치(외부 장비 예시)** → **HDMI 출력(TV/모니터)**, 허브에 USB 주변기기(키보드·마우스·USB 드라이브·외장 HDD). **전원은 허브에서 케이블을 통해 노트북 쪽으로 역공급(PD)** — DISPLAY→SOURCE 방향이 주황색 화살표로 한눈에 보여야 한다. 이 시나리오는 매뉴얼 기재대로 **2 lane DP 1.4 + USB 3.2 10G 모드(4K@60Hz)**.
- **시나리오 1 · 직결**: 노트북 → HDF-CCF → TV/모니터, **4 lane DP 1.4 + USB 2.0 모드(8K@60Hz·4K@144/120Hz)**, 모니터가 노트북에 PD 100W 역공급(매뉴얼 표기).
- 방향 표기: **SOURCE = 소스 기기(노트북), DISPLAY = 디스플레이·허브 쪽, 반대로 꽂지 않기**(매뉴얼 4쪽).
- 전력 수치는 그림에 직접 쓰지 말고 "PD 역공급"으로 표기하고 사양 표를 참조하게 한다(5m 90W · 10m/15m 85W 사양표 vs 본문 100W 충돌 `CONFLICTED` 유지).

## 포털 구현 방식 (조사 후 선택)

- 포털 제품 JSON의 `signalFlow` 블록: `beta/site/detail/detail-enhancements.mjs`의 `validFlow`·`flowTypes`(extender·converter·power 등)로 검증, 입출력 항목은 io 행 인덱스를 `evidence`로 가리킴. 기존 구현 제품(`blu-100`, RTCOM 포털 매핑 등)의 signalFlow 데이터와 렌더(`detail-enhancement-view.mjs`)를 조사해 **같은 방식으로 데이터를 구성**한다.
- 전원 역방향 점선·두 줄 케이블 등 본보기 요소를 포털 렌더러가 표현하지 못하면, **새 flow type을 만들지 말고** 기존 type·그룹·`secondary` 경로 표현으로 최대한 표현하고, 부족한 점은 보고한다. 렌더러 최소 변경이 불가피하면 이 제품에만 영향을 주는 범위로 한정하고 다른 제품 화면 불변을 증명한다.
