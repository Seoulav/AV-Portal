## 왜 하는가

공개 사이트가 **제조사·유통사의 영업 자료를 그대로 내려받게** 하고 있다. 제조사가 다운로드센터로 배포하는 사용설명서와는 성격이 다르다.

### 기록과 실제가 어긋나 있었다

> *"**원본 사본은 게시하지 않음**; SHA-256 67ad244b…"*

**그런데 실제로는 `beta/site/manuals/`에 올라가 공개되고 있었다.** 이번 작업은 그 모순을 바로잡는 일이기도 하다.

## ★★ 비밀번호를 저장소에 적지 않는다

**`Seoulav/AV-Portal`은 공개 저장소다**(`visibility: public`). 명세·인계서·커밋·검사 코드·근거표 어디에도 비밀번호를 쓰면 **암호를 거는 의미가 사라진다.**

- 비밀번호는 **Codex에게 대화로 전달**한다
- 문서에는 **"별도 전달"**이라고만 적는다
- 전용 검사도 **비밀번호 문자열 없이** 작성한다. "암호가 걸려 있는가"와 "비번 없이 못 여는가"만 검사하면 된다

## 도구 — 새 의존성이 필요 없다

Work가 시험해 확인했다.

```
pypdf 6.19.0        이미 설치돼 있음
cryptography 50.0.2 AES-256을 위해 설치함
```

```python
from pypdf import PdfReader, PdfWriter
r = PdfReader(src); w = PdfWriter(clone_from=r)
w.encrypt(PASSWORD, algorithm="AES-256")
w.write(dst)
```

시험 결과: 비번 없이 본문 접근 **차단**(`FileNotDecryptedError`), 올바른 비번 **해제**, 틀린 비번 **거부**.

**사이트 코드의 의존성은 늘지 않는다.** 작업용 Python 도구일 뿐이다.

## 웹 뷰어가 비밀번호를 물어야 한다

암호를 걸면 `beta/site/shared/pdf-viewer.mjs`가 그대로는 열지 못한다. PDF.js의 **`onPassword` 콜백**으로 입력을 받아야 한다.

- 비밀번호 입력 화면이 뜨고, 틀리면 **다시 물어야** 한다
- **비밀번호를 코드에 넣지 않는다.** 사용자가 입력한다
- 암호가 없는 나머지 자료는 **지금과 똑같이** 열려야 한다
