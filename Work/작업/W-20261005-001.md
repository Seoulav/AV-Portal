### 대조군을 같이 돌렸다

없는 모델코드를 끼워 넣어 같은 경로로 요청했다.

```
qhc-series/LH99ZZZZZZZZZZ/   →   "Samsung Business 대한민국"      (일반 제목만)
qhc-series/LH115QHFEBGXKR/   →   "단독형 UHD H 시리즈 290.7cm …"  (실제 제품 제목)
```

**삼성 사이트는 모델이 그 시리즈에 없으면 일반 제목만 돌려준다.** 115가 실제 제목을 돌려줬다는 것은 **`qhc-series` 아래에 실제로 있다**는 뜻이다.

> **결론.** `LH115QHFEBGXKR`와 `LH43QHCEBGCXKR`는 **삼성 스스로 같은 시리즈명(`단독형 UHD H 시리즈`)으로 부른다.** 사용자 말이 근거 있는 사실이다.

### 선 긋기

이것은 **탐색 화면의 묶음**일 뿐이다.

- 모델코드 `LH115QHFEBGXKR`를 **바꾸지 않는다**
- 제품 사양·`keyFacts`·`io`·문서를 **건드리지 않는다**
- 상세 화면의 제품명 표기를 **바꾸지 않는다**

## ★ QHF와 QHC가 부딪히는 자리 — 손대지 않고 푼다

### 무엇이 부딪히나

[W-20261004-022](W-20261004-022.md)에서 사용자가 준 순서는 **"QHF, QHC, QMC, 비디오월, 호텔TV, 비즈니스TV, 전자칠판순"**이었다. QHF가 **따로, 맨 앞**이다.

이번에는 **115도 QHC 라인**이라고 한다. 두 말이 겉보기에 어긋난다.

### 확인해 보니 어긋나지 않는다

목록 화면에는 **묶음 제목줄이 없다.** 카드가 순서대로 늘어설 뿐이다. 그래서 두 해석의 **화면 결과가 같다.**

```
지금 (QHF 따로)        115 → 43QHC → 75QHC → 32QMC …
합쳤을 때 (QHC 안)      115 → 43QHC → 75QHC → 32QMC …
```

> **그러므로 `brandSort`를 건드리지 않는다.** 시리즈 묶음에서만 `QHF`와 `QHC`를 **한 칸으로 보여준다.**

### 이렇게 푸는 이유

| | |
|---|---|
| W-022에서 사용자가 승인한 **순서가 그대로 지켜진다** | |
| `tests/catalog-order.test.mjs`를 **고치지 않아도 된다** | 이 테스트는 `brandSort.order === index + 1`을 줄줄이 고정한다(`:30`). 115를 QHC로 옮기면 **8묶음 전부 번호가 밀린다** |
| W-031의 `?brand=Samsung&sort=brand`가 **그대로 돈다** | |
| 되돌리기 쉽다 | 데이터가 아니라 **보여주는 쪽만** 바뀐다 |

### 안 고른 쪽도 적어 둔다

`brandSort.group`에서 `QHF`를 지우고 115를 `QHC`로 옮기는 방법도 있다. **고르지 않았다.** 8묶음 번호가 전부 밀리고, 승인된 테스트를 고쳐야 하고, W-022의 승인 순서를 다시 해석해야 한다. **얻는 화면은 똑같다.**

**이 판단이 틀렸다고 보이면 구현 전에 말해 달라.**

## 만들 것

### 1 · 시리즈 묶음표를 한곳에 둔다

새 파일 **`beta/site/shared/brand-series.mjs`**.

제조사별로 `brandSort.group` 값을 묶음 한 칸에 이어 붙인다. **이름은 위 ★ 표에서 확인한 삼성 제목을 쓴다.**

| 칸 | 이름(화면) | 들어가는 `brandSort.group` |
|---:|---|---|
| 1 | **단독형 UHD H 시리즈 (QHC)** | `QHF` **+** `QHC` |
| 2 | **단독형 UHD M 시리즈 (QMC)** | `QMC` |
| 3 | **비디오월** | `Video Wall` |
| 4 | **호텔 TV HU8000F 시리즈** | `Hotel TV` |
| 5 | **비즈니스TV** | `Business TV` |
| 6 | **전자칠판** | `Whiteboard` |
| 7 | **LED 사이니지** | `LED Signage` |

**칸 순서는 `brandSort.order`가 가장 작은 것을 따른다.** 따로 번호를 적지 않는다. 1번 칸은 `QHF`(order 1) 덕분에 맨 앞이다.

사용자가 이름을 댄 것은 **4개(QHC·QMC·비즈니스TV·호텔TV)**다. **나머지 3개(비디오월·전자칠판·LED)도 반드시 남긴다.** 지금 들어갈 수 있는 길을 없애지 않는다.

> **삼성 외 제조사는 묶음표에 넣지 않는다.** 묶음표가 없는 제조사는 **지금과 똑같이** 동작한다.

#### ★ 다음 작업이 붙을 자리를 비워 둔다

[W-20261005-002](W-20261005-002.md)(RTCOM 제품군 탐색)가 **같은 장치를 쓴다.** 서로 다른 두 개를 만들지 않기 위해서다.

RTCOM은 묶음의 출처가 다르다.

| | 삼성 | RTCOM |
|---|---|---|
| 묶음 값 | `catalog.json`의 `brandSort.group` | 동기화된 `product.group` |
| 묶음 이름 | **이 파일의 고정 표** | `rtcom/raw/index.json`의 `groups` |

그래서 `brand-series.mjs`는 **제조사로 갈라지는 모양**으로 만든다. 묶음표를 꺼내는 함수 하나를 밖으로 내보내고, 삼성 갈래만 채운다.

```
seriesGroupsFor(brand, items)  →  [{ id, label, match(item) }]  또는  null
```

**이 작업에서 RTCOM 갈래를 구현하지 않는다.** 나중에 갈래 하나를 더하는 것으로 끝나게만 해 두면 된다.

**이 모양이 어색하면 더 나은 쪽으로 바꿔도 된다.** 지켜야 할 것은 하나다 — **002가 001을 다시 쓰게 만들지 않는 것.**

### 2 · 탐색 상태에 `series`를 더한다

`beta/site/app.js`

- `parseExploreState` — `series: input.get('series') ?? ''`
- `serializeExploreState` — `if (state.series) params.set('series', state.series);`
- `filterCatalog` — `(!state.series || seriesIdFor(item) === state.series)`

**`series`가 비면 지금과 한 글자도 다르지 않아야 한다.** 이것이 W-031 호환의 전부다.

```
?brand=Samsung&sort=brand           → 지금 그대로 18종(선행 작업 뒤에는 늘어난 수)
?brand=Samsung&series=qmc&sort=brand → QMC만
```

`series` 값은 **소문자 영문 id**를 쓴다(`qhc` · `qmc` · `video-wall` · `hotel-tv` · `business-tv` · `whiteboard` · `led-signage`). 화면 이름은 한글이지만 주소에는 넣지 않는다.

### 3 · 고르는 칸을 화면에 붙인다

`beta/site/index.html` **`#results-workspace`(`:44`) 안, `.result-context`(`:45`) 바로 아래**에 `#series-browser`를 넣는다.

- 고른 제조사에 묶음표가 **있을 때만** 보인다. 없으면 `hidden`
- **맨 앞에 `전체` 칸**을 둔다. 누르면 `series`가 빈다
- 각 칸에 **그 묶음의 제품 수**를 함께 적는다 (`#manufacturer-browser`와 같은 모양)
- 지금 고른 칸은 `aria-pressed="true"`
- 생김새는 **`.manufacturer-chip`을 그대로 쓴다.** 새 디자인을 만들지 않는다

`#result-context-title`은 묶음을 고른 동안 **`삼성전자 · 단독형 UHD M 시리즈` 처럼 묶음 이름까지** 적는다 (`contextCopy`, `app.js:167`).

### 4 · 지워져야 할 때 확실히 지운다 ★ 검토 세션이 짚은 자리다

`series`가 엉뚱하게 남으면 **결과가 0건으로 보인다.** 아래를 **모두** 처리한다.

| 언제 | 어떻게 |
|---|---|
| 제조사 칩을 누를 때 (`app.js:219`) | `series: ''` |
| `#brand-filter` 고름이 바뀔 때 | `series: ''` |
| 검색 제안으로 제조사/카테고리를 고를 때 (`stateForSuggestion`, `app.js:63~65`) | **세 갈래 모두** `series: ''` |
| 검색어를 넣을 때 (`submitSearch`, `app.js:222`) | `series: ''` |
| 카테고리 칸을 누를 때 (`app.js:217`) | `series: ''` |
| `#filter-clear` · `#clear` · `#empty-reset` (`app.js:234~236`) | `series: ''` |
| `setFacets`에서 **고른 제조사가 그 묶음을 갖고 있지 않을 때** | `state.series = ''` — `ui.brand.value` 되돌리기와 같은 자리에서 처리 |
| 주소로 바로 들어왔는데 **`series`만 있고 `brand`가 없을 때** | `series` 버린다 |
| 주소로 바로 들어왔는데 **`series` 값이 묶음표에 없을 때** | `series` 버린다 |
| 뒤로가기 (`popstate`, `app.js:237`) | `parseExploreState`를 다시 읽으므로 **위 버리기 규칙이 그대로 걸려야 한다** |

**상세 화면(`detail/`)은 이 상태를 쓰지 않는다.** 상세로 들어갔다 뒤로 오면 `popstate`가 주소에서 되살린다. **상세 쪽 파일은 건드리지 않는다.**
