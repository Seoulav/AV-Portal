## 만들 것

### 1 · 시리즈 묶음표를 한곳에 둔다

새 파일 **`beta/site/shared/brand-series.mjs`**.

제조사별로 `brandSort.group` 값을 묶음 한 칸에 이어 붙인다. **이름은 위 ★ 표에서 확인한 삼성 제목을 쓴다.**

| 칸 | 이름(화면) | 들어가는 `brandSort.group` |
|---:|---|---|
| 1 | **단독형 UHD H 시리즈 (QHC)** | `QHF` **+** `QHC` |
| 2 | **단독형 UHD M 시리즈 (QMC)** | `QMC` |
| 3 | **비디오월** | `Video Wall` |
| 4 | **호텔 TV HU8000F 시리즈** | `Hotel TV` |
| 5 | **비즈니스TV** | `Business TV` |
| 6 | **전자칠판** | `Whiteboard` |
| 7 | **LED 사이니지** | `LED Signage` |

**칸 순서는 `brandSort.order`가 가장 작은 것을 따른다.** 따로 번호를 적지 않는다. 1번 칸은 `QHF`(order 1) 덕분에 맨 앞이다.

사용자가 이름을 댄 것은 **4개(QHC·QMC·비즈니스TV·호텔TV)**다. **나머지 3개(비디오월·전자칠판·LED)도 반드시 남긴다.** 지금 들어갈 수 있는 길을 없애지 않는다.

> **삼성 외 제조사는 묶음표에 넣지 않는다.** 묶음표가 없는 제조사는 **지금과 똑같이** 동작한다.

#### ★ 다음 작업이 붙을 자리를 비워 둔다

[W-20261005-002](W-20261005-002.md)(RTCOM 제품군 탐색)가 **같은 장치를 쓴다.** 서로 다른 두 개를 만들지 않기 위해서다.

RTCOM은 묶음의 출처가 다르다.

| | 삼성 | RTCOM |
|---|---|---|
| 묶음 값 | `catalog.json`의 `brandSort.group` | 동기화된 `product.group` |
| 묶음 이름 | **이 파일의 고정 표** | `rtcom/raw/index.json`의 `groups` |

그래서 `brand-series.mjs`는 **제조사로 갈라지는 모양**으로 만든다. 묶음표를 꺼내는 함수 하나를 밖으로 내보내고, 삼성 갈래만 채운다.

```
seriesGroupsFor(brand, items)  →  [{ id, label, match(item) }]  또는  null
```

**이 작업에서 RTCOM 갈래를 구현하지 않는다.** 나중에 갈래 하나를 더하는 것으로 끝나게만 해 두면 된다.

**이 모양이 어색하면 더 나은 쪽으로 바꿔도 된다.** 지켜야 할 것은 하나다 — **002가 001을 다시 쓰게 만들지 않는 것.**

### 2 · 탐색 상태에 `series`를 더한다

`beta/site/app.js`

- `parseExploreState` — `series: input.get('series') ?? ''`
- `serializeExploreState` — `if (state.series) params.set('series', state.series);`
- `filterCatalog` — `(!state.series || state.series === 'all' || seriesIdFor(item) === state.series)`

**거르는 결과는 `series`가 비었을 때 지금과 한 글자도 달라지지 않아야 한다.**

```
?brand=Samsung&sort=brand             거르는 결과 그대로 · 화면은 시리즈 칸
?brand=Samsung&series=all&sort=brand  거르는 결과 그대로 · 화면은 전체 카드
?brand=Samsung&series=qmc&sort=brand  QMC만
```

`series` 값은 **소문자 영문 id**다.

```
all · qhc · qmc · video-wall · hotel-tv · business-tv · whiteboard · led-signage
```

**`all`은 예약어다.** 묶음 id로 쓰지 않는다. 화면 이름은 한글이지만 주소에는 넣지 않는다.

> **제품 수를 명세에 못 박지 않는다.** [W-20261004-029](W-20261004-029.md)·[-030](W-20261004-030.md)이 삼성 제품을 늘린다. 테스트는 **그때의 카탈로그에서 세어** 비교한다.

### 3 · ★ 어떤 화면인지 먼저 정한다 — **단계형으로 간다**

독립 검토에서 짚은 자리다. 내가 처음에 적은 것은 **전체 목록 위에 칩을 얹는 필터**였다. 사용자가 말한 것은 **단계형 진입**이다.

> **"삼성 → 시리즈/제품군 선택 → 해당 모델 목록 → 상세 진입"**
> **"이런식으로 분류해서 들어가는 구조로 변경하자"**

**사용자 말대로 단계형으로 만든다.**

| 상태 | 결과 영역에 보이는 것 |
|---|---|
| 제조사 고름 + **`series` 비었음** | **시리즈 칸만.** 제품 카드는 **안 보인다** |
| 제조사 고름 + `series=qmc` | **QMC 제품 카드.** 시리즈 칸은 **계속 위에 남는다** |
| 제조사 고름 + **`series=all`** | **그 제조사 전체 카드** |
| 묶음표가 **없는** 제조사 | **지금과 똑같다.** 시리즈 칸 자체가 없다 |

`전체 보기` 칸을 **맨 앞에** 둔다. 누르면 `series=all`이다. **빈 값이 아니라 `all`이라는 명시값**을 쓴다. 그래야 "아직 안 골랐다"와 "전체를 골랐다"가 구분된다.

#### ★ 거르는 일과 보여주는 일을 나눈다

**`filterCatalog`는 지금과 똑같이 둔다.**

```js
// series가 ''이든 'all'이든 거르지 않는다
(!state.series || state.series === 'all' || seriesIdFor(item) === state.series)
```

**카드를 숨기는 것은 `filterCatalog`가 아니라 화면 쪽 판단이다.** 이렇게 나누면 기존 테스트의 `filterCatalog` 결과가 그대로 유지된다.

#### ★ W-031과의 관계를 정확히 적는다

`?brand=Samsung&sort=brand`는 **주소도 결과 집합도 그대로다.** 다만 **첫 화면이 카드 대신 시리즈 칸**이 된다.

> **이것은 호환 깨짐이 아니라 사용자가 요청한 변화다.** W-031이 만든 "제조사 누르면 그 제조사로 간다"는 그대로고, **도착한 화면의 모양**이 바뀐다.

**보고할 때 이 변화를 화면으로 보여 달라.** 사용자가 뜻한 것과 다르면 그때 고친다.

| `#filter-clear` · `#clear` · `#empty-reset` | `app.js:234~236` |

#### 표시 전에 정규화한다 — 순서를 못 박는다

주소에서 읽은 값을 **그리기 전에** 손본다. **순서가 중요하다.**

```
1  parseExploreState   주소에서 읽는다
2  정규화              아래 세 가지를 버린다
3  setFacets / render  그린다
4  saveUrl             손본 결과를 주소에 다시 쓴다
```

##### ★ 허용값을 먼저 적는다 — 초판의 규칙이 서로 부딪혔다

2판에서 `all`을 **예약어**로 정해 놓고, 버리는 규칙에는 **"묶음표에 없는 값은 버린다"**고 적었다. **그대로 만들면 `전체 보기`를 고르는 순간 풀린다.** 규칙끼리 부딪힌 자리다.

**버릴 것을 적기 전에 남길 것을 적는다.**

| 최종 `brand` | 허용하는 `series` |
|---|---|
| 묶음표가 **있는** 제조사 (지금은 삼성) | **빈 값** · **`all`** · **그 묶음표의 id** |
| 묶음표가 **없는** 제조사 | **빈 값만.** `all`도 **버린다** |
| `brand`가 **없음** | **빈 값만.** `all`도 **버린다** |

> **`all`은 묶음 id가 아니지만 허용값이다.** 두 가지를 섞어 판단하지 않는다.

| 버리는 경우 | |
|---|---|
| `brand`가 없는데 `series`가 있다 | 고아 값. **`all`도 버린다** |
| 그 `brand`에 묶음표가 없다 | 다른 제조사 값. **`all`도 버린다** |
| `series`가 `all`도 아니고 그 묶음표의 id도 아니다 | 모르는 값 |

**「최종 `brand`」라고 쓴 이유가 있다.** `setFacets`가 목록에 없는 제조사를 만나면 `state.brand`를 비운다(`app.js:136`). **그 뒤에 남은 `series`도 함께 없어져야 한다.** 제조사를 지우고 시리즈만 남기면 고아가 된다.

**버린 뒤에 그린다.** 그려 놓고 고치면 0건 화면이 한 번 번쩍인다.

`setFacets`가 `ui.brand.value`를 되돌리는 자리(`app.js:135~136`)와 **같은 흐름**에서 처리한다.

#### ★ 이력과 스크롤 — 처음 명세에서 빠졌던 자리다

`render()`는 `replaceState`, `render(true)`는 `pushState`다(`app.js:121~122`).

| | |
|---|---|
| 시리즈 칸 누르기 | **`render(true)`** — 이력에 쌓는다. 뒤로가기로 시리즈 고르는 화면에 돌아올 수 있어야 한다 |
| 누르기 직전 | **`saveScroll()`** — 지금 주소의 스크롤을 저장한다 |
| **같은 칸을 다시 누르면** | **이력을 쌓지 않는다.** 뒤로가기가 제자리걸음이 되면 안 된다 |
| 「유지」 조작들 | **`render()`** — 지금 그대로. `replaceState` |

#### ★ 상세에 갔다 돌아오기 — 길이 **셋**이다

**상세 화면(`detail/`)은 이 상태를 쓰지 않는다. 상세 쪽 파일을 건드리지 않는다.**

2판에 **"새로 읽기와 캐시 복원은 첫 로딩 경로로 들어온다"**고 적었다. **틀렸다.** bfcache는 **문서와 JS 상태를 되살리므로 최초 로딩용 초기화가 다시 돌지 않는다.** 둘을 묶으면 안 된다.

**다만 「아무 일도 안 일어난다」는 뜻이 아니다.** 바로 아래에서 관측하라고 한 `pageshow`가 그 증거다. 복원 이벤트는 일어나고, 멈춰 있던 JS 작업도 다시 움직일 수 있다.

**셋으로 나눈다.**

| 길 | 무엇이 도는가 | 확인할 것 |
|---|---|---|
| **같은 문서 안 뒤로가기** | `popstate` (`app.js:237`) | 다시 읽고 **정규화까지** 걸린다 |
| **문서를 새로 읽음** | 최초 초기화가 처음부터 돈다 | **정규화가 걸린다** |
| **bfcache 복원** | **최초 로딩용 초기화는 다시 돌지 않는다.** 기존 문서·JS 상태가 복원되고, **`pageshow` 같은 복원 이벤트는 일어난다** (멈춰 있던 JS 작업도 다시 움직일 수 있다) | 아래 |

##### bfcache를 어떻게 확인하나

`pageshow`에서 **`event.persisted === true`를 실제로 관측**한다. 그 순간 아래가 **서로 맞는지** 본다.

```
고른 시리즈  ·  주소  ·  보이는 카드  ·  스크롤 위치
```

근거: <https://web.dev/articles/bfcache#observe_when_a_page_is_restored_from_bfcache>

> **리스너를 새로 만들라는 말이 아니다.** 지금 복원 동작으로 네 가지가 이미 맞으면 **그대로 둔다.** **어긋날 때만** 손댄다.

##### ★ 재현이 안 되면 그렇게 보고한다

브라우저·설정에 따라 bfcache가 안 걸릴 수 있다.

> **재현하지 못했으면 「최초 로딩으로 확인했다」로 대신 통과시키지 말고, 재현하지 못했다고 적어 달라.** 둘은 다른 길이다.

#### 검색 제안에서 제품으로 바로 갈 때

`app.js:211`은 `stateForSuggestion`을 **거치지 않는다.** `location.href`로 그냥 떠난다.

> **떠나기 전 목록 주소가 그대로 남아 있는지 확인한다.** 여기서 주소를 덮어쓰면 돌아올 곳이 사라진다.
