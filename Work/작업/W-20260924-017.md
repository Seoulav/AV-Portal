## 범위

### 1. Library ↔ 상세 연결을 데이터로

- `beta/site/catalog.json`의 각 항목에 **안정적인 `slug`** 와 **상세 보유 여부**를 넣는다.
- `detail-links.js`의 하드코딩 Map과 표시 텍스트 매칭을 제거한다. 카드가 자기 `slug`로 상세 링크를 만든다.
- 상세가 있는 제품 수와 실제 `detail/data/*.json` 수가 일치하는지 검사하는 테스트를 추가한다.
- `slug`는 `/^[a-z0-9-]+$/`를 만족해야 한다(상세 화면의 기존 검증과 동일). 중복 불가.

### 2. 공개 게이트를 규칙 기반으로

`beta/verify-pages.mjs`에서 **제품 수·제품별 해시·제품별 허용 호스트를 상수에서 뺀다.** 대신 다음을 유지·강화한다.

- 공개 필드 허용 목록 (`brand`·`categories`·`kind`·`official_links`·`product` + 이번에 추가할 `slug`·상세 보유 여부)
- 상세 JSON의 허용 키 집합 검사 — 지금은 해시로 간접 보장되던 것을 **명시적 키 화이트리스트**로 바꾼다
- 금지 표식 정규식(`privateMarkers`)
- URL 규칙: `https:` 전용, 자격정보 없음, PDF·이미지 확장자 차단
- **제품별 허용 호스트는 상수 대신 규칙으로** — 상세 JSON 안의 모든 `url`/`sourceUrl`이 그 제품의 `official_links` 호스트 또는 그 상위 도메인에 속하는지 검사
- `images` 배열이 비어 있는지, `MISSING` 문서에 `url`이 없는지, `imageStatuses`의 상태값이 허용 집합인지
- 파일 목록은 정확 일치 대신 **허용 패턴**으로 (`detail/data/<slug>.json`만 허용, 그 외 확장자·경로 금지)

제품을 추가할 때 사람이 해시를 고치는 단계가 남아 있으면 이 작업은 완료가 아니다.

### 3. 빌드의 제품 목록을 데이터로

`beta/build-group1-pages.mjs`의 `filenames` Map을 제거하고, 패키지 폴더를 읽어 슬러그를 도출하거나 목록 파일 하나로 관리한다. 어느 쪽이든 **새 제품 추가 시 코드를 수정하지 않는다.**
