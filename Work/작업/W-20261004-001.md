## 문제

사용자가 두 화면을 나란히 놓고 **"아직도 디자인이 다르다"**고 지적했다. **"아직도"**는 이전에도 같은 요청이 있었다는 뜻이다. 이번에는 추정하지 않고 양쪽 소스를 직접 대조했다.

- AV Portal: `beta/site/detail/detail-enhancement-view.mjs` `renderPortMap()` + `beta/site/detail/app.js` `updatePortMap()`
- 알티컴: `rtcom-configurator/src/products.js` `portMapBlock()` + `src/styles.css`

### 번호가 사진을 덮는 것이 "어지러움"의 원인이다

AV Portal은 번호표를 사진 위에 올리고, 겹치면 30px씩 밀어내는 회피 반복문을 돌린다.

```js
let markerY = y + sign*28;
while (placed.some(p => Math.abs(p.x-cx) < 28 && Math.abs(p.y-markerY) < 28)) markerY += sign*30;
```

Lumantek VS10은 단자가 26개라 번호가 기기 사진을 거의 가린다. 알티컴은 사진 위아래에 **40px 여백**을 확보하고 번호를 **그 여백 안**에 둔다. 사진은 절대 가려지지 않는다.

## 알티컴의 그리기 규칙 (옮길 대상)

`products.js:609` `portMapBlock()`.

```
X0 = 40, Y0 = 40
W  = map.displayWidth ? map.displayWidth - 80 : 680
s  = W / 원본가로,  H = 80 + 원본세로 * s
viewBox = "0 0 (W+80) H"
<image x=40 y=40 width=W height=원본세로*s>
```

번호 하나당 (위쪽 기준, `B = Y0` 또는 `Y0 + it.y*s`):

```
괄호   M{x1} {B+8} V{B-6} H{x2} V{B+8}      stroke #007AFF  width 1.5  fill none
지시선 M{cx} {B-6} V{B-14}                   stroke #007AFF  width 1.5
원     <circle cx={cx} cy={B-24} r=10 fill=#007AFF>
숫자   <text x={cx} y={B-20} text-anchor=middle font-size=11 font-weight=700 fill=#fff>
```

아래쪽(`side:"bottom"`)은 부호를 뒤집고 `B = Y0 + 원본세로*s`, 원 중심 `B+24`, 글자 `B+28`.

## 주의

### 클래스 이름은 `rt-` 접두사를 쓰지 않는다

알티컴의 `rt-pg-*`는 그쪽 이름공간이다. AV Portal은 기존 `port-map-*` 이름을 유지하되 **값만** 같게 한다. 이름까지 베끼면 `beta/site/rtcom/` 동기화와 섞인다.

### ★ 가장 큰 위험 — `crop`이 47종 중 25종에 걸려 있다

지금은 사진을 CSS 음수 여백으로 잘라낸다.

```js
featured.style.marginTop    = matches && map.crop ? -map.crop.top    * cropScale + 'px' : '';
featured.style.marginBottom = matches && map.crop ? -map.crop.bottom * cropScale + 'px' : '';
```

SVG 방식에는 음수 여백이 없다. **`<image>`의 `y`를 올리고 `viewBox` 높이를 줄여** 같은 결과를 내야 한다. 알티컴에는 `crop` 개념 자체가 없으므로 **베낄 코드가 없다. 새로 설계해야 하는 유일한 부분이다.**

잘라내는 양이 큰 제품부터 검증하라.

| 제품 | `crop` | 비고 |
|---|---|---|
| `srg-x40uh` | `top 930 / bottom 0` | **한쪽만** 잘라낸다 |
| `dm7` | `top 520 / bottom 570` | 최대 |
| `dci-4-600da` | `top 400 / bottom 360` | 시범 5종 |
| `cdi-*` 12종 | `top 120 / bottom 100` | 가장 많은 묶음 |

**`crop` 25종이 이전과 똑같이 보이지 않으면 이 작업은 실패다.** 먼저 현재 화면을 캡처해 두고 전후를 비교하라.

### `displayWidth`는 우리 데이터에 0건이다

알티컴 코드의 `map.displayWidth` 분기는 **옮기되 동작 확인은 불가능하다.** 기본값 `W=680` 경로만 실제로 검증된다. 보고에 적어라.

### 47종 전부가 대상이다

`portMap`을 가진 제품은 **47종**이다. 한 종만 맞추고 끝내면 안 된다. 실측한 분포는 이렇다.

| 항목 | 종수 |
|---|---:|
| `portMap` 보유 | **47** |
| `crop` 사용 | **25** |
| `side:"bottom"` 포함 | **47 (전부)** |
| `displayWidth` 사용 | **0** |
| 번호 최다 — `vs10` | **26개** |

`side:"bottom"`은 47종 **전부**가 쓴다. 아래쪽 경로가 본선이지 예외가 아니다.

## 미결 사항

- 알티컴은 높이 **88mm(2U) 이상**일 때만 정면·후면 전환 버튼을 둔다. AV Portal은 항상 `Front | Rear` 토글이다. **이번 범위 밖**으로 두고 보고만 한다.
- 알티컴의 `side:"left"|"right"` 세로 괄호는 AV Portal `validMarker`가 허용하지 않는다(`['top','bottom']`만). 벽부형 제품이 생기면 별도 과제다.
