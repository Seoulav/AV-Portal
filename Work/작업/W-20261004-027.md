## A — 모바일에서 상단이 따라다닌다

### 두 페이지가 서로 다르게 돼 있다

| | 모바일에서 |
|---|---|
| **목록** `beta/site/styles.css:113` | `.site-header { position: relative; top: 0; padding: 12px; }` → **안 따라다닌다** |
| **상세** `beta/site/detail/styles.css:136` | `.site-header { position: sticky; }` → **따라다닌다** |

```css
/* beta/site/detail/styles.css */
@media (max-width:650px) {
  .detail-search-toggle { display: inline-flex; }
  .detail-search { position: absolute; top: 100%; … }
  .site-header { position: sticky; }     /* ← 여기 */
  …
}
```

**650px 이하에서 일부러 `sticky`를 다시 박아 놓았다.** 목록 페이지는 같은 자리에서 반대로 풀어 놓았다.

**목록 쪽에 맞춘다.** 상세도 모바일에서 **같이 스크롤되게** 한다.

### 머리말을 지우는 것이 아니다

사용자 말은 **"스크롤할 때 계속 따라다니는 것"**을 없애 달라는 것이다. **머리말 자체를 지우라는 말이 아니다.**

| | |
|---|---|
| **없앤다** | 스크롤해도 **따라다니는 것** |
| **남긴다** | 머리말 **자체.** 맨 위로 올리면 보인다 |
| **남긴다** | **검색창** · **제품 탐색 버튼** |

머리말을 통째로 숨기면 **모바일에서 검색과 목록으로 가는 길이 사라진다.**

### PC는 건드리지 않는다

**650px을 넘는 화면은 지금 그대로** 따라다녀야 한다. 사용자가 말한 것은 **휴대폰**이다.

### 딸린 것 하나

`beta/site/detail/styles.css:6`

```css
section[id], details[id], .source-row[id] { scroll-margin-top: 105px; }
```

**따라다니는 머리말에 가리지 않게** 둔 여백이다. 모바일에서 고정이 풀리면 **필요 없는 여백**이 된다.

**다만 목록 페이지도 `scroll-margin-top: 100px`을 그대로 둔 채 고정만 풀었다.** 따라 하는 것이 일관되다. **고쳐야 한다고 판단되면 근거와 함께 보고하고 고쳐라.** 판단을 맡긴다.

## B — RS-232C 출력 설명이 틀렸다

### 사용자가 바로잡았다

> **"RS232 출력은 MDC랑 연결하는 목적이 아니라 다음 모니터에 RS232 커맨드를 pass through 시킬 때 사용하는 것"**

맞는 말이다. 데이지 체인으로 **다음 디스플레이에 명령을 넘기는 단자**다.

### 지금 입력과 출력에 **같은 문장**이 들어 있다

| 번호 | 라벨 | `desc` |
|---|---|---|
| 9 | RS-232C **입력** | `RS232C 어댑터를 이용하여 MDC를 연결할 때 사용합니다.` |
| 10 | RS-232C **출력** | **같은 문장** |

**삼성 매뉴얼이 두 줄에 같은 설명을 적어 놓았다.** Work가 QMC 20쪽과 115인치 15쪽을 직접 읽어 확인했다. 우리 데이터는 **매뉴얼을 충실히 베낀 결과**다.

**그런데 읽는 사람에게는 틀린 안내가 된다.** 출력에 MDC를 꽂으면 안 된다.

### ★ 우리 데이터 안에 이미 맞는 기록이 있다

**`io` 행은 제대로 적혀 있다.**

```json
{ "connector": "RS-232C 출력", "signal": "외부 제어(루프아웃)", "direction": "OUT", … }
```

**`루프아웃`이 바로 그 뜻이다.** 틀린 것은 **Port Map의 `desc` 하나뿐**이다.

**다른 제조사 제품에도 맞는 표현이 있다.**

```
novastar-h2  7번 RS-232 출력 — "직렬 제어 신호를 다음 장치로 전달합니다."
```

**우리 저장소 안에서 삼성만 어긋나 있다.**

### 대상 — **7종**

| 제품 | 번호 |
|---|---|
| `lh115qhfebgxkr` | 10 |
| `lh32qmcebgcxkr` | 5 |
| `lh43qmcebgcxkr` · `lh85qmcebgcxkr` · `lh98qmcebgcxkr` | 10 |
| `lh43qhcebgcxkr` · `lh75qhcebgcxkr` | 10 |

**입력(9번·4번)은 건드리지 않는다.** 그 문장은 맞다.

### 출처를 사용자 확인으로 남긴다

**매뉴얼에 없는 문장을 매뉴얼 출처로 달면 안 된다.**

저장소에 이미 쓰는 방법이 있다.

```json
{ "code": "U1", "name": "사용자 현장 확인(2026-10-04) — VXT Player 지원 여부", … }
```

**같은 방식으로 적는다.** 새 코드를 만들든 `U1`의 범위를 넓히든 **Codex가 정하되, 사용자 확인임이 드러나야 한다.**

### 문장은 Codex가 정한다

뜻만 지키면 된다.

- **다음 디스플레이로 RS232 명령을 넘긴다**는 것
- **MDC를 꽂는 자리가 아니라는** 것
- `novastar-h2`의 **"다음 장치로 전달합니다"**와 결이 맞게

`desc`는 **사람이 읽는 글**이다. 짧고 분명하게.

- **매뉴얼을 그대로 베끼는 것과 읽는 사람에게 맞게 적는 것**이 부딪히는 첫 사례다. 이번은 **사용자가 직접 바로잡아** 근거가 분명하다. **앞으로 같은 일이 생기면 사용자에게 묻는다.** Work가 임의로 고치지 않는다.
