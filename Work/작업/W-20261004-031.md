## A — 제조사 이름이 링크가 아니다

`beta/site/detail/index.html:37`

```html
<nav class="breadcrumb"><a href="../">Equipment Library</a><span>/</span>
  <span id="breadcrumb-brand"></span><span>/</span><strong id="breadcrumb-model"></strong></nav>
```

`app.js:94`

```js
$('#breadcrumb-brand').textContent = data.manufacturer;
```

**`Equipment Library`는 링크인데 제조사는 그냥 글자다.** 눌러도 아무 일이 없다.

### 갈 곳은 이미 있다

목록 쪽이 **`?brand=…&sort=brand`**를 받는다. Work가 확인했다.

```
https://seoulav.github.io/AV-Portal/?brand=Samsung&sort=brand
```

[W-20261004-022](W-20261004-022.md)로 **삼성은 제품군 순서로** 나온다. **새로 만들 것이 없다.**

### "모든 영역으로 확대" — 제조사가 나오는 자리

Work가 `app.js`를 훑었다.

| 줄 | 자리 | 지금 | 링크로? |
|---|---|---|---|
| `:94` | **브레드크럼** `#breadcrumb-brand` | `<span>` 글자 | **그렇다** — 사용자가 지목 |
| `:99` | **MANUFACTURER 카드** `#footer-manufacturer` | `<strong>` 글자 | **그렇다** |
| `:97` | 제목 밑 `#product-subtitle` | `제조사 · 시리즈 · 분류` **한 덩어리** | **판단해 보고하라** |
| `:98` `:100` | 바닥글·대화상자 제목 | `제조사 모델명` 한 덩어리 | **아니다** |

**`:97`은 `[manufacturer, subtitle].join(' · ')`로 만든다.** 쪼개서 앞부분만 링크로 할 수 있지만, **글이 많은 자리라 링크가 늘면 어수선해질 수 있다.** 직접 보고 판단하라.

**`:98`·`:100`은 제품 이름의 일부**라 링크로 만들면 뜻이 흐려진다. 건드리지 마라.

### 지킬 것

- **제조사 이름을 그대로** 넘긴다. `Samsung` · `NETGEAR` · `BSS Audio`처럼 띄어쓰기·대소문자가 있는 것도 있다. **주소로 만들 때 제대로 인코딩**하라
- **목록 쪽에서 그 제조사가 실제로 걸러지는지** 확인하라. 이름이 어긋나면 빈 화면이 된다
- **눌러서 가는 곳이 보이게** 한다. 글자색이나 밑줄로 링크임이 드러나야 한다
- 키보드로도 **닿아야** 한다

## B — 돋보기를 1.2배 키운다

`beta/site/detail/app.js:293`

```js
const LOUPE_SIZE = 180, LOUPE_ZOOM = 3;
```

`beta/site/detail/styles.css:117`

```css
.image-loupe { position: absolute; width: 180px; height: 180px; … }
```

**같은 180이 두 곳에 따로 박혀 있다.** 한쪽만 고치면 **원이 어긋난다.**

### 무엇을 키우나

사용자 말은 **"돋보기가 크기 1.2배"**다. **배율이 아니라 원의 크기**다.

```
180px  →  216px
```

**`LOUPE_ZOOM`(=3)은 건드리지 않는다.** 들여다보는 배율은 그대로다.

### 어디를 키우나

사용자가 말한 것은 **"제품 확대 보기시"** — `확대 보기` 버튼으로 여는 대화상자다.

**그런데 `LOUPE_SIZE`는 두 군데가 같이 쓴다.**

| 자리 | |
|---|---|
| `app.js:314` **확대 보기 대화상자** | **키운다** |
| `app.js:319` **02 Port Map** | **사용자가 말하지 않았다** |

**둘을 나눌지 같이 키울지 판단해 보고하라.** Work의 의견은 **같이 키워도 된다**는 쪽이다 — 같은 기능이 자리마다 크기가 다르면 오히려 어색하다. 다만 **Port Map에서 원이 커지면 가려지는 부분도 커진다.** 실제로 보고 정하라.

### 두 곳이 어긋나지 않게

**앞으로 또 한쪽만 고치는 일이 없게** 하라. CSS 변수로 묶든 JS에서 크기를 넣든 **방법은 정하되, 검사로 고정하라.**
