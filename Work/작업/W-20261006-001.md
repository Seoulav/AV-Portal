## ★★ 가장 중요한 제약 — 01 카드는 최대 4개다

```js
// beta/site/detail/detail-enhancements.mjs:103
keyFacts: Array.isArray(product.keyFacts) && product.keyFacts.length <= 4 && ...
```

**16종 중 11종이 이미 4개로 꽉 차 있다.** 임피던스를 그냥 더하면 **5개가 되어 카드 전체가 사라진다.**

### 그래서 지우지 말고 합친다

| | |
|---|---|
| **하지 마라** | 커버리지 각도·주파수 범위를 **지워서 자리 만들기** |
| **하라** | **임피던스와 전력을 한 항목에** 담는다 |

사용자가 요청한 것은 **"몇 옴 몇 와트"**다. 스피커에서 이 둘은 **같이 읽는 값**이다. 한 줄에 담는 것이 요청에 더 맞고 **기존 정보를 하나도 잃지 않는다.**

```json
{ "label": "공칭 임피던스 · 연속 프로그램 전력", "value": "8 Ω · 60 W", "unit": "" }
```

`validFact`는 `label`·`value`·`unit` 세 키만 요구한다(`detail-enhancements.mjs:10`). **이 형태로 통과한다.**

## 제품별로 할 일

### 가) 전력 항목이 **이미 01에 있는** 11종 — 그 항목을 고친다

`412C/T` · `414C/T` · `416C/T` · `418C/T` · `447C/T` · `419CS/T` · `440CS/T` · `424C/T` · `424LP` · `426LP` · `AC18/26`

현재 **`연속 프로그램 전력 · 2시간` = `60 W`** 같은 모양이다. **여기에 임피던스를 붙인다.**

| | |
|---|---|
| 개수 | **4개 그대로** |
| 나머지 3개 | **건드리지 마라** — 감도·커버리지 각도·주파수 범위 |

> `AC18/26`만 전력 항목 이름이 **`시스템 전력 · AES`**다. **그 이름을 살려서** 합쳐라.

### 나) 01에 전력이 **없는** 5종 — 한 항목을 **더한다**

지금 3개라 **자리가 있다.**

| 제품 | 임피던스 | 읽어 올 사양 행 |
|---|---|---|
| Control 23-1 | `8` | `전력 정격` = `100W 컨티뉴어스 프로그램(2시간) …` |
| Control 25-1 | `8` | `전력 정격` = `200W 컨티뉴어스 프로그램(2시간) …` |
| Control 28-1 | `8` | `전력 정격` = `240W 컨티뉴어스 프로그램(2시간) …` |
| AC18/95 | `8` | `시스템 전력 정격` = `250W 컨티뉴어스 핑크노이즈 / 500W 프로그램 / 1000W 피크` |
| CONTROL 426C/T | `12` | `전력 용량` = `110W(피크 440W) 컨티뉴어스 핑크노이즈(2시간) …` |

> **원문이 길다. 01 카드는 한눈에 보는 자리다.** 대표 수치 하나만 골라 쓰고 **어느 수치를 골랐는지 `label`에 드러내라.**
>
> 예: `공칭 임피던스 · 연속 프로그램 전력(2시간)` → `8 Ω · 100 W`
>
> **값을 바꾸지 마라.** 원문에 없는 수를 만들지 말고, 고른 근거를 보고에 적어라.
