## 목표와 현재 동작

공개 RTCOM 목록을 고르면 지금은 제품명 정렬 카드가 바로 나온다. 동기화된 `beta/site/rtcom/raw/index.json`에는 `groups`의 이름·순서와 각 `products[].group`이 이미 있지만 `adaptRtcomCatalog()`가 탐색용 소속·순서를 전달하지 않는다. 포털에서 RTCOM에 진입하면 삼성 W-001과 같은 선택 단계에서 **전체 보기 + 원본 5개 제품군**을 고르고, 그다음 기존 항목 카드와 상세·자료 링크로 이동하게 한다.

현재 사본은 `series` 3, `integrated` 2, `distribution` 8, `extender` 15, `cable` 4로 **항목 32개**다. `series`의 XDM·SPX·VDM은 독립 모델이 아니라 제품군 항목이다. 이 수치는 착수 시 실측 기준이며 미래 항목 수를 영구 고정하지 않는다. `lineup` 행, 송수신 쌍, 케이블 길이를 독립 모델로 만들지 않는다.

원본 목록의 그룹 이름과 순서는 `index.groups`의 키·값, 각 카드의 소속은 `products[].group`에서 읽는다. 제품명 규칙·카테고리로 재분류하지 않는다. 원본 `index.products` 순서를 RTCOM의 **기본 제조사 정렬**에 반영한다. 사용자가 제품명·관련도 정렬을 직접 고르면 해당 선택을 존중한다. 현재 첫 254개 AV 항목의 순서와 삼성 22종 시리즈 동작을 바꾸지 않는다.

## 사용자에게 보이는 계약

| 주소·행동 | 결과 |
|---|---|
| `?brand=RTCOM&sort=brand` | 제품 카드 대신 `전체 보기`와 원본 순서의 5개 제품군 선택, 실제 항목 수 표시 |
| `?brand=RTCOM&series=series&sort=brand` | XDM·SPX·VDM **시리즈 항목 3개**. 각 항목의 기존 포털 상세·문서 링크 유지, 원본 구성기 `#products/<id>` 링크 유지 |
| `?brand=RTCOM&series=distribution&sort=brand` | 현재 분배기·선택기 8개. 포함 대상 `HD-104U`·`HD-108U` 유지 |
| `?brand=RTCOM&series=all&sort=brand` | 현재 RTCOM 항목 32개 전체. `전체`는 여섯 번째 제품군이 아님 |
| 모르는 `series`, 브랜드 없는 `series`, 삼성 URL | W-001 정규화 계약을 유지. 잘못된 RTCOM 값은 제거, 삼성 7칸은 그대로 |

선택은 W-001처럼 URL과 브라우저 이력에 남는다. 직접 주소·새로고침·뒤로/앞으로가기·상세에서 복귀해도 선택, 카드, 스크롤이 맞아야 한다. 결과 내 검색·세부 분류·자료 필터·정렬은 선택한 `series`를 유지하고, 제조사 칩·제조사 선택·상단 검색·상위 분류·초기화 경로는 해제한다. `series`를 삼성과 RTCOM이 함께 쓰되 각 제조사의 유효 그룹으로만 정규화한다. `series`가 없는 다른 제조사는 기존 카드 목록으로 바로 들어간다.

기존 포털 상세 URL·문서·관련 제품·공식 링크와 검색 결과를 보존한다. XDM 등의 메인프레임·입출력 카드 **선택·구성은 포털에서 만들지 않는다**. 기존 원본 링크로 RTCOM 구성기에 들어간다. `rtcom-xdm-...`처럼 원본 id가 없는 상세 주소를 만들지 않는다.

## 구현 경계와 자료 검증

- 공개 목록의 어댑터·시리즈 그룹 선택·정렬·URL 상태와 그 검사만 변경한다. 예상 경로는 `beta/site/shared/rtcom-adapter.mjs`, `beta/site/shared/brand-series.mjs`, `beta/site/app.js`, 필요한 목록 CSS/HTML, `tests/rtcom-adapter.test.mjs`와 신규 탐색 검사다. 실제 범위는 구현 PR에서 증명한다.
- RTCOM `raw/index.json`·`raw/products/*.json`, `SYNC.json`, 원본 RTCOM 사이트·Logic, 254개 AV 카탈로그/제품 JSON, 기존 상세 렌더러·문서 자산은 변경하지 않는다. 이번 작업은 **동기화를 실행하거나 원격 문구 차이를 손으로 덮지 않는다**.
- `validateRtcomIndex` 또는 동기화의 후보 검증 단계에서 `groups`가 비어 있거나 제품의 `group`에 대응하는 비어 있지 않은 이름이 없으면 **후보 승격 전에 실패**하게 한다. 알 수 없는 그룹을 조용히 숨기거나 임의의 그룹으로 옮기지 않는다. 이 검증은 포털 사본 보호이고 원본 RTCOM Logic 수정이 아니다. 기존 제외 정책 `HS-88M-U`, `HS-88MX`, `HD-D104U`, `HD-D108U`를 유지한다.
- `HD-104U`·`HD-108U`는 위 제외 모델과 다른 정상 포함 대상이다. ID·모델을 글자 그대로 비교한다.
- 그룹 항목 수와 총수는 실제 유효 목록에서 계산한다. `3/2/8/15/4`와 `32`는 이번 스냅샷 회귀 기준으로 기록하되, 정상 동기화로 항목이 늘어나는 것을 영구 고정 테스트로 막지 않는다.
- 원본과 현재 사본의 요약 문구 차이는 [조사 기록](../기록/W-20261005-002-조사기록.md)에 이미 있다. 이번 탐색 구현과 섞지 않는다.
