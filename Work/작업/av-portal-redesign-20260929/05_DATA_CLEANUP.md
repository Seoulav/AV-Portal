# 5단계 — 데이터 이름 정리 (카테고리·그룹)

- 선행: 4단계 완료·사용자 확인
- 바꾸는 것: `catalog.json`·`detail/data/*.json`의 **이름 표기만**(카테고리, 사양 그룹, 연결 단자 그룹), 다시 만든 `search-index.json`
- 바꾸지 않는 것: 사양 값, 수량, 단위, 조건, 출처, 검증 상태, 설명 문장
- 이 단계는 데이터를 바꾸므로 **대응표를 먼저 사용자에게 승인받은 뒤** 적용합니다.

## 1. 문제 (2026-09-29 집계)

- 카테고리 71종: 한글·영문이 섞이고 같은 뜻이 따로 세어짐(마이크로폰/Microphone, 프로젝터/Projector 등)
- 사양 그룹 이름 173종
- 연결 단자 그룹에 신호 종류와 방향이 섞임(Video·Audio와 Input·Output·Audio In이 같은 칸)

## 2. 절차

1. **대응표 초안 작성**: `Work/작업/<작업ID>-mapping.md`에 표 세 개를 만듭니다.
   - 카테고리: 현재 이름 → 정리 이름 → 해당 제품 수
   - 사양 그룹: 현재 이름 → 정리 이름 → 해당 행 수
   - 연결 단자 그룹: 현재 이름 → 신호 그룹(Video·Audio·Network·Control·USB·Power·RF·Data) → 방향이 섞인 경우 `direction`으로 옮길 값
2. 정리 원칙
   - `categories` 배열의 관례(첫 항목 한글 대분류, 이어서 영문 분류)를 유지하고, 같은 뜻의 중복만 합칩니다.
   - 영문 분류 이름은 하나의 표기로 통일합니다(예: `Microphone`).
   - 연결 단자 그룹 이름이 Input·Output·Audio In처럼 방향을 담고 있으면, 신호 그룹으로 바꾸고 `direction`이 비어 있을 때만 방향을 옮겨 적습니다. `direction`에 이미 값이 있으면 그 값을 우선합니다.
3. **사용자 승인** 뒤 스크립트로 일괄 적용합니다(손으로 파일을 하나씩 고치지 않습니다). 스크립트는 저장소에 남깁니다.
4. `search-index.json`, `catalog.html`, `llms.txt`처럼 데이터에서 만들어지는 파일을 다시 만듭니다.

## 3. 검증

1. 적용 전·후 카테고리 수, 사양 그룹 수, 연결 단자 그룹 수 비교표
2. 값 필드(`value`, `unit`, `quantity`, `condition`, `source`, `verification`)가 한 글자도 바뀌지 않았음을 스크립트로 확인
3. 홈 카테고리 개수와 필터 결과가 대응표와 맞는지 확인
4. 상세 화면 대표 4종 캡처가 2단계 캡처와 비교해 이름만 바뀌었는지 확인

## 4. 이 단계에서 하지 않는 것

- 주요 기능 문장 어투 통일(730건이 "~다."로 끝남): 문장 내용을 바꾸는 일이라 별도 결정이 필요합니다. 하려면 사용자에게 먼저 묻습니다.
- 관련 제품 데이터 추가: 근거 조사가 필요한 별도 작업입니다.
