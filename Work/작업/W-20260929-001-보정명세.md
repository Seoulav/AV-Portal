## 1. 1단계 디자인 기반 — 지금 확정된 범위

1. `PretendardVariable.woff2`·OFL과 공통 디자인 토큰/부품은 1단계에서 준비한다. **새 글꼴·스타일의 시각 적용은 견본에만** 한다. 실제 홈·상세 화면은 1단계에서 원래 레이아웃과 본문 글꼴을 유지하며, 각각 3단계·2단계에서 새 디자인을 적용한다. 공통 CSS를 연결하더라도 전역 `body` 배경·글자색·font-family 등으로 기존 화면을 바꾸지 않도록 범위를 한정한다.
2. 견본 화면은 저장소 안의 로컬 견본으로 만든다. **공개 `beta/site/`와 Pages 아티팩트에는 넣지 않는다.** 공통 CSS/글꼴은 후속 실제 화면에서 사용할 자산이므로 `beta/site/`에 둘 수 있다. 견본의 위치·상대 경로·로컬 미리보기는 구현 때 검증한다.
3. 가독성 보정을 허용한다: 모든 화면의 새 디자인 글자는 **최소 11px**이며 원문의 10.5px 지정은 11px로 바꾼다. 대비, 긴 문구 줄바꿈, 좁은 칸의 열 수를 보정할 수 있다. 색상 토큰, 모서리 반경, 글래스 카드, 카드 번호 체계, 01~07 배치는 유지한다. 기존 화면의 글꼴·구성을 1단계에서 바꾸기 위한 예외는 아니다.
4. 1단계 완료 증거는 로컬 견본 1280px·390px 캡처, 견본에서 Pretendard 실제 로딩, 기존 홈·상세 회귀 확인, 공개 Pages에 견본이 없다는 검사다. 실제 홈·상세의 Pretendard 적용 확인은 2·3단계에서 한다.

## 2. 2단계 상세 화면 — 배치·표시·근거

1. 카드 HTML의 DOM 순서는 **01→07**이다. PC에서만 grid 영역으로 원문의 왼쪽 01/04/05, 오른쪽 02/03/06/07 배치를 만든다. **721~1000px는 1열 01→07**, 720px 이하도 1열 01→07이다. CSS `order`로 DOM/키보드 순서를 뒤섞지 않는다. 숨긴 카드가 있으면 남은 번호는 그대로 둔다.
2. 연결 단자 카드 격자는 `repeat(auto-fill, minmax(180px, 1fr))`를 사용한다. 좁은 화면에서는 칸 수가 자동으로 줄어들며, 이름·조건은 읽을 수 있게 줄바꿈한다. 가로 넘침을 확인한다.
3. 단자 색은 `signal`/`protocol`의 명시적 근거를 우선한다. 그것으로 판정할 수 없으면 중립색으로 표시한다. 커넥터 외형(BNC, RJ-45, XLR 등)만으로 SDI·네트워크·오디오 신호를 확정하지 않는다.
4. 단자 표시에는 현재 `connectorPresentation`의 `portCount`, `channelSignal`, `specificationCondition`, `flags`를 재사용한다. 물리 포트 수 미확인과 채널 수를 분리한다. 옵션·카드/모듈 필요 조건을 해당 카드/표 행에서 읽을 수 있게 한다. 전체 단자 표에는 원래의 출처·검증 상태 접근을 유지한다.
5. 문서는 현재 접근 가능한 `FOUND`·`VERIFIED`·`READY` 상태를 유지한다. 새 디자인을 이유로 기존 READY 링크가 사라지지 않도록 검사한다. MISSING은 열기 버튼을 만들지 않는다.
6. `CONFLICTED`, 옵션, 제품·기능 적용 조건은 해당 사양·단자·문서 **행 안에서** 계속 확인할 수 있어야 한다. 패키지 전체 상태와 이미지 권리 문구만 하단의 자료 출처·검증 기록으로 옮긴다. 행별 상태를 하단 한곳으로 일괄 이동하지 않는다.
7. 제품별 근거가 없는 Port Map 번호·Signal Flow·EDID/딥 스위치 도식은 생성하지 않는다. 번호 카드 레이아웃만 공통 적용한다. 없는 카드 해시의 이동과 인쇄 전체 내용은 [사전 검토](W-20260929-001-사전검토.md)의 검증 항목을 따른다.

## 3. 3단계 홈·목록

1. 새 글꼴·공통 디자인을 실제 홈에 적용하는 시점은 3단계다. 1단계에서 준비한 토큰·글꼴을 사용한다.
2. 기존 검색·필터·정렬·주소 동작과 이미지/요약의 근거 상태를 보존한다. 첨부 원문의 데이터 무변경 원칙과 [사전 검토](W-20260929-001-사전검토.md)의 경로 보정을 따른다.

## 4. 4단계 검색 인덱스

1. 매 실행마다 달라지는 `generatedAt`을 쓰지 않는다. **원본 데이터의 안정적인 해시**를 저장하거나 생성 시각 필드를 제외한다. `--check`가 동일 입력에서 결정적으로 통과해야 한다.
2. 성능 비교에서는 **데이터 요청 수/용량**과 **이미지 요청 수/용량**을 따로 측정한다. 전체 요청 수만으로 목표 달성 여부를 판단하지 않는다.
3. 기존 검색 결과, 추천, 정렬, 별칭, 필터, `?q=` 동작을 유지한다. 상세가 없는 카탈로그 항목도 검색·카드 표시에서 누락하지 않는다. 저장된 인덱스가 없거나 손상됐을 때의 기존 로더 복구를 검증한다.

## 5. 5단계 데이터 이름 정리

1. 이 단계의 변경은 승인된 카테고리·사양 그룹·연결 단자 그룹 **이름 표기**에 한정한다. `direction` 빈칸 채우기는 **이번 범위에서 제외**한다. 원문의 해당 제안은 실행하지 않는다.
2. 대응표는 먼저 사용자에게 확인받고, 그 뒤 이름 변경을 적용한다. 신호 종류나 방향을 그룹 이름만으로 추측하지 않는다.
3. 공개 `beta/public-snapshot.json`, 필요한 고정 해시·검사, `catalog.html`·`llms.txt` 및 4단계 검색 인덱스의 재생성 영향은 작업 범위에 포함한다. 현재 공개 기준 25개의 보호값은 실제 변경과 승인 범위를 따져 갱신 여부를 판단하며 기계적으로 덮어쓰지 않는다. 값·수량·단위·조건·출처·검증 상태는 보존한다.

## 6. 6단계 RTCOM 읽기 연동

1. RTCOM에서 받은 **원본 JSON의 바이트와 SHA**를 보존한다. Portal 화면에 필요한 기본 presentation, 링크, 로컬 파일 주소, `rtcom-<id>` slug 등은 별도의 **표시용 어댑터**에서 처리한다. 원본 파일을 수정해 두 형식을 억지로 같게 만들지 않는다.
2. 동기화는 같은 시점의 목록·상세·이미지 세트가 모두 검증된 뒤에만 새 정상본으로 교체한다. 문서(PDF)는 [6단계 원문](av-portal-redesign-20260929/06_RTCOM_INTEGRATION.md) 2장대로 RTCOM 공개 주소로 **링크만** 하고 AV Portal에 복사하지 않는다. 동기화 때는 상세 JSON의 `documents[].file`이 가리키는 공개 주소가 열리는지만 검사한다. PDF 복사가 필요해지면 권리 근거와 함께 사용자에게 별도로 묻는다. 일부 실패하면 **마지막 정상본을 유지**한다. 시점이 다른 파일이 한 배포물에 섞이지 않도록 검증한다.
3. 기존 제외 모델 정책과 공개 자료/권리·비공개 정보 배제 정책을 유지한다. 현재 피드 31종은 구현 시 다시 확인하며 고정 상수로 삼지 않는다.
4. **`catalog.html`·`llms.txt`에 RTCOM 제품을 넣을지는 6단계 시작 전에 사용자에게 다시 묻는다.** 지금 결정된 것으로 처리하지 않는다.
