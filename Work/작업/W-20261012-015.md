## Work가 원인을 확정했다 — 동기화 문제가 아니다

`beta/site/rtcom/raw/products/qms-88ux.json`과 구성기 원본 JSON을 바이트
대조했더니 **완전히 같다.** 다른 것은 화면이다: 변환기
`beta/site/shared/rtcom-adapter.mjs`의 `adaptRtcomDetail`이 원본 필드 중
**`portMap`·`videoModes`·`audioOutFlow`·`catalogPages`·`officialLinks`를
버린다.** 그래서 구성기에 있는 02 PORT MAP·비디오 모드·오디오 흐름이
포털 상세에 없다.

## 할 일 — 버리는 필드를 포털 상세 구조로 넘긴다

1. **portMap** — 원본 좌표·항목을 포털 상세의 `portMap`(validMap 규약)으로
   전달. 좌표 체계가 다르면 원본 이미지 크기 기준으로 변환하고, 렌더
   결과를 `portmap-audit`로 눈 확인. **원본 값을 고치지 않는다** — 못
   넘기는 항목은 사유 보고.
2. **videoModes** — 상세 보조 섹션 `modes`(detail-enhancements의 'modes'
   kind)로 매핑하거나, 구조가 안 맞으면 표 형태 제안 후 보고.
3. **audioOutFlow** — signalFlow 또는 보조 섹션으로 매핑. 무리한 끼워
   맞춤 금지 — 안 맞으면 어떤 구조가 필요한지 보고.
4. **officialLinks** — documents/공식 링크로 병합 (허용 호스트 검사 유지).
5. `catalogPages`는 내부 참고 값이면 버려도 된다 — 판단 근거를 보고.
6. 변환기 단위 시험(rtcom-adapter 쪽 기존 시험)에 새 필드 보존을 고정.

## 테두리

- **원본 우선 원칙**: 포털 쪽에서 RTCOM 값을 손으로 고치지 않는다. 항상
  구성기 동기화 본에서 변환만 한다. (동기화 자동화 복구는 별도 —
  저장소 설정은 소유자 액션 대기 중.)
- 원본 페이지 링크('알티컴 제품정보에서 자세히 보기 ↗')는 유지한다.
- RTCOM 32종 전체에 적용하되, 필드가 없는 제품은 섹션을 만들지 않는다.
- 렌더러 변경은 RTCOM 전달 경로에 한정 — 다른 제조사 상세 불변 증명.
