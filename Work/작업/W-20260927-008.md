## 범위

- 변경할 파일·영역:
  - `beta/site/catalog.json`
    - `Duecanali 804 DSP+D`의 `official_links[0]`을 정확 변형 페이지로 교체한다.
    - `link_scope: series`는 제거한다. 교체 URL이 정확한 Model 804 + Version DSP+D 페이지이므로 모델 단위 링크다.
    - `EB-PU1008B`는 기준 main에서 이미 후보 URL과 일치하므로 무변경 확인 대상으로 둔다. 구현 기준 main에서 404 단축 URL이면 후보 URL로 교체한다.
  - `docs/research/equipment-listing-decisions-2026-09-25.json`
    - 두 항목의 `official_urls`를 확인된 정확 URL과 일치시킨다.
    - 두 항목에 `url_corrected`를 추가한다. 기존 GSM4212P 형식(`corrected_at`, `previous_urls`, `reason`, `work_id`)을 그대로 따른다.
    - EB-PU1008B의 `verification`은 현재 유효한 한국엡손 상세 페이지를 확인했다는 의미로 갱신한다.
    - Duecanali 804 DSP+D의 `verification`을 정확 변형 페이지 확인 결과에 맞춰 갱신하고, `grade`는 `B`에서 `A`로, `link_scope`는 `series`에서 `model`로 변경한다. 결정표의 `series_rule`에 따라 B등급은 모두 series 범위이므로 정확 모델 페이지가 확인된 이 항목은 A/model이어야 한다. 다른 Powersoft 항목으로 확대 적용하지 않는다.
    - 상단 `counts`의 A/B 집계를 `177/79`에서 `178/78`로 갱신한다. 전체 합계와 다른 등급 집계는 유지한다.
  - `beta/public-snapshot.json`
    - 공개 카탈로그가 실제로 변경되면 `node beta/update-snapshot.mjs`로 카탈로그 SHA를 갱신한다. 두 대상은 카탈로그 인덱스 148·221로 기준 25개 밖이므로 `baselineSha256`은 바뀌지 않아야 한다.
  - `beta/site/catalog.html`, `beta/site/llms.txt`
    - 직접 편집하지 않고 공개 `catalog.json` 변경 뒤 `node beta/build-readable-catalog.mjs`로 재생성한다.
    - `tests/readable-catalog.test.mjs`가 `catalog.json`의 모든 `official_links`가 `catalog.html`의 `href`에 존재하는지 검사하므로 두 생성물을 구현 PR에 포함한다. 재생성하지 않으면 `npm test`가 실패하는 것을 2026-09-27 재현 확인했다.
    - PR #101·#104·#105에서 적용한 것과 같은 생성 절차를 따른다.
- 변경하지 않을 영역:
  - 두 제품의 상세 JSON, 이미지, 문서, Features, Specifications, I/O
  - 다른 제품 링크와 결정표 항목
  - 위 재생성 대상 외 코드·UI·생성물 직접 편집
  - Group 1 고정 상세 JSON 5개와 `tests/verification-ui.test.mjs`의 Git blob 해시
  - `Work/지시서.md`는 Codex 구현 단계에서만 해당 작업의 진행 기록을 추가한다.
- 유지해야 할 결정:
  - 공식 제조사 HTTPS 링크만 사용한다.
  - 제목·본문에서 정확 모델과 변형이 확인되지 않으면 추측해 교체하지 않는다.
  - 과거 URL은 삭제 이력 대신 `url_corrected.previous_urls`에 보존한다.
  - PR #107이 먼저 병합되면 최신 main을 통합한 뒤 같은 파일의 다른 항목 변경을 보존한다.

## 검증 방법

1. 두 URL을 열어 제조사 도메인, HTTPS, 페이지 제목과 본문 모델 표기를 확인한다.
2. JSON을 파싱해 두 제품의 카탈로그·결정표 URL과 `url_corrected` 구조를 비교한다.
3. 변경 전후 `beta/site/detail/data/{brc-am7,dm7,ki-pro-go2,pt-mz17k,rally-bar}.json`의 Git blob이 같음을 확인한다.
4. 공개 카탈로그가 변경되면 `node beta/update-snapshot.mjs`를 실행하고 `baselineSha256` 불변을 확인한다.
5. `node beta/build-readable-catalog.mjs`를 실행해 `catalog.html`과 `llms.txt`를 재생성하고, `catalog.json`의 모든 공식 링크가 읽기용 카탈로그에 반영됐는지 확인한다.
6. `npm test`, `node beta/verify-pages.mjs`, `git diff --check origin/main...HEAD`를 실행한다.

기준 main에서 `npm test`는 100건 중 99 pass·1 skip·0 fail이다. skip은 비공개 제품 목록 경로를 지정할 때만 실행되는 기존 조건부 검사다.
