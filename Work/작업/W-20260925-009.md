## 범위

`beta/site/catalog.json`에 **156개 항목을 덧붙인다.** 기존 27개는 값·순서 모두 건드리지 않는다.

각 항목은 다섯 필드만 갖는다. 상세가 없으므로 `slug`·`card_image`는 넣지 않는다.

```json
{
  "brand": "<manufacturer>",
  "product": "<model>",
  "categories": ["<1단>", "<2단>", "<3단>"],
  "kind": "equipment",
  "official_links": ["<선택된 공식 URL 1개>"]
}
```

### 대상 선정

결정표 `entries`의 177행에서 다음을 뺀 **156행**이 대상이다.

- 제조사가 특정되지 않은 2행 (`manufacturer`이 `null`)
- 현재 공개 27개와 제조사·모델이 같은 19행

판정은 `manufacturer`·`model`을 소문자로 바꾸고 영숫자 외 문자를 제거해 비교한다. 결과 건수가 156이 아니면 **멈추고 보고한다.** 숫자를 맞추려고 규칙을 바꾸지 않는다.

### 필드 값

- `brand`·`product`: 결정표의 `manufacturer`·`model`을 **그대로** 쓴다. 표기를 정리하거나 추측해 바꾸지 않는다.
- `categories`: 결정표의 `categories`를 그대로 쓴다. 2단은 `Audio`·`Video`·`Display`·`Control`·`Network`·`Conferencing` 여섯 개뿐이다. 다른 값이 나오면 오류다.
- `official_links`: `official_urls`가 한 개면 그것. 여러 개면 **제조사 한국 도메인**(`.co.kr` 또는 경로에 `/sec/`·`/ko/`)을 먼저 고르고, 없으면 첫 번째를 쓴다. 항상 한 개만 넣는다.
- 추가 정렬을 하지 않는다. 기존 27개 뒤에 결정표 순서대로 붙인다.

### 변경하지 않을 영역

- 기존 27개 항목의 값과 배열 위치
- 상세 5개(`beta/site/detail/`) — 파일도 데이터도 건드리지 않는다
- `beta/group1-images.mjs`, `beta/manufacturer-hosts.mjs` — 상세가 없는 항목에는 해당 없다
- 검증 로직(`beta/verify-pages.mjs`) — W-017로 이미 데이터 기반이다. **이 작업에서 코드를 고쳐야 한다면 W-017이 덜 된 것이므로 멈추고 보고한다.**
- B등급 79행·C등급 12행 — 이번에 올리지 않는다
- RTCOM 65행 — 제조사 직접 제공 자료 정책 대상이라 별도 작업이다
- 카테고리 3단 계층 정리(W-20260924-011) — 기존 2단짜리 두 항목은 그대로 둔다
