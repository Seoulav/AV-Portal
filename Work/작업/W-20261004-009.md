## 문제

사용자가 `blu-101`과 알티컴 `qms-44ux`를 비교하며 **"03과 02가 거의 같은 내용이 반복된다"**고 지적했다.

| | `blu-101` 02 | `blu-101` 03 |
|---|---|---|
| 내용 | 번호 11개 — 입력 A·B·C, 출력 D·E, BLU link, Ethernet, RS-232, CONTROL, LOGIC | 카드 6장 — 같은 단자를 `io` 행 단위로 다시 |

**같은 단자를 두 번 보여 준다.**

알티컴에는 03 연결 단자가 **없다.** 02 Port Map 하나가 그 역할을 한다.

## 알티컴의 구조 — 그대로 가져온다

`rtcom-configurator/src/products.js:1025`

```js
const portSection = item.group!=='cable' ? (portMapDiagram(item) || portCards(item)) : null;
```

`:1055`

```js
<h2><span class="rt-pg-idx">02</span>Port Map
  <span class="rt-pg-note">— ${item.portMap ? (basis||'실제 제품 사진 기준') : '입출력 표 기준'}</span></h2>
```

**사진 지도가 있으면 사진, 없으면 `io`에서 뽑은 카드만.** 제목 꼬리표가 근거를 밝힌다.

`portCards()`는 `io` 행마다 카드 하나를 만든다.

```js
`<div class="rt-pg-port"><b><span class="rt-pg-n">${i+1}</span>${방향} · ${신호}</b>${수량}개${프로토콜}${조건}</div>`
```

## 이 구조가 174종 문제를 해결한다

| 상태 | 종수 | 합친 뒤 |
|---|---:|---|
| `portMap` + `io` | **51** | 사진 지도. **중복 제거됨** |
| **`io`만** | **174** | **「입출력 표 기준」으로 02에 들어간다** |
| 둘 다 없음 | 17 | 02에 사진만 |

**174종이 03을 잃어도 정보를 잃지 않는다.** 이 확인이 이 작업의 전제다.

## 바뀌는 것

### 카드 02 — `#gallery`

- 제목을 **`02 제품사진(Port Map)`**으로 바꾼다. 지금은 상황에 따라 `제품 사진`·`Port Map`으로 흔들린다
- 제목 옆 꼬리표로 근거를 밝힌다

| 꼬리표 | 조건 |
|---|---|
| `— 실제 제품 사진 기준` | `portMap`이 있고 사진과 맞는다 |
| `— 입출력 표 기준` | `portMap`이 없고 `io`가 있다 |
| (없음) | 사진만 있다 |

- `portMap`이 없고 `io`가 있으면 **`io`에서 `.port-map-ports` 격자를 만든다**

### 카드 03 — `#io`

- **`#port-grid`를 02로 옮기고 03에서 없앤다**
- **`#io-table-details`(검증 상태가 붙은 상세 표)는 `#io-records`(출처 기록)로 옮긴다.** 지금은 `signalFlow`가 있을 때만 옮겨진다. **항상 옮긴다**
- `#rear-connector-panel`은 **02 갤러리의 Front/Rear 전환과 중복**이다. 없앤다
- **03은 `signalFlow`가 있을 때만 보인다.** 없으면 숨긴다

### 카드 번호

번호는 HTML에 고정돼 있고 안 보이는 카드는 **숨김** 처리된다. **지금도 번호에 빈칸이 생기는 구조이며 이번에 바꾸지 않는다.** `signalFlow`가 없는 제품은 `01 · 02 · 04 · 05`로 보인다.

**이는 03 SIGNAL FLOW가 채워지면서 해소된다.** 이번 범위가 아니다.

## ★ 내용은 우리 것을 유지한다

알티컴의 `portCards()`는 `방향 · 신호` + `수량·프로토콜·조건`만 넣는다. **우리 `#port-grid`는 검증 상태 표시와 조건까지 보여 준다.**

**격자 모양은 알티컴을 따르되 넣는 내용은 지금 것을 유지한다.** 검증 상태는 AV Portal의 핵심이며 버리면 안 된다.

→ `.port-map-ports` / `.port-map-port` / `.port-map-n` **기존 클래스를 재사용**한다. 새 스타일을 만들지 않는다.

## ★ 번호가 두 곳에서 생긴다

| 출처 | 번호 |
|---|---|
| `portMap` | `items[].n` — **사진의 번호와 같아야 한다** |
| `io` 폴백 | 행 순서 `index + 1` |

**섞이면 안 된다.** `portMap`이 있으면 `portMap`의 번호만 쓴다. `io` 폴백은 `portMap`이 없을 때만이다.

## ★ `absentConnectors`를 확인한다

`#io-count`가 `data.io.length - data.absentConnectors.length`로 계산된다. **"없음"으로 기록된 단자가 있다.** 폴백 카드에 그것들이 끼지 않는지 확인하고, 처리 방식을 보고한다.

- **03 SIGNAL FLOW는 후속 작업**이다. 사용자는 **"자동 생성 후 보강"**을 택했다. 알티컴 `ioFlowDiagram()`처럼 `io`에서 그리고, 부족한 제품만 나중에 손으로 올린다.
