# B-20261013-03 — 슬롯·카드 데이터 형식과 라이브러리 반영

- 상태: 초안

- 작성일: 2026-10-13
- 기준 main: 744452e
- 선행 작업: 없음(B-20261013-01과 병행 가능)

## 배경

2026-10-13 사용자: "XDM, SPX, VDM 같은 슬롯형 비디오장치의 경우에도 슬롯구성을 할 수 있도록 되어있었는데 그부분도 구현되어 있지 않고." 같은 날 결정: RTCOM 카드 데이터는 **RTCOM 원본에 추가**, 슬롯 방식은 **슬롯 번호별**.

RTCOM 쪽 요청은 [RTCOM 슬롯·카드 데이터 요청](../RTCOM-슬롯카드-데이터-요청.md)으로 따로 보냈다(브랜치 `claude-feat/rtcom-slot-card-request`). 이 작업은 **같은 형식**을 Portal 제품에도 정하고, 라이브러리 생성기가 두 출처를 같은 방식으로 읽게 한다.

카드가 이미 Portal 제품인 경우:

| 프레임 | 슬롯(상세 I/O 행) | 카드 제품 |
|---|---|---|
| Novastar H2 | 입력 4 · 출력 2 (`FOUND`) | `h-input-card-*` 7종, `h-output-card-*` 2종, `h-preview-card-*` 1종 |
| Novastar H5 | 입력 10 · 출력 3 · MVR 슬롯(수량 없음, `PARTIAL`) | 같음 |
| BSS BLU-160 | 카드 4슬롯(현재 override로 "최대 16채널"을 단자로 펼침) | `blucard-in`, `blucard-out`, `blu-aec-in` 등 |

## 목표

`builder-library.json`의 프레임 제품에 슬롯 정보가, 카드 제품에 장착 정보가 실린다. Builder 화면은 바꾸지 않는다(B-20261013-04).

## 범위

- 할 것
  - **Portal 상세 JSON 필드 추가**(RTCOM 요청서와 같은 뜻)
    - 프레임: 최상위 `slots: { input, output, shared?, source, verification, note? }`
    - 카드: 최상위 `slotType: "input"|"output"|"shared"`, `compatibleFrames: [<프레임 slug>…]`. 카드 단자는 카드 제품의 기존 `io[]`를 그대로 쓴다.
    - 대상: Novastar H2·H5와 H 카드 10종, BSS BLU-160과 장착 카드. 값은 각 상세의 기존 I/O 행·근거 자료에서만 가져오고, 없는 값(H5 MVR 슬롯 수 등)은 넣지 않는다.
    - 프레임의 기존 "카드 슬롯" I/O 행은 **지우지 않는다**(Portal 상세 화면용). 생성기는 `slots`가 있으면 그 행을 슬롯 정보로 대체한다.
  - **생성기**(`beta/builder-library.mjs`)
    - 프레임 제품: `slots`를 라이브러리 제품에 싣는다. 슬롯 번호 `IN1…`, `OUT1…`, `S1…`.
    - 카드 제품: `card: { slotType, compatibleFrames }`를 싣는다. 카드도 지금처럼 단독 배치는 가능하게 둔다(D2).
    - RTCOM 시리즈: `lineup[]`에 `slots`·카드 `io`가 생기면 같은 구조로 싣는다. **지금 데이터엔 없으므로** 코드와 테스트(가짜 입력)만 준비한다.
    - BLU-160 override(`port-vocabulary.mjs` `blu-160#0~4`): `slots`가 들어오면 "최대 용량 펼침"을 끄고 카드 장착으로 바꾼다. 이미 그 단자로 연결한 구성도는 B-04에서 처리(이 작업에선 라이브러리 변경만, 기존 구성도엔 `library-drift`).
    - 라이브러리 `schemaVersion` 1.0.0 → 1.1.0(필드 추가).
  - 생성기 보고서(`--report`)에 "슬롯 정보 있는 프레임 n · 카드 n · 호환 대상 없는 카드 n".
  - 검사: `compatibleFrames`가 가리키는 slug가 없거나 그 프레임에 해당 `slotType` 슬롯이 0이면 생성기 오류.
  - Portal 데이터 절차: 검색 인덱스·snapshot·읽기용 목록 재생성, `verify-pages`.
- 하지 않을 것
  - Builder 화면(B-04), RTCOM 원본 수정(요청서로 전달됨), Aquilon·X100PRO(카드가 Portal 제품으로 없음 — 카드 등록이 먼저).
  - 슬롯 수·카드 단자 추정.
- 지킬 결정
  - 장비는 Portal 제품만. 카드도 Portal(또는 RTCOM 원본) 제품만 장착 대상이다.
  - Portal 데이터 수정 전 `Work/지시서.md`·`지시서-B.md`·열린 PR과 같은 파일이 겹치는지 확인.
