## 목표

**지금**

- 장비 라이브러리(`builder-library.json`)는 생겼다.
- 구성도 JSON 1.2는 [기반 명세](../기반명세.md) §7·§8에 문서로만 있다.

**이 작업이 끝나면**

- 화면 없이도 다음 일을 하는 **엔진**이 저장소에 생긴다.
  - 라이브러리의 장비로 노드를 만든다.
  - 연결 규칙(§7)으로 엣지를 판정·생성한다.
  - 이슈(§8.5)를 계산한다.
  - 결정적으로 직렬화한다(§8.4).
  - 파일을 검증한다.
- 견적 담당자가 쓸 수 있는 **JSON Schema**, **검증 명령**, **가상 예제**가 공개된다.
- P4 화면(React)은 이 엔진을 그대로 가져다 쓴다. 규칙이 화면과 검증기 두 곳에 따로 있지 않게 하기 위해서다.

## 범위

### 할 것

1. **`builder/engine/`** — 의존성 없는 ES 모듈(`.mjs`, JSDoc 타입 주석). Node와 브라우저 양쪽에서 돈다
   - `library.mjs`
     - 라이브러리 JSON을 읽어 배치 단위·단자 색인을 만든다
     - 어휘(`vocabulary`)에서 대칭 신호·호환 커넥터·레벨 쌍을 읽는다
   - `geometry.mjs`
     - 노드 폭·헤더·행 높이 상수
     - 노드 높이 계산(`measured.height`). 구 Builder `store.ts:308-378`의 식을 옮긴다
   - `rules.mjs`
     - §7.1 판정표(0~9번), §7.2 레벨 쌍, §2.8 커넥터 호환
     - 연결 신호·엣지 선 종류(§5.3) 계산
   - `diagram.mjs`
     - 빈 구성도 만들기
     - 배치 단위로 장비 노드 만들기(§8.2 키·순서). 메모·영역 노드
     - 엣지 만들기(§8.3: 출발·도착 바꾸기, 양방향 핸들 접두어, `style`, `data`)
     - `bomRows` 넣기
   - `issues.mjs`
     - §8.5 이슈 계산
       - 엣지: `connector-adapter`, `connector-unknown`, `signal-level`, `unverified-port`, `cable-unspecified`
       - 노드: `no-ports`, `series-config-pending`, `product-removed`, `library-drift`
     - 정렬
   - `validate.mjs`: 결과를 오류(저장 차단)와 이슈로 나눈다
     - 구조 검사(§8.6 표의 필수 키와 타입)
     - 참조 무결성(엣지 노드·핸들)
     - 단자 점유(단자 1개 = 엣지 1개)
     - 연결 규칙 재검사
   - `serialize.mjs`: §8.4 결정적 직렬화. 노드·엣지 정렬, 키 순서, 좌표 반올림, 2칸 들여쓰기, LF
   - ID 발급: `node_`·`e-…` + ULID. 시험에서는 고정 시드로 바꿔 넣을 수 있게 한다
2. **`builder/schema/diagram-1.2.schema.json`** (JSON Schema 2020-12)
   - §8 구조. 견적 담당자가 자기 도구(ajv 등)로 쓸 수 있게 한다
3. **`builder/cli/validate.mjs`**
   - `node builder/cli/validate.mjs <파일> [--library <경로|URL>]`
   - 오류·이슈를 출력한다. 오류가 있으면 종료 코드는 1
   - 라이브러리를 주면 `library-drift`·`product-removed`를 계산한다
4. **`builder/examples/`**
   - `legacy-1.1.example.json`: 구 Builder 키 구조와 같은 가상 예시. B-20261006-01 조사 때 저장소 밖에 만든 파일로, 이름은 모두 가상이다
   - 1.2 예제 3종: 소회의실(영상), 중강당 오디오(마이크·DSP·앰프·스피커), RTCOM 연장기 영상 분배
     - 실제 Portal 제품으로 엔진 API를 써서 만든다
     - 현장명은 가상으로 둔다
   - `README.md`: 1.1 대비 바뀐 점(§8.6 표), 필드 의미, 검증 명령. 견적 담당자용이다
5. **테스트 `tests/builder-engine.test.mjs`** (루트 `npm test`에 포함, 의존성 없음)
   - 연결 규칙: 기반명세 §7.3 시험 사례 22건을 그대로 옮긴다
   - 직렬화: 같은 구성 → 같은 바이트. 노드를 섞어 넣어도 같은 결과
   - 1.1 상위 집합: §8.6 표대로 `legacy-1.1.example.json`의 키 경로가 1.2 예제에도 같은 타입으로 있는지(정해진 예외 제외)
   - 검증기
     - 깨진 예제가 정확한 오류 코드로 실패하는지(참조 깨짐, 없는 핸들, 단자 두 번 연결, 방향 반대, 신호 불일치)
     - 정상 예제 3종은 통과하는지
   - 이슈: 사례별 코드와 정렬
   - 라이브러리 변경 대응: 저장 후 라이브러리에서 단자·제품이 바뀌어도 파일이 열리고, `library-drift`·`product-removed`가 나오는지
   - **현재 데이터 수치에 묶지 않는다.** 예제 파일은 스스로 완결돼 있어서 라이브러리 없이 검증된다
6. **문서**
   - 기반명세 §8의 미정 항목(높이 계산식 등)을 채운다
   - `.gitignore`에 `builder/examples/` 밖의 `*.diagram.json`을 넣는다
   - README 검증 절에 CLI 한 줄을 추가한다
   - 이 작업 파일과 `Work/빌더/README.md`를 갱신한다

### 하지 않을 것

- 화면(React 앱), Vite 빌드, Pages의 `builder/` 경로 (P4)
- 오토 레이아웃·교차 점프·평행선 알고리즘 이식 (P5)
- 라이브러리 생성 규칙 변경(P2 범위). 필요해지면 따로 기록한다
- 구 Builder 파일(1.1) 가져오기 변환기 (구 데이터는 폐기하기로 결정했다)

### 지킬 결정

- 1.1 형식 호환, 필드는 추가만 한다(통합 기획 §0)
- 노드 1개 = 1대, 단자 1개 = 연결 1개, 출력 분배 차단(D4)
- 전원선은 1단계에서 긋지 않는다(D5, §7.1 5번)
- 실제 구성도 파일은 커밋하지 않는다(예제는 가상 현장만)
- 루트 `package.json`의 의존성은 0개로 유지한다

## 검증 방법

```powershell
node builder/cli/validate.mjs builder/examples/small-room.diagram.json
node builder/cli/validate.mjs builder/examples/small-room.diagram.json --library beta/.generated/builder-library.json
node --test tests/builder-engine.test.mjs
```

이 밖에 공통 검증을 돌린다: LF 복제본 전체 테스트, `verify-pages`, 검색 인덱스 `--check`, `git diff --check`.

## 결정이 필요한 사항

| ID | 항목 | 기본값 | 이유 |
|---|---|---|---|
| F-a | 엔진을 무엇으로 쓸지 | **의존성 없는 JavaScript ES 모듈 + JSDoc 타입** | Node 검증 명령, 루트 `npm test`, P4 React 앱이 빌드 없이 같은 파일을 쓴다. TypeScript는 P4에서 앱 쪽에만 쓴다 |
| F-b | JSON Schema 자체의 기계 검증 | P4에서 `builder/`의 개발 의존성(ajv)으로 Builder CI에 넣는다 | 루트 의존성 0개를 지키기 위해서다. P3에서는 엔진 검증기가 같은 규칙을 직접 검사하고, 스키마는 계약 문서로 둔다 |
| F-c | 예제 3종의 구성 | 소회의실 영상 / 중강당 오디오 / RTCOM 연장기 분배 | 영상·오디오·TX/RX 단위를 각각 한 번씩 다룬다 |

## 작업 방식

| 일 | 맡기는 곳 | 근거 |
|---|---|---|
| 엔진·스키마·CLI·테스트 구현 | 직접 | 기반명세와 라이브러리 맥락을 갖고 있다. 결과는 22건 사례·직렬화·상위 집합 시험이 잡아 준다 |
