## 배경

2026-10-13 사용자 결정: 단자 편집은 "단자를 편집하여 portal에 반영가능하도록 (빌더only / portal 선택)".

Builder는 GitHub Pages 정적 화면이라 브라우저에서 저장소를 직접 고칠 수 없다. 그래서 **요청 파일을 내보내고, 저장소에서 스크립트로 적용해 PR로 올리는** 2단계로 만든다.

## 목표

설정 창에서 단자를 고친 뒤 **"Portal 반영 요청 파일 내보내기"**를 누르면 파일이 내려받아지고, `node beta/apply-builder-io-request.mjs <파일>`로 Portal 상세 JSON의 `io` 행에 반영할 수 있다.

## 범위

- 할 것
  - 설정 창 단자 탭에 버튼 2개: **이 구성도에만 적용**(B-01 동작) / **적용하고 Portal 반영 요청 내보내기**.
  - 요청 파일 `builder-io-request-<productId>-<날짜>.json`
    ```json
    {
      "schema": "av-portal.builder-io-request", "schemaVersion": "1.0.0",
      "productId": "…", "source": "portal",
      "library": { "catalogSha": "…", "detailSetSha": "…" },
      "changes": [
        { "op": "add",    "row": { "group": "Input", "connector": "HDMI", "signal": "HDMI", "direction": "IN", "quantity": "2" }, "reason": "" },
        { "op": "update", "ioIndex": 3, "before": { … }, "after": { … }, "reason": "" },
        { "op": "remove", "ioIndex": 5, "before": { … }, "reason": "" }
      ]
    }
    ```
    - 단자 단위 편집을 **I/O 행 단위**로 묶는다(같은 행에서 나온 단자는 `portalIo`로 묶임). 행 하나에서 나온 단자 수가 바뀌면 `quantity` 변경.
    - 단자마다 "근거(자료명·쪽)" 칸을 설정 창에 두고 `reason`으로 내보낸다.
  - `beta/apply-builder-io-request.mjs <파일> [--dry-run]`
    1. 요청의 `catalogSha`·`detailSetSha`가 현재와 다르면 경고하고 `before` 값이 지금 행과 같은지 행마다 확인한다. 다르면 그 변경은 적용하지 않고 보고한다.
    2. `Work/지시서.md`·`Work/지시서-B.md`의 진행 중 작업과 열린 PR이 같은 상세 파일을 고치는지 확인한다(`gh` 있으면 자동, 없으면 확인 목록 출력). 겹치면 중단.
    3. 적용: 추가·변경 행은 `verification: "REVIEW REQUIRED"`, `source`는 비우고 `reason`을 `condition` 끝에 적지 않는다(근거는 PR 본문에). 삭제는 행을 지운다.
    4. `node beta/build-search-index.mjs`, 필요 시 읽기용 목록 재생성, `node beta/build-builder-library.mjs --check`.
    5. 바뀐 행 요약과 PR 본문 초안을 출력한다.
  - RTCOM 제품(`source: "rtcom"`)은 요청 파일을 만들 수는 있되 스크립트가 **적용을 거부**하고 "RTCOM 원본 담당에게 전달" 안내를 낸다(AGENTS.md: RTCOM 원본은 Portal에서 고치지 않는다).
  - 운영 문서: [Builder 작업 흐름](../README.md)에 "Portal 반영 요청 처리" 절 추가(누가·언제 적용, PR 제목 규칙, 검증).
- 하지 않을 것
  - 브라우저에서 GitHub PR 자동 생성(토큰 보관 문제). 필요해지면 별도 작업.
  - `VERIFIED` 자동 부여. 확인은 사람이 자료로 한다.
  - 사진·Port Map 좌표 변경.
- 지킬 결정
  - 제조사 사양을 추측하지 않는다. 새 행은 항상 `REVIEW REQUIRED`로 들어간다.
  - Portal 데이터 수정은 기존 절차(검색 인덱스·snapshot·Pages 검증)를 따른다.
  - 같은 상세 파일을 다른 작업과 동시에 고치지 않는다.
