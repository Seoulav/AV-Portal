## 목표

**지금:** `/AV-Portal/builder/`에서 장비를 놓고 선을 긋고 JSON으로 저장할 수 있다. 다만 조작은 React Flow 기본값이다.

- 단자 점(8px)을 정확히 잡아야 선이 그어진다.
- 왼쪽 드래그는 화면 이동이고, 범위 선택이 없다.
- 이슈(`issues`)는 파일에만 있고 화면에 보이지 않는다.

**이 작업이 끝나면:** 사용자가 요청한 기본 조작이 [기반 명세](../기반명세.md) §9 수치대로 동작한다. P4 완료 조건(통합 기획 §11)을 채운다.

1. **근접 연결.** 단자 행 어디서든 선을 끌기 시작한다. 놓을 때 화면 기준 40px 안의 연결 가능한 빈 단자 중 가장 가까운 것에 붙는다.
2. **장비 몸체에 놓기.** 장비 위 아무 곳에 놓아도 그 장비의 연결 가능한 빈 단자 중 가장 가까운 것에 붙는다.
3. **범위 선택.** 빈 캔버스에서 왼쪽 드래그로 장비·메모·영역을 고른다.
4. **화면 이동.** 가운데 버튼 드래그, 또는 Space를 누른 채 왼쪽 드래그(C2)로 화면을 옮긴다.
5. **이슈 패널.** 엔진 `computeIssues` 결과를 목록으로 보이고, 누르면 해당 장비·연결로 화면을 옮긴다.
6. **브라우저 시험.** Playwright로 위 조작과 "만들기 → 내보내기 → 다시 열기 = 바이트 동일"을 확인한다.

## 범위

### 할 것

1. **근접 연결** (`builder/src/`)
   - 시작 영역: 단자 행 전체. 입력 열·출력 열은 그 칸, 양방향은 행 전체 폭이다. 단자 점 밖 16px 여유는 행 경계를 넘지 않는다.
   - 끝점 흡착: 반경은 `40 / 확대 배율`로 매번 계산한다. 후보는 엔진 `judgeConnection`으로 거른다. React Flow `connectionRadius`는 쓰지 않는다(기반명세 §9).
   - 장비 몸체에 놓기: `onConnectEnd`에서 놓은 지점과 가장 가까운 연결 가능 단자를 고른다.
   - 양방향 단자: 그 행에서 시작하면 `source_` 핸들, 그 행에 놓으면 `target_` 핸들이다. 엔진이 방향을 뒤집으면 접두어도 함께 바뀐다(§7.1 0번).
   - 순수 계산(단자 좌표, 가장 가까운 후보)은 `builder/src/` 안의 함수로 분리해 vitest로 시험한다. 좌표는 엔진 `geometry`를 쓴다.
2. **노드 이동 영역**: 헤더와 사진 영역으로만 옮긴다(E8). 단자 행은 선 긋기 영역이다.
3. **범위 선택·화면 이동**
   - `selectionOnDrag`, `SelectionMode.Partial`, `panOnDrag={[1]}`. Space를 누르는 동안 왼쪽 버튼도 화면 이동이다.
   - 영역(shape) 안쪽은 클릭이 통과해 범위 선택이 된다(지금도 통과한다).
   - 여러 개를 고른 뒤 옮기기·지우기는 한 번의 실행 취소 단위다.
   - `connectOnClick`을 끈다.
4. **막힌 연결 알림 유지**: B-04의 `onConnectEnd` 알림을 근접 연결에도 잇는다. 반경 안의 단자가 모두 막혔으면 가장 가까운 단자의 막힌 이유를 알린다.
5. **이슈 패널**
   - 오른쪽 패널. 연결을 고르지 않았을 때 보인다.
   - 심각도(error·warning·info)별로 묶고, 항목을 누르면 대상 노드·엣지를 선택하고 화면을 옮긴다.
   - 이슈 계산은 엔진 `computeIssues`를 그대로 쓴다.
6. **브라우저 시험 (Playwright, `builder/e2e/`)**
   - 통합 기획 §7.4 중 P4 항목:
     - 반경 안에서 시작·종료한 연결이 맞는 단자에 붙는다
     - 장비 몸체에 놓은 연결이 가장 가까운 연결 가능 단자에 붙는다
     - 왼쪽 드래그는 범위 선택이고 가운데 버튼 드래그는 화면 이동이다
   - 막힌 연결(같은 방향·신호 불일치·사용 중)이 화면에서도 막힌다.
   - 만들기 → 내보내기 → 새 구성도 → 열기를 하면 내보낸 파일과 자동 저장본이 바이트 단위로 같다.
   - 합성 라이브러리 픽스처로 돌린다. 실제 Portal 데이터 변화에 시험이 흔들리지 않게 한다.
   - `builder-ci.yml`에서 돌린다. Pages 배포에는 넣지 않는다.
7. **케이블 수치 검사를 엔진에도 둔다** (결정 H-d)
   - B-04는 화면에서만 막는다. 다른 도구로 만든 파일은 CLI가 걸러 내지 못한다.
   - `builder/engine/validate.mjs`가 같은 규칙을 검사한다: 기성 수량은 1 이상 정수, 제작 길이는 0보다 큰 수, 제품명 필수.
   - 화면 검사(`cableProblem`)도 엔진 함수 하나를 함께 쓴다.
8. **문서**: `builder/README.md`(사용법·시험), `builder/CHANGELOG.md` v0.2.0, 기반명세 §9 표(화면 시험으로 바꾼 수치가 있으면), 이 작업 파일, `Work/빌더/README.md`

### 구현 메모

- **시작·놓기 영역.** React Flow는 선을 놓을 때 포인터 바로 아래 핸들(`elementFromPoint`)을 거리 판정보다 먼저 본다. 그래서 핸들 상자를 단자 행 칸 전체(+ 테두리 밖 점까지)로 키웠다.
  - 선은 핸들 상자의 바깥 끝에 붙는다(`getHandlePosition`). 점도 그 끝에 그리므로 선은 B-04와 같은 자리에 붙는다.
  - 점 바깥 16px 여유는 `::before`다. React Flow는 핸들 크기를 잴 때 가상 요소를 넣지 않는다.
- **흡착.** `connectionRadius`를 0으로 두고, 포인터 아래 단자가 없거나 막혔을 때 `onConnectEnd`에서 `proximity.ts`가 붙일 단자를 고른다. 미리보기(`ConnectionLine`)도 같은 함수를 쓴다.
- **양방향 단자.** 엔진은 양방향끼리의 순서를 바꾸지 않는다. 그래서 React Flow와 같은 규칙으로 방향을 정한다: 받는 쪽 핸들에서 끌기 시작했으면 후보가 source다.
  - 판정(`connectionJudge`)이 엣지에 실제로 남을 핸들을 돌려주고, 고리는 그 점에 그린다.
- **명세와 다르게 한 것.**
  - 이슈 패널은 심각도를 warning·info로 묶었다. 명세의 "error·warning·info" 중 error(오류)는 저장을 막으므로 이슈에 없다(기반명세 §8.5).
  - 범위 선택 뒤 React Flow가 덮는 사각형(`.react-flow__nodesselection-rect`)을 없앴다. 리뷰 2번 참고.
