## 설계 결정

- cpq/를 독립 npm 앱으로 반입하고 빌드 결과만 beta/site/cpq에 배치한다. 코드는 7dcb7ab의 허용 경로만 추출하고 UPSTREAM.json에 바이트 해시를 기록한다.
- 견적 만들기는 같은 origin의 별도 탭에 postMessage로 전달한다. 준비 응답, origin/창/랜덤 식별자 검증, 만료·중복 방지, payload 크기 제한을 둔다. 원문은 메모리에만 둔다. URL에는 구성도 본문과 전송 식별자 모두 넣지 않는다.
- 새 구성도 전송은 새 견적 생성이다. 동일 CPQ 탭을 재사용하는 경우에도 기존 mayReplaceDocument로 취소할 수 있다. 기존 작업 파일·JSON 입구를 유지한다.
- 기존 CPQ parseDiagram → diagramToQuote를 사용하고 annotation/shape만 견적 대상에서 제외한다. 알 수 없는 노드 타입은 조용히 버리지 않는다.
- Builder에 장비별 시스템명과 견적 옵션 입력을 추가한다. 옵션은 Portal 목록 제품에서만 선택하며 단자·호환 규칙을 바꾸지 않는다. 기존 파일의 옵션 정의·수량은 저장/재열기 때 보존한다. 품목에 없는 옵션은 CPQ에서 미확정 안내한다.
- 케이블·커넥터는 현행 CPQ의 첫 시스템 귀속을 유지하고 안내한다. 새 시스템별 케이블 계산 규칙을 만들지 않는다.
- 원가 세션은 CPQ 메모리 전용이다. 공유 코드에 원가 상태를 넘기지 않는다. 기존 영업팀 Excel 명시적 내보내기만 예외다.

## 검토 초점

1. CPQ 로딩 중 반복 클릭과 이전 전송 지연: 가장 최근 요청만 유효하고 미저장 확인을 거쳐야 한다.
2. 구성도와 원가 객체에 같은 이름의 키가 섞인 경우: 허용 필드만 새 객체로 복사한다.
3. 메모/도형 및 없는 옵션 정의: 장비를 잘못 만들거나 옵션을 누락하지 않는다.
4. 새로고침/뒤로가기/직접접속: 과거 전송을 재생하지 않고 JSON/작업 파일 입구로 복구 가능하다.
5. CPQ 하위 경로와 실제 정적 자산: 개발 서버 성공만으로 배포 경로 검증을 대신하지 않는다.
