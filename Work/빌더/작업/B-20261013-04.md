# B-20261013-04 — 슬롯 번호별 카드 장착 화면

- 상태: 초안
- 로드맵 단계: P9(카드 장착 구성)
- 작성일: 2026-10-13
- 기준 main: 744452e
- 선행 작업: [B-20261013-01](B-20261013-01.md)(설정 창), [B-20261013-03](B-20261013-03.md)(라이브러리 슬롯 정보). RTCOM XDM·SPX·VDM은 RTCOM 원본 반영·동기화 후 추가 작업 없이 같은 화면으로 동작해야 한다
- 승인: 대기
- 브랜치·PR: 미생성

## 목표

슬롯 정보가 있는 프레임 노드의 설정 창에 **슬롯** 탭이 생기고, 슬롯 번호마다 카드를 고르면 카드 단자가 노드에 붙어 결선할 수 있다.

## 범위

- 할 것
  - 설정 창 **슬롯** 탭: `IN1…`·`OUT1…`(·`S1…`) 목록, 슬롯마다 호환 카드 선택(없음 포함). 입력 슬롯엔 입력 카드만 보인다.
  - 카드 단자 합성: 카드 `io`에서 만든 단자를 슬롯 순서대로 노드에 붙인다. 이름은 `IN2 HDMI In 3`처럼 슬롯 번호를 앞에 둔다.
  - 저장 형식(구 Builder 1.1과 호환, 필드 추가만)
    - `selectedOptionQuantities`: 키 `portal-option:<카드 productId>`, 값은 장착 장수. **견적 옵션과 같은 키**를 써서 카드가 곧 견적 품목이 된다(지금 견적 패널의 옵션 품목과 의미가 하나로 합쳐짐).
    - `optionPortIds`: 카드가 만든 단자 id 목록. id는 `opt-<카드 productId>-<슬롯번호>-<카드 단자 id>` — 구 Builder `opt-<옵션id>-<n>-<단자id>` 규칙을 따르되 `<n>`에 슬롯 번호를 넣어 카드 교체 시 다른 슬롯 연결이 유지된다.
    - 추가 필드 `slotAssignments: { "IN1": "<카드 productId>", … }`.
    - 최상위 `options[]`에 카드 품목을 등록(지금 견적 옵션과 같은 방식).
  - 카드를 빼거나 바꾸면 그 슬롯 단자에 걸린 연결을 B-01과 같은 확인 후 정리.
  - 이슈: 슬롯 정보가 있는데 빈 슬롯만 있으면 `slot-empty`(info). RTCOM 시리즈의 `series-config-pending`은 슬롯 정보가 생기면 이 흐름으로 바뀐다.
  - BLU-160 등 B-03에서 펼침이 꺼진 프레임: 예전 단자로 연결된 구성도를 열면 "카드 구성으로 옮기기" 안내(자동 변환은 D1).
  - 견적(CPQ) 쪽 확인: `selectedOptionQuantities`의 카드 키를 견적이 품목으로 읽는지 `cpq/` 테스트로 확인.
- 하지 않을 것
  - 슬롯 수·카드 데이터 보강(B-03·RTCOM 원본), 카드 단자 편집(카드는 Portal 값 그대로. 필요하면 B-01 단자 편집으로 노드에서 고친다).
- 지킬 결정: 1.1 호환(필드 추가만), 노드 1개 = 장비 1대(카드는 노드가 아니라 프레임의 구성).
