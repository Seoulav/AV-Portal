## 목표

**지금:** 선은 React Flow 기본 smoothstep으로 그린다. B-06의 평행 간격은 같은 두 장비 사이 선만 띄운다.

다음 경우는 아직 선이 겹치거나 알아보기 어렵다.

- 여러 장비에서 한 장비로 모이는 선(마이크 8대 → 믹서)
- 한 장비에서 여러 장비로 퍼지는 선(분배기 → 디스플레이 4대)
- 서로 다른 묶음의 세로 구간이 같은 x에 놓이는 경우
- 선끼리 교차하는 곳

구 Builder는 이 문제를 오래 다듬은 코드로 풀었다(통합 기획 §8 "이식").

**이 작업이 끝나면:** 구 Builder와 같은 품질로 선을 그린다. 파일 형식은 바꾸지 않는다. 선 모양은 화면에서만 계산한다.

1. **평행선 간격.** 같은 쌍, 모이는 선, 퍼지는 선, 그 밖의 겹침, 전체 세로 통로 충돌을 구 Builder `edgeProcessing` Stage 0~4로 띄운다.
2. **채널 순서.** 묶음 안의 순서를 바꿔 서로 건너는 선을 줄인다(`optimizeChannelOrder`).
3. **교차 점프.** 선이 교차하는 곳에 작은 반원을 그린다(`edgeGeometry`, 구 `CustomSmoothstepEdge`).
4. **양방향 선 방향.** 양방향끼리 이은 선은 장비 위치에 맞게 화면에서만 뒤집어 그린다(`normalizeBidiEdges`). 파일의 source·target은 그대로다.

- **파일**
  - `builder/src/edges/edgeProcessing.ts`: Stage 0~4, `optimizeChannelOrder`, `normalizeBidiEdges`. 끝점은 엔진 `portAnchors`(B-05 `anchorOf`)로 구한다. 구 Builder가 따로 계산하던 포트 좌표(헤더 54px 등)는 쓰지 않는다
  - `builder/src/edges/edgeGeometry.ts`: `getEdgePoints`(가로-세로-가로, 뒤로 가는 선은 아래 U자, 높이 차가 8px 미만이면 직선), `computeJumps`, `buildOrthogonalPath`, 그리고 새로 만든 `edgeJumps`
  - `builder/src/components/BuilderEdge.tsx`: 구 `CustomSmoothstepEdge`. React Flow `edgeTypes.smoothstep` 자리에 둔다. 라벨 역스케일 `min(3.2, max(1, 0.85/zoom))`, 케이블 요약 `cableLabel`
- **계산 위치**
  - 간격·점프·뒤집기는 Canvas에서 구성도 좌표로 한 번에 구해 엣지 `data`로 넘긴다. 엣지 컴포넌트는 그리기만 한다.
  - 구 Builder 함정 "앱 memo에서 React Flow 내부 좌표를 읽으면 한 프레임 늦다"는 구성도 좌표만 쓰므로 생기지 않는다.
- **교차 점프**: 구 Builder는 엣지마다 다른 엣지 전체를 견준다(엣지 600개에 142ms). `edgeJumps`는 세로 구간을 x 64px 칸으로 색인해 한 번에 구한다. 무작위 엣지로 구 `computeJumps`와 같은 결과를 확인했다.
- **간격 순서**: 구 Builder는 같은 조건이면 입력 순서로 정한다. 내보낸 파일은 엣지를 id 순으로 적으므로, 계산 전에 id 순으로 맞춰 다시 열어도 같게 그린다(리뷰 3번). 미리보기 엣지는 `e-<source>-<target>-~`로 같은 자리에 정렬되게 한다.
- **끌기 중 계산(J-c)**: 측정 결과 엣지 600개에서 간격 계산이 한 프레임 5~10ms였다.
  - 끄는 동안에는 끌기 시작 때의 간격을 그대로 쓰고, 놓을 때 전체를 다시 계산한다. 끝점과 교차 점프는 매 순간 다시 구한다.
  - 명세의 기본값("끄는 장비에 붙은 선만 다시 계산")과 다르다. Stage 3·4는 전체 세로 통로를 함께 보므로 일부만 다시 계산할 수 없어서, 놓을 때 한 번에 계산하는 쪽을 골랐다.
- **그 밖의 성능**
  - 바뀌지 않은 노드·엣지는 앞의 화면용 객체를 그대로 넘긴다.
  - 이슈 목록은 이슈가 바뀔 때만 다시 만든다(장비 이름을 찾던 이중 반복도 없앴다).
  - 노드별 단자 좌표는 장비 정보가 같으면 다시 구하지 않는다.
- **측정**: 같은 PC에서 Chrome으로 장비 하나를 끌며 한 프레임의 중앙값을 쟀다. Playwright 추적을 끄고 쟀다(켜면 몇 배 느리게 나온다).

| 5 | 낮음 | 묶음 미리보기가 포인터가 움직일 때마다 전체 간격을 다시 계산한다. 600개 끌기가 끊기지 않는다는 완료 조건은 측정상 충족하지 않았고, "142ms → 3ms"는 교차 점프만의 수치다 | 미리보기 계산을 구성도와 미리보기 쌍이 바뀔 때만 하도록 메모했다. 완료 조건은 체크하지 않고 측정값을 남겼다. CHANGELOG 문구를 고쳤다 |
| 6 | 낮음 | 통합 기획 §8의 "이식 상태" 문단이 표 중간에 들어가 뒤의 행이 표로 보이지 않는다 | 표 아래로 옮겼다 |
| 7 | 범위 밖 | 구 Builder의 선 종류 필터(`hiddenLineTypeIds` 칩, 보이는 연결이 없는 장비 흐리게)가 이식 목록에 없다 | 통합 기획 §8 이식 상태와 아래 "남은 일"에 적었다. 옮길 때 간격은 전체 엣지로, 점프는 보이는 엣지로만 계산한다(구 Builder와 같다) |

리뷰어가 확인한 것: 구 Builder 대조 1,949개 일치, 임시 사본이 원본과 바이트 단위로 같음, `edgeJumps`와 `computeJumps`가 점프 53,895개에서 같음, Stage 3 탐색 순서 같음, 일부러 망가뜨린 세 가지(밀기 전 자르기 빼기, 채널 순서 끄기, Stage 4 빼기)가 각각 vitest 2건 이상을 실패시킴, 끝점이 React Flow 핸들 바깥 가장자리와 같음, 끌기 중 고정된 간격이 남지 않음, 화면용 값이 파일에 들어가지 않음.
