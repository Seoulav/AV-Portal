## 목표

**지금:** 선은 React Flow 기본 smoothstep으로 그린다. B-06의 평행 간격은 같은 두 장비 사이 선만 띄운다.

다음 경우는 아직 선이 겹치거나 알아보기 어렵다.

- 여러 장비에서 한 장비로 모이는 선(마이크 8대 → 믹서)
- 한 장비에서 여러 장비로 퍼지는 선(분배기 → 디스플레이 4대)
- 서로 다른 묶음의 세로 구간이 같은 x에 놓이는 경우
- 선끼리 교차하는 곳

구 Builder는 이 문제를 오래 다듬은 코드로 풀었다(통합 기획 §8 "이식").

**이 작업이 끝나면:** 구 Builder와 같은 품질로 선을 그린다. 파일 형식은 바꾸지 않는다. 선 모양은 화면에서만 계산한다.

1. **평행선 간격.** 같은 쌍, 모이는 선, 퍼지는 선, 그 밖의 겹침, 전체 세로 통로 충돌을 구 Builder `edgeProcessing` Stage 0~4로 띄운다.
2. **채널 순서.** 묶음 안의 순서를 바꿔 서로 건너는 선을 줄인다(`optimizeChannelOrder`).
3. **교차 점프.** 선이 교차하는 곳에 작은 반원을 그린다(`edgeGeometry`, 구 `CustomSmoothstepEdge`).
4. **양방향 선 방향.** 양방향끼리 이은 선은 장비 위치에 맞게 화면에서만 뒤집어 그린다(`normalizeBidiEdges`). 파일의 source·target은 그대로다.

## 범위

### 할 것

1. **구 Builder 코드 가져오기** (읽기만)
   - 원본: `seoul-visual-tech/av-system-builder` `main` `2fd568e`(v1.20.1). 통합 기획 §0의 기준과 같다.
   - 대상 파일
     - `src/utils/edgeProcessing.ts`(432줄)
     - `src/utils/edgeGeometry.ts`(227줄)
     - `src/CustomSmoothstepEdge.tsx`
   - 이력은 가져오지 않는다. 고객 구성도가 들어 있다.
   - 구 저장소 `CLAUDE.md`에 기록된 함정(예: 헤더 54px 불일치)을 확인해 회귀 시험으로 만든다.
2. **이식** (`builder/src/edges/`)
   - 순수 함수는 그대로 옮기고, 좌표는 엔진 `geometry`(`portAnchors`·`nodeHeight`)를 쓰도록 바꾼다. 구 Builder의 따로 계산하던 포트 좌표는 버린다.
   - 엣지 컴포넌트는 React Flow `edgeTypes`의 `smoothstep`에 등록한다. 파일의 `type: "smoothstep"`은 그대로다.
   - B-06의 `edgeSpacing.ts`를 이 코드로 바꾼다. 묶음 미리보기도 같은 계산을 쓴다.
3. **성능**: 장비 150대·엣지 600개에서 끌기 중 한 프레임 계산 시간을 잰다. 끌기 중에는 계산을 줄이는 방법(끌기를 마칠 때 다시 계산 등)을 정한다(결정 J-c).
4. **시험**
   - vitest: Stage 0~4·채널 순서·교차 점프·양방향 뒤집기의 회귀 시험. 구 Builder에서 같은 입력에 같은 결과가 나오는지 표본으로 대조한다.
   - Playwright: 모이는 선 8개·퍼지는 선 4개가 겹치지 않는다. 교차하는 곳에 점프가 그려진다.
5. **문서**: `builder/README.md`, `builder/CHANGELOG.md` v0.4.0, 통합 기획 §8 표의 이식 상태, 이 작업 파일, `Work/빌더/README.md`
