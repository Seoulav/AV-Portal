## 목표

**지금:** 구성도는 JSON 파일로만 내보낸다. 견적·시공 담당자에게 도면을 보여 주려면 화면을 캡처해야 한다.

구 Builder(`2fd568e`)는 "PDF"를 눌러 **화면을 PNG 한 장으로 찍어** PDF에 붙였다(`App.tsx:536-568`, `html-to-image` + `jsPDF`). 그래서 다음 문제가 있었다.

- 확대하면 흐려진다. 글자를 고르거나 찾을 수 없다
- 화면 크기·줌·테마에 따라 결과가 바뀐다
- 화면 밖 장비는 빠질 수 있다(찍기 전 화면 맞춤에 의존)

**이 작업이 끝나면:** 상단 막대의 "SVG"·"PDF"로 도면을 받는다.

1. **SVG**: 구성도 데이터(엔진 좌표)로 직접 그린 벡터 도면이다. 장비 상자·모델명·단자 이름·단자 점, 연결선(B-07과 같은 경로·간격·교차 점프), 연결 라벨, 메모·영역이 들어간다. 화면 상태(줌·선택·필터·테마)와 무관하게 늘 같은 결과다.
2. **PDF**: 같은 SVG를 벡터 그대로 PDF로 옮긴다. 글자를 고르고 찾을 수 있다.

## 범위

### 할 것

1. **SVG 그리기** (`builder/src/export/diagramSvg.ts`, 순수 함수)
   - 입력: 구성도(1.2)와 선 종류 색. 출력: SVG 문자열. 브라우저 화면(DOM)을 읽지 않는다.
   - 좌표는 엔진 `geometry`, 선은 `edges/edgeProcessing`·`edgeGeometry`를 그대로 쓴다. 화면과 같은 선 모양이 나온다.
   - 장비: 상자, 제조사·모델명·장비 이름, 단자 행(이름·점·색), 양방향 구획. 사진은 결정 M-c를 따른다.
   - 연결: 선 종류 색, 라벨(있으면), 케이블 요약은 넣지 않는다(화면의 "케이블 보기"와 같은 선택은 결정 M-d).
   - 메모·영역: 서식 그대로(B-09 그리기와 같은 규칙).
   - 도면 범위는 모든 노드를 감싸는 상자 + 여백이다.
2. **PDF** (`builder/src/export/diagramPdf.ts`)
   - SVG를 벡터로 옮긴다(결정 M-a). PDF 생성 라이브러리는 누를 때 불러온다(첫 화면 번들에 넣지 않는다, B-08의 Dagre와 같다).
   - 한글 글꼴을 넣는다(결정 M-e). 넣지 않으면 PDF에서 한글이 깨진다.
3. **상단 막대**: "SVG", "PDF" 버튼(또는 내보내기 메뉴). 파일 이름은 JSON 내보내기와 같은 규칙(`구성도-YYYYMMDD-HHmm`).
4. **시험**
   - vitest: SVG가 모든 장비·연결·메모를 담는다, 선 경로가 화면 경로와 같다, 결과가 결정적이다(같은 입력 → 같은 문자열), 필터·선택·테마와 무관하다, XML로 읽힌다(특수 문자 이스케이프 — `&`·`<`가 든 모델명·라벨).
   - Playwright: 버튼을 눌러 파일을 받는다, PDF 첫 쪽 크기·글자 추출(한글 포함).
5. **문서**: `builder/README.md`, `builder/CHANGELOG.md` v0.7.0, 통합 기획 §8 이식 상태, 이 작업 파일, `Work/빌더/README.md`

### 하지 않을 것

- PNG 내보내기(구 방식). 필요하면 SVG를 이미지로 바꾸는 별도 작업으로 한다
- 케이블 목록·BOM 표를 PDF에 붙이기(견적 범위, 통합 기획 §8 "보류")
- 여러 쪽 나누기·인쇄 축척 지정
- 구성도 파일 형식 변경

### 지킬 결정

- 1.1 호환 JSON. 이 작업은 파일을 바꾸지 않는다
- 공개 저장소 규칙: PDF·SVG 결과물과 실제 구성도는 커밋하지 않는다. 시험은 합성 픽스처로 한다
- 고객명·현장 정보는 구성도 파일에 없으므로 표제에도 넣지 않는다(결정 M-b)

## 결정이 필요한 사항

| ID | 항목 | 기본값(추천) | 이유 |
|---|---|---|---|
| M-a | PDF 만드는 방법 | `jspdf` + `svg2pdf.js`(SVG를 벡터로 옮김). 누를 때 불러온다 | 구 Builder도 `jspdf`를 썼다. 화면 캡처(PNG)는 흐리고 글자를 찾을 수 없다. 직접 PDF를 쓰는 방법은 만들 것이 많다 |
| M-b | 종이와 표제 | 도면 크기 그대로 한 쪽(구와 같다). 오른쪽 아래에 "AV Portal Builder 버전 · 내보낸 날짜"만 작게 적는다 | 인쇄 축척을 정하려면 현장 관행이 필요하다. 고객·현장 정보는 파일에 없다 |
| M-c | 장비 사진 | 넣지 않는다(1차). 사진 자리는 비우지 않고 높이를 화면과 같게 둔다 | Portal 사진은 WebP라 PDF에 넣으려면 변환이 필요하고 파일이 커진다. 결선 도면에는 모델명·단자가 핵심이다. 필요하면 다음 작업으로 넣는다 |
| M-d | 연결 라벨 내용 | 화면과 같다: 라벨이 있는 연결만 라벨을 적는다. 케이블 요약은 넣지 않는다 | 케이블 목록은 견적 쪽이 JSON으로 받는다. 원하면 "케이블 보기"를 켠 상태처럼 요약을 넣는 선택지를 둔다 |
| M-e | PDF 한글 글꼴 | 오픈 라이선스 한글 글꼴(예: Pretendard, SIL OFL)의 필요한 글자만 담은 파일을 누를 때 불러와 넣는다 | 넣지 않으면 한글이 깨진다. 글꼴 전체는 수 MB라 글자 묶음을 줄인다. 글꼴 파일의 라이선스 문서를 함께 둔다 |
| M-f | 테마 | 내보내기는 늘 밝은 바탕이다 | 인쇄·문서용이다. 화면 테마와 무관해야 같은 결과가 나온다 |

## 작업 방식

| 일 | 맡기는 곳 | 근거 |
|---|---|---|
| SVG 그리기·PDF 연결 | 직접 | 엔진 좌표와 B-07 선 그리기를 그대로 써야 한다 |
| 글꼴 묶음 줄이기 | 직접 | 라이선스와 글자 범위를 확인해야 한다 |
| 독립 리뷰 | 하위 에이전트, 상위 모델 1회 | 결과물 모양과 의존성은 사람 눈이 필요하다 |
